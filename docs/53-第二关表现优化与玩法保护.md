# 1-2 表现优化与玩法保护

本轮只接入 1-2 的表现优化。`levels.json`、`GardenWorld`、`GameSession`、原图片素材和存档格式均未修改。

## 玩法契约

- 固定地图仍为 14 格；起点 `f:0:1`，根台 `f:1:1`，花坛 `f:4:1`，中央阻挡 `[2,1]`。
- 预算仍为 4 节，从根尖连续延伸；上绕和下绕均可完成。没有复制 1-1 单节、东西二选一的专属文案。
- 保留原七个 socket 和 `[3,1]` 目标、原高度层级/邻接判定、伙伴跟随与会合、可选收集/观察。
- 岩石不能穿过；错误方向/超预算继续由领域规则拒绝。撤回最后一节、撤销、部分生长存档及完成存档保持有效。
- 预览不开放尚未提交的道路；回首页取消待提交动作；提示仍为底部显示/点击内容轮换/再次点击按钮隐藏。

原冻结 JS 参考的 1-2 子集（15 个案例、96 次命令、303 项状态/命令/快照对照）通过。为运行该子集，只给原测试增加 `--level=1-2` 过滤参数，没有改写 fixture；不带参数时保持原全量检查行为。

## 表现设计与公共边界

1. `second_garden_profile.gd` 独立定义第二关地形，不依赖首关坐标。使用已抽离的 `StairGeometry`、`TerraceMaterials`、交互与提示公共逻辑。
2. 保持左岛和绕岩石根路坐标不变；右岛第 4 列物理宽度为 2.4，后续列顺移。双向映射保留逻辑格和归一化存档偏移。
3. 第二关物理层高设为 0.45，形成 0 / 0.45 / 0.90 的落脚面；领域高度仍为 0 / 1 / 2。新增可选 `base_height(tile)` 契约，使网格、碰撞、道具和运动目标使用同一高度；其他 profile 仍沿用原值。
4. 入口采用 5 级低台阶，后排采用 6 级横向阶梯；入口完整位于右岛，不侵入根路的转角。脚底上包络在后排衔接处提前过渡，原生碰撞仍控制真实身体。
5. 使用原铺地石材、草地、岩石、花坛、蕨类与花卉。中央障碍改为石基承托原岩石图，取消墙纸方盒。花坛使用共用完整原图与接触阴影，移除裁切小图式表现。
6. 选材配置提供 `top_scale` / `face_repeat`，加宽格独立缓存；地面按物理宽度重复原纹理，侧面用 `wall_uv` 展开，阶梯石缝密度随宽度调整，防止拉伸。默认值保持首关原表现。
7. 原楼梯图的分面 UV 提取为 `painted_stone_uv.gd`；花坛绘制提取为 `integrated_garden_props.gd`。两关都调用公共实现，各自配置比例和布局。
8. 1-2 平地根路保持 0.20 的平直薄板底面。生成方向从真实前驱节点计算，逐节向根尖展开；1-1 继续使用从高处向低处的阶梯生成规则。两者不再依赖相对原点猜方向。

## 验证与已解决问题

- 初稿实走发现转弯时入口台阶侵入根路，已收回右岛；偏边检测又发现高台阶下行/转角接触误差，最终通过扩宽落脚区域、降低物理层高及调整踏步解决，没有放宽测试阈值或取消碰撞。
- 两条解法的真实角色/应用事务测试：106 项通过；包含不收集直接通关、预算、存档往返、撤销/撤回、未提交动作取消、提示与生长方向。
- 入口和后排两列在 ±0.22、±0.30 偏移下上下行、停步与返回：35 项通过，最大身体/地面接触误差约 0.1633，低于 0.20 阈值。
- 15 个关卡共 110 个状态的网格/碰撞/接口回归：95965 项通过；首关材质 19189、角色深度 4968、应用 61、跨关配置 93、存档偏移 510 项通过。
- 桌面 1280×720、手机横屏 844×390 的真实鼠标/键盘流程通过。最终纹理密度调整不修改拓扑和动作流程，另行完成渲染测试与正式版画面对照。
- 1-2 带已生成根路存档的“继续”测试通过：首次最大帧间隔约 41.68ms，后两次约 10.67/8.93ms，无超过 50ms 的帧，无继续时的着色器编译/链接或几何重建。这是当前机器测量，不是所有手机帧率保证。
- 调试预览为 4217，正式预览为 4216。正式版对照脚本使用隔离 IndexedDB 存档与真实控件点击，不开启 release QA 接口；入场、生长、抵达花坛、完成四阶段均通过，画面平均 RGB 差异 0.0004–0.0228。结果见 `docs/qa-godot-native/second-garden/release/checks.json`。

相关证据集中在 `docs/qa-godot-native/second-garden/`。保留试验中失败报告用于追溯；最终通过报告为 `verified-headless`、`texture-check`、`verified-browser`、`continue` 和 `release`。首关旧全量 `rule_reference` 的 16/19 格差异仍是此前已记录的问题，本轮没有掩盖或覆盖它。

## 2026-11-08：恢复连续生长的操作表达

用户确认 1-2 的原玩法是“四节根芽绕过中央岩石，再到对岸花坛”。上一轮加号修复把所有关卡的选项都固定在根台周围，虽然命令与通关条件没改，连续生长的落点选择却失去了空间含义。仅以规则与通关测试证明“玩法未改变”不足以验收这种交互变化。

- 花坛周围的径向按钮成为首关独立开关 `seedbed_growth_choices`。1-2 和其他连续生长关卡恢复原来的真实目标格定位：每长一节，下一步的加号跟着根尖向前移动，并绘制目标格轮廓。
- 仍共用显示、可见性与命中检测，避免有图无热区或隐藏热区。公共代码只统一机制，不统一各关卡的种植操作模型。
- 中央岩石底座由满格缩为 0.68 格，两侧留出可见缺口；装饰底座关闭支撑碰撞。它不应让未生长的缺口看起来已被普通石路接通。
- 根台 `f:1:1`、岩石 `[2,1]`、花坛 `f:4:1`、四节预算和两条绕行解法保持原关卡定义。本次没有进一步重排平台，前轮右岛加宽与台阶高度调整仍在。
- 验证新增每节按钮位置与实际目标格一致、连续选点随根尖移动、岩石底座不会产生通路支撑。桌面与手机横屏使用真实鼠标/触摸逐节种植并留存截图；原 1-2 冻结参考的 303 项对照通过。

本次独立证据目录：`docs/qa-godot-native/second-garden-flow-restore/`。之前的报告保留用于追溯，不代表此前操作表达没有问题。
