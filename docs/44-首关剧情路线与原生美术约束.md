## 问题与本轮结论

用户反馈原生改造后的1-1建模退化。对照原TS截图、旧Godot截图和实际关卡内容，问题不止是材质：通用生成器把每条高差邻接都强调成相同浅绿色坡板，花床退化为单色薄盒，原遗迹的石灯、蘑菇、草地和墙面植物层次消失。空间虽然可以走通，却弱化了“选择一节根路—探索或修复—小花回应”的场景表达。

本轮只处理1-1的表现配置。先确定以下玩法与叙事合同，再选择原有美术资源和原生物件；不能把“角色全露出”“最短路线最明显”“所有地面一样平整”作为独立优化目标。

## 剧情与地点合同

| 地点 | 原内容与意义 | 表现边界 |
|---|---|---|
| 起始岛，根台 `f:0:0` | “引一节芽，决定第一段路”，预算只有1 | 东、南都可选择。不要用固定便道、路标或装饰自动选出答案 |
| 起点歇息角 `f:-2:-1` | 收集、休息，没有赶路时限 | 自然边缘植物，保留孢子与歇息位置 |
| 南侧低岛，`f:0:2` / `f:0:3` | 可选孢子与观察：“露薇种下第一节路，小花朝她靠近了一点” | 保留探索价值和高差，不改为主线必经或收集门槛 |
| 东侧岛前排 h1，花床 `f:3:0` | “种下第一束微光”，目的地是等待回应的小花 | 根路先接前排，花床保持原坐标；石质花床承托原植物 |
| 东侧岛后排 h2 | 原遗迹高台、空间层次与探索 | 保留合法通行和遮挡深度；石灯、红蘑菇位于外缘，不放进通行中心 |

原始开场：“小花在缺口那边等你。点亮根台，再选择根须向哪里长。”东向直接修复与南探回收改道均为合法玩法。三颗孢子、观察、伙伴与主动修复继续保留。关卡JSON与修改前快照逐字节一致。

## 实际实施

- `garden_art_profile.gd` 提供仅含表现的Resource：关卡身份、地表贴图、踏边方向、装饰锚点/用途、石质花床。
- `first_garden_art.tres` 仅匹配1-1。起始岛、低岛、高台采用原石砖、草地、苔地的固定分区；不再依赖当前格子哈希随机挑植物。
- 原浅绿坡板换为原石材贴图。右侧保留明确踏边，另两处不再叠重复楼梯条纹。**它们仍是可见、可走的石质过渡坡面，没有删除原合法边或碰撞。** 本轮没有把斜面重做为真实阶梯几何，不能宣称恢复了原预渲染楼梯模型。
- 花床以原生石块边缘与低土床承托原flower/bloom植物裁片。原图片带等角底座，不能把完整图片再叠在3D地面产生双重透视。
- 恢复原素材石灯、红蘑菇、自然花草和5株墙面藤蔓。地面植物使用真实支撑高度；墙面藤蔓沿墙面朝向摆放，避免billboard与墙相交而仅剩零星像素。
- 地形、支撑采样、碰撞和角色motor仍使用同一原生空间。未修改输入、角色图像、相机、全局规则、地图高度、花床/收集位置或存档格式。其它关卡继续原表现。
- 踏边方向加入几何缓存签名。播种仅新增对应根桥，固定岛的Node、Mesh和碰撞Shape身份保持一致。

## 后续同类调整的步骤

1. 从关卡定义核对剧情、资源预算、主线、可选支线、回程与回收、伙伴、失败保护；记录地点为何存在。
2. 标出通行中心、交互落脚点、缺口、视线遮掩与装饰外缘。遮掩不等于错误，缺口不等于需要补桥。
3. 先做单关表现配置。表现资源只消费已存在的状态与支撑，不开新路、不添加发现锁、不挪剧情点、不写规则状态。
4. 新增或重塑承载模型时，同时处理可视面、支撑采样、碰撞和motor通行宽度；若仅改贴图和装饰，应保持原几何。不能靠透明地面、角色永远置顶、隐藏坡面或传送遮掩穿模。
5. 必须玩通最短合法路线和可选探索回程，检查无种路不可过、占用支撑不可回收、撤销、刷新、连续走动及每条受影响高差边。规则快照相同不能替代这些实际体验检查。
6. 同一冻结运行源导出debug/release，核对动态接地和截图，再发布。把失败原因和修正记录下来，通过后才考虑推广到其它关卡。
