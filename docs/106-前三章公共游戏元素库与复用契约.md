## 后续常见操作

### 一处替换全部花坛

在 `element-theme.json` 给 `flower`、`bloom` 设置新的 `res://` 纹理路径；所有引用普通石质花坛的关卡都会使用它们。实时预览可调用：

```gdscript
stage.apply_element_theme({
    "schema_version": 1,
    "resource_overrides": {
        "flower": "res://assets/my-theme/flower.png",
        "bloom": "res://assets/my-theme/bloom.png"
    }
})
```

主题参数是完整覆盖集合，每次替换先验证所有槽位，失败保留旧主题。仅路径替换要求同画布；若脚点、透明留白或硬底改变，须同时修改 `prop-elements.json` 的测量定义，并验证通行和完成前后状态。花坛自身大小和脚锚不再靠逐关散落常量维护，1-1和3-3/3-4的已知尺寸例外保留。

3-3自然根盆使用 `symbiosis-root` / `symbiosis-root-settled`。1-4归铃点、2-3乘台点、2-4共享邀请点、3-2记忆机关不会被公共“花朵”分类补画成花坛。

### 统一替换地板和墙纸

全项目相同资源替换使用公共资源别名；只替换某章或某一用途则修改章节主题槽。地板有 `stone/grass/moss/terrainTop`，墙面有 `wallLeft/wallRight/terrainSide`，楼梯单列 `stairPaint/stairGrain`。预览调用 `SurfaceDefinitions.set_theme_overrides(chapter, values)` 后 `stage.reload_element_visuals()`；未知槽、无法解析的纹理和非法密度拒绝提交。

旋转板保留局部 `texture_origin/texture_turn`；贴图不随重建换方向。墙纸不能改变墙高，地板贴图不能创建支撑或消除解谜缺口。

### 角色换装、换蘑菇宠物

`actor-elements.json` 记录角色身份、皮肤、动画、脚锚、运动和携带规则。新增外观使用 `ActorDefinitions.register_skin(id, definition)`，应用使用 `stage.set_actor_skin("luvie"或"buddy", id)`。已验证更换伙伴的渲染器仍保留身体、碰撞、位置、规则快照和行走动画相位。

皮肤不会改变主角/伙伴身份。当前跳跃是视觉动作，不能越过规则缺口；宠物能力目录描述现有能力，没有将任意新蘑菇技能接成可执行玩法。后续新功能需要新增能力ID、规则命令和相关测试。当前没有新增换装界面或保存皮肤选择的系统。

### 编辑器组合与导出

编辑器可复用目录的元素类型、资源槽、测量参数、状态变体和实例支撑。`element_id`必须能解析，实例ID不可重复，支撑引用必须有效。现阶段 `source_level` 是导入导出的权威数据，`instances` 是派生索引；修改索引不会暗中修改谜题。装饰生成器、运行时派生路、已有定制关卡规则不能当作任意通用图元随意拼接。

搬运物另记录地面放置、依附持有角色、已交还/消耗三个生命周期；空支撑仅在与快照一致的离场物品上允许，不能被其他元素用于绕过支撑校验。`scenery.*` 中的资源型登记包含可引用图像，不是可直接放置的素材栏；未来素材栏应按语义显式筛选，避免把角色动画帧当装饰模板。

```powershell

godot --headless --path godot --script res://tests/export_element_inventory.gd -- --write
```

## 缓存与发布规则

资源替换同步失效舞台材质、图像、角色/携带、自然图集、遮挡测量与池塘私有材质。道具定义版本同步失效布景摆位和碰撞缓存；草地效果绑定语义而非图片文件名。移动板尚未落稳时舞台主题事务拒绝重建。

`PropDefinitions.reload_definitions()`支持同结构测量数据刷新；新增资源注册或结构仍需重启。资源路径热换用 `apply_element_theme()`，不是依赖重读道具测量表。后续编辑器应集中调用这些入口并显示错误，不直接修改共享内部字典。
