## 一、2-3「雨滴节拍」

### 关卡机制
- **通关条件**：`flag("latch") and together(world_tiles)`（固定便道 + 两位在一起）
- **起点**：f:-4:0（露薇），f:-4:1（小苔灵）
- **花台(stage)**：m:stage:0:0，rotate 类型，5格 shape
- **琴台(song)**：f:-4:0，排练舞曲
- **便道(latch)**：f:0:-4，固定后打开路径
- **花心(core)**：f:1:-4

### 正确流程（根据源码分析）
1. 露薇走到花台上
2. 排练舞曲：默认 song = ["turn", "rise", "rest"]（转庭→升台→停拍），顺序正确
3. 试奏：花台转90度后升到 h2，带着露薇到高处
4. 露薇从花台走到北岸 (0,-4)
5. 固定便道（latch），打开 (-4,-1)→(-4,-4) 和 (-4,-4)→(0,-4) 的路径
6. 切换到小苔灵，走回露薇身边
7. 两位到花床旁，种微光→通关

### 测试状态
- **进入关卡**：✅ 成功
- **排练/试奏**：✅ 成功执行三拍（转庭→升台→停拍），"第3拍：停拍"
- **花台升起**：✅ 花台升到 h2
- **走到北岸固定便道**：❌ 角色从花台无法走到 h2 层的北岸
  - 花台转一次后覆盖 (0,0),(0,-1),(0,-2),(-1,0),(-2,0)，升到 h2
  - 从 h0 的 (-3,0) 到花台 h2 的 (-2,0) 高度差 2，不能直接走
  - 需要先在花台升之前走到花台上，再随花台升到 h2
  - 但"重新排练"操作难以通过 UI 触发（操作面板选项点击不精确）
- **通关**：未完成

### 发现的问题

#### Bug-6：操作面板选项点击不精确
**现象**：操作面板中的"重新排练"、"开始/继续试奏"等选项难以精确点击，尝试多个坐标经常点不到或触发其他操作。
**影响**：无法可靠地执行关卡操作，测试效率极低。

#### Bug-7：试奏后角色无法从花台走到北岸
**现象**：试奏完成后（花台升到 h2），角色在 h0 层无法走到 h2 层的北岸。需要先在花台上再试奏，但"重新排练"操作难以触发。
**可能原因**：设计意图是先走到花台上再试奏（花台带着角色升到 h2），但 UI 交互问题导致无法正确执行此流程。
**提示信息**："露薇走上花台，小苔灵留在琴台。转庭必须先于升台；可以单步试奏。"

### 关卡设计观察
- 2-3 的舞曲机制创意好：排练→试奏→花台转动升起
- 默认 song 顺序正确（转庭→升台→停拍）
- hint 信息清晰："正确朝向应向北。若先升后转，重新排练；到北岸后固定便道。"
- 核心问题是 UI 交互（操作面板选项点击不精确），而非关卡逻辑本身

## 二、2-4「池塘守护者」

### 关卡机制（源码分析）
- **通关条件**：`flag("pollinated")`（授粉完成）
- **起点**：f:-4:0
- **花粉(pollen)**：f:-4:0，flower 类型
- **种植(plant)**：m:boat:0:0，flower 类型
- **滑动(slide)**：m:boat:0:0，turn 类型
- **邀请(invite)**：m:boat:0:0，flower 类型
- **花心(core)**：f:10:0
- **船(boat)**：slide 类型，3x3 网格，可沿 x 轴滑动 distance=6

### 正确流程（根据源码分析）
1. 走到船上（移动花园）
2. 种蜜花（plant flag）
3. 滑动花园靠近左岸
4. 邀请光虫（invite）落在蜜花上
5. 滑动花园到右岸
6. 邀请光虫飞向核心花岸授粉（pollinated flag）
7. 到花床种微光→通关

### 测试状态
- **进入关卡**：✅ 成功
- **走到船中心**：✅ 成功（从起点(-4,0)向右走4步到船中心(0,0)）
- **操作面板**：✅ 弹出"种一朵蜜花"、"移动整座花园"、"邀请光虫"三个选项
- **种蜜花**：❌ 点击操作面板选项未成功（Bug-6：操作面板选项点击不精确）
- **通关**：未完成

### 发现的问题

#### Bug-8：2-4 操作面板选项点击不精确（同 Bug-6）
**现象**：在船中心弹出操作面板后，尝试多个坐标点击"种一朵蜜花"均未成功。
**影响**：无法执行种蜜花操作，关卡无法继续。

### tiles 布局
- h0: 左岸 (-5,-1)到(-3,1) + 右岸 (9,-1)到(11,1)
- 船(boat): 3x3 网格，可滑动（左/右两个位置）

## 三、测试方法问题汇总（2-3 和 2-4）

当前测试的主要瓶颈仍然是**操作面板交互**：

1. **操作面板选项点击不精确**：选项的精确位置难以确定，点击经常落空或触发其他操作
2. **"重新排练"等关键操作难以触发**：需要精确点击操作面板中的特定选项
3. **设置面板频繁误触**：按 R/Esc 等键时容易打开设置

### 建议
1. **提供调试接口**：让测试能直接调用 `world.apply("resetSong")`、`world.apply("play")` 等内部 API
2. **操作面板加键盘导航**：用方向键选择选项，Enter 确认
3. **修复设置面板误触**：R 键不应触发设置
