# 主界面与继续关卡的导航语义

日期：2026-11-06。

用户明确指出：“回到花园”指返回主界面，而非关闭设置后仍停在1-1。此前文档34验证了关卡恢复操作，却没有满足这一导航目的。本次以原TypeScript的`mainMenu / levelSelect / game`三类场景为依据纠正，不把选关地图当作主界面。

## 1. 明确的入口与去向

| 入口 | 结果 |
| --- | --- |
| 返回主界面 | 显示独立品牌首页，隐藏关卡世界、标题、操作栏和方向按钮，游戏保持暂停。 |
| 继续当前关卡 | 只关闭游戏中的设置或其他弹层，继续当前关卡；保留普通暂停中尚未提交的动作。 |
| 开始旅程 | 从主界面进入“关卡地图”，选择解锁的关卡后才进入游戏。 |
| 继续上次的微光 | 从主界面恢复稳定进度、已种道路及位置；从归档回看返回时恢复活动旅程，不把归档当作活动存档。 |
| 主界面的设置、图鉴、纪事、存档工具 | 返回或Esc回到主界面，不恢复隐藏的1-1。 |

原含糊的“回到花园”改为“返回主界面”。游戏来源的子页另列“继续当前关卡”，主界面来源的子页不显示这条恢复游戏入口。正常启动首先显示主界面；明确的关卡启动参数仍可直接进入关卡。

## 2. 进度和规则保护

回主界面取消未提交的移动、播种预演及自动路线、等待和按键意图，只保存`session.world.snapshot()`里的已提交状态。不会将`motion.after`或准备中的事务当作已发生的结果。继续之后不重放旧输入，玩家仍可正常重新播种。

普通“继续当前关卡”保留暂停事务，与真正离开关卡的处理分开。浏览已完成花园、归档回看仍遵守原拒写保护，活动run和完成memory不互相覆盖。新旅程尚无活动进度时，主界面的继续按钮明确禁用。

主界面使用原`assets/images/main/bg.png`和`assets/images/material-ready/menu-logo.png`原字节图片；没有重画角色、改地形、移动轨迹或种子开路规则。

## 3. 实现与验证

`Main`明确维护`home_active`和`has_active_game`，分别处理`home / map / continue / resume`。`GardenHUD`提供`show_home()`与统一的返回按钮构造，主界面背景和关卡HUD可见性相互独立。

调试模式原有规则/镜头工具可继续直接进关，新的`?qa=1&home=1`观察正常首页流程。新浏览器检查不发QA快照或动作写请求，实际点击“返回主界面”后检查首页和关卡隐藏状态，再验证保存重载与继续。

| 检查 | 结果 |
| --- | --- |
| Home控制器与真实HUD合同 | 379项通过，含输入隔离、取消未提交事务、道路保留、回看隔离及原图字节检查。 |
