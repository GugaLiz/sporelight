# 全关卡位置整理计划与验收

2026-11-11。**状态：15关位置整理与分版本独立验收完成，4222已更新最终release；最终源码、边界与交付见第8节。** 用户确认本轮尺寸可用，指出1-3画面中的位置仍不协调，要求全部关卡调整位置。71号保留当时的元素/比例及已报告问题验收历史；本轮不能用旧通过结论否定新反馈。

范围仅为落点、脚锚、支撑、边缘余量、与通路/机关/角色的相互位置及动态随动。冻结现行物件大小、角色大小、镜头密度、地形/高度/规则/存档；需要移动的是有理由的对象，不为“每关都改”机械平移正确实例。15关全部审查，1-1仍是已认可参考，1-2仍是正式revision2。

## 1. 修改前证据与判断方法

独立验收者实际查看[用户1-3初态截图](qa-godot-native/scene-placement/2026-11-11-position-feedback.png)，并重新查看15关桌面普通清场/全景各一张，补看1-4与2-1最新普通图及1-3～3-4十关初态图。使用既有accepted-stroll、landmark-stroll、final-npc-stroll和final-visual；不同批次用于对应仍未改变的摆位，花门/喷泉/NPC以最新专项为准。此次重看不增加71号历史530张独立截图统计，未运行GPU或改运行时。

用户截图中1-3的控制台在真实转庭中心、人物在转庭上，没有足够证据将整个转庭或人物位置判成错误；主要需要整理固定岸装饰的贴边和相邻主体投影，不能先移动规则操作中心。该图只有一个朝向，不能从单张图断言存在动态漂移或实际碰撞阻路。

三个概念分别记录：

- **源坐标**：原站2D scenery表中的(x,z,h)，用于追溯身份。`.24`向边缘偏移及旧绘制顺序不是3D最优构图的保证。
- **当前3D实际落点**：经原生逻辑到物理映射、实际surface高度和Sprite脚锚后的全局位置；以运行节点/支撑面为准，不能把源h直接当世界Y。
- **画面问题**：底座/脚部越界、主体相互遮住、压交互/靠岸位置，或者虽有支撑但孤立贴角、对齐成一排造成的不协调。后者是布局调整理由，不能伪称已经证实浮空/堵路。

源实例编号与原坐标见[104条清单](qa-godot-native/original-elements-audit/final-source-inventory.md)。坐标候选必须在保留尺寸条件下通过完整底面支撑、当前/未来接岸区排除与角色通行检查后才落地；本页不凭屏幕像素编造最终世界坐标。

## 3. 顺序与放行条件

1. **先做1-3**：固定岛装饰先处理贴角/拱与拾取/核心前灌木；输出源位置→当前实际位置→候选实际位置→支撑ID→移动理由。普通初态、完成、清场、全景、各旋转朝向确认后，才推广共用摆位辅助。
2. **山谷**：1-1/1-2只回归或有证据的局部微调；1-4分离同格灯/莲。不要全关统一缩进系数。
3. **池塘**：2-1三水位；2-2镜叶可放区；2-3高岸接头/拱；2-4灯/蕨与核心、船/岸分属。池外生态可调整同一水面/岸带的间距，不更改水域轮廓或尺寸。
4. **洞窟**：逐关优先清空桥口、低门、控制台前与核心接近方向，检查隐藏区/水路/光路父级。3-4保留已解决的鼹鼠位置。
5. **云庭**：以细茎花、盆栽、终点标记的投影分离为主，保持建筑和机制中心。云2台面与水口回归。
6. **集成验收**：受影响实例完整脚/底座支撑及核心/角色/未来靠岸区检查；15关双尺寸普通/全景/返回静帧；有运动父级的起/中/止/撤销；代表桥口实体走过与当前玩法路线。最后实际源码/资源一致再交付。

每关记录为“保留”“已移动待验”或“独立复验通过”，附准确实例、旧/新位置及证据。不能仅凭距离阈值/源坐标一致宣称美术布局合理；也不把一处瞬时角色遮花全部判成硬缺陷。任何条件下没有合法空位时，保留尺寸并重新选择同区域候选，不新增地块、不抬物件、不关闭深度、不悄悄删除元素。
