# 守护者关自然机关与界面适配修正

2026-11-15。当前状态：**本轮自然机关、光学与原生界面检查通过，已部署到原本地入口**。本记录不作为浏览器截断、全关界面或性能问题已解决的证明。

## 反馈、根因与范围

用户在3-4“沉睡的守护者”截图中指出界面适配和场景文字表达不自然。内庭、送水庭、花台、反光庭仍使用通用浅色圆牌，以 `Label3D` 的“转／↕”说明用途；高处镜槽只是纯色圆饼，重镜与光柱也没有采用已调整的银镜与柔光表现。

已确认的场景原因：`MechanismProps._instrument()`为四个控制器创建同类圆牌，3-2和3-3专用自然道具分支没有覆盖3-4；高槽仍由stage的通用slot分支生成，银镜和柔光此前限定2-2。这属于GQ-003/014/017的表现适配问题。

截图右边缘控件与实际浏览器视口、DPR、缩放及截图裁切的关系仍须独立复现。当前不能断言具体截断原因，更不能由原生场景测试推出浏览器问题已经修好。GQ-019的极窄屏长帮助覆盖保持开放。

## 自然造型与物理边界

3-4专用 `guardian_dressing.gd` 从 `MechanismProps.build_mark()`接入，仅处理本关五个标记。复用现有symbiosis木轮、水力柱PNG，没有生成新位图；三个旋转控制器通过实际附着结构区分职责，不以圆牌换图标或仅换颜色。

| 对象 | 候选呈现 | 保留的边界 |
| --- | --- | --- |
| 内庭 `inner` | 木轮、真实横向驱动轴与底部齿牙 | 原模块、同格操作点及旋转局部偏移 |
| 送水庭 `water` | 木轮、带槽壁和水面的浅出水槽 | 伙伴专属小庭、原供水方向与通行限制 |
| 载物花台 `lift` | 水力立柱和随真实高度移动的浮子 | 原升降、供水、承载、碰撞和安全回程 |
| 反光庭 `light` | 木轮、黄铜承轴叉与侧向微调旋钮 | 旋转模块身份、原光路朝向与角色站位 |
| 高镜槽 `highslot` | 低矮凹面、石边和两侧夹座 | 原 `f:8:0` 落镜格，无新增硬障碍或落脚限制 |

尺度与占地分别记录：轮的可见主体约 `0.359×0.62m`，柱约 `0.315×0.62m`；不直接复制3-3的0.9m高度。原控制器局部偏移为 `(0.28,0,0)`，light为 `(0.28,0,-0.04)`，随对应模块旋转。低矮承托高 `0.025m`，原画石脚从承托顶面注册，避免“自然石脚上再叠厚圆柱”的95号已否决形式。

`_cylinder()`底半径是传入半径的1.05倍，因此旧实际硬脚为上半径0.19m、下半径0.1995m，导航包围占地 `0.399×0.399m`。本轮这些XZ边界、地面floor与 `floor+0.41m` 硬碰撞顶面保持；可见低座高度与硬碰撞高度不能混写。高槽几何仍在原 `0.52m`宽、`0.04m`高范围内，夹座不新增阻挡。

附着轴、槽和叉座随模块同一角度旋转，并与基座同步位移；浮子按实际升降进度更新，反向、撤销、恢复不得累积偏移。角色、伙伴、花坛、岛体尺寸不受本适配器影响。

## 银镜与光路

3-4重镜复用已有双面银色椭圆镜、玻璃和金属支架，镜面中心与真实光轴统一为支撑面以上0.37m。原角度、镜面法线、拾取格、初始镜槽内北移0.20m和高槽放置语义保持；携带继续使用既有叶包图示。

光柱复用已有带收束的圆柱主体及克制光晕，沿规则真实线段渲染；正常深度、镜面接点、遮挡与转动期间上下游显隐分别检查。模型改善不能修改 `rays()`、旧反射角度、受光条件或把装饰光当成可走支撑。

## 原玩法与界面验收

3-4原有根、水、载物、光、双人归来流程保持。三节预算、逐格前端搭建、接通自动固定、伙伴送水、露薇搬镜、高槽放镜、实际当前光照和双人合法照料仍成立。不能把3-3新“蓄露升台接路”规则推广到本关，也不能把 `star`历史点亮替换为当前光照条件。

界面适配须另验桌面和小横屏的HUD、操作面板、选项滚动及四边界；长帮助需要展开后检查，不能只看收起态。场景实体文字清零不等于移除原操作界面文字、主动分级帮助或状态反馈。浏览器还需核对实际 `window/viewport`、DPR、缩放、画布与CSS显示尺寸，原生GPU截图不替代Web实玩。
