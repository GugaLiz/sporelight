## 统一覆盖

| 入口 | 接入方式 |
| --- | --- |
| 浏览器tab和书签 | 专用简化SVG、16/32px PNG和多帧ICO，图标URL带版本参数 |
| 默认favicon请求 | `/favicon.ico`实际返回ICO，移除旧204分支 |
| Safari固定标签 | 独立单色SVG和苔绿颜色 |
| Apple收藏/主屏幕 | 180px完全不透明图标 |
| 手机/桌面添加快捷方式 | manifest声明192/512px普通图和独立maskable图；保留中心安全区 |
| Godot窗口 | `application/config/icon`指向专用512px PNG |
| Windows文件及任务栏 | 原生ICO及Windows导出图标配置；预设中包含原生ICO文件 |

图标源码、确定性生成方式、格式清单及来源见 [品牌资源说明](../assets/branding/README.md)和 [资源指纹](../assets/branding/manifest.json)。新图标不含外部图片或字体；原游戏素材没有变化。主图保留卷帽尖、小圆帽和宠物表情，小尺寸只保留两种帽形、少量白斑和短奶油柄。HTML图标缓存参数已升级为`sporelight-mushroom-2`。

Web shell和原TypeScript入口均使用相对路径。manifest位于`branding/`，`id/start_url/scope`为`../`，图标路径相对manifest自身。没有启用离线缓存或新建service worker。Godot两个Web预设仍关闭自动图标注入，避免和手工声明重复。

- 解析Windows正式EXE的实际PE图标资源，确认引擎写入16/32/48/64/128/256六种标准尺寸；每一帧解码后的RGBA像素与新ICO对应帧完全一致，见 [当前EXE资源报告](qa-godot-native/mushroom-icons/windows-icon-resources.json)。源ICO额外的24px帧不要求引擎写入EXE。
- 新Web与Windows正式导出成功；正式Web PCK由同版引擎无头启动60帧正常退出，见 [当前启动日志](qa-godot-native/mushroom-icons/release-smoke.log)。

- Vite生产构建完成，检查其图标链接在`/sporelight/`子目录下仍对应实际输出文件。当前PATH无npm命令，使用同一项目已安装的`node node_modules/vite/bin/vite.js build`完成构建，无依赖安装。

本轮没有重新操作浏览器、手机或Windows桌面UI；此前浏览器访问授权拒绝继续遵守。实际显示缓存与手机添加结果没有冒充已观察，验证范围是原尺寸图像检查、导出EXE资源和实际HTTP交付。已有穿模、性能和小屏阅读问题不因图标更新被关闭。

## 后续维护

先改`assets/branding/`的SVG母版，再运行`python -B scripts/prepare_brand_icons.py`，最后重新导出；不要只替换build内图标。公开品牌文件由导出脚本复制并记入`browserAssets`摘要。若修改图标母形，增加HTML图标版本参数以刷新旧favicon缓存；保持同尺寸帧和独立maskable图。

字段依据：[Godot Windows图标说明](https://docs.godotengine.org/en/stable/tutorials/export/changing_application_icon_for_windows.html)、[MDN manifest icons](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Manifest/Reference/icons)。
