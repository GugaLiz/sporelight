## 3. 先保护玩法，再改善表达

每关优化前必须完成文档 57 对应卡片：

1. 目标与核心决策：玩家在比较什么，哪个行动会改变世界。
2. 因果链：初态 → 操作条件 → 中间状态 → 可通行结果 → 完成操作。
3. 不变量：预算、邻接、高差、障碍、角色能力、物品归属、可选/必需条件。
4. 替代路线与回程：保留已有合法解，不把参考路线误当唯一允许解。
5. 失败恢复：占用保护、关键物件安全、撤销、暂停、回首页、继续、读档与重开。
6. 可见性：哪些是可操作目标、哪些是装饰、哪些信息需要玩家探索后才显露。

**全局完成语义**：主线的 `ready()` 只是机关条件。实际还需要露薇在花坛合法同层邻近位置获得 `repair` 命令，并满足伙伴会合 `together()`，才提交完成。不能改成到达某格自动结算。云庭另有独立完成语义，详见文档 57，不能一律套用主线伙伴条件。

普通微光、观察、休息不升级为门槛；末关的八份赠礼是机关阶段结果，不能恢复成旧版“先找齐八颗散落孢子”的任务。

## 4. 渲染与空间规则

| 编号 | 必须满足 | 禁止的捷径 |
| --- | --- | --- |
| R01 原素材与风格 | 延续原角色、花坛、石材和章节美术；修正采样、比例、接地与密度；池塘/洞窟保持自身材质和色调 | 全关改为首关暖石色；用程序盒子替换完整花坛；任意缩小人物来让画面显得宽敞 |
| R02 几何同源 | 可见表面、碰撞、支撑高度、步态与目标物位置读取同一个关卡 profile；逻辑/物理映射往返一致 | 只移动图片、单独抬高碰撞、传送角色或改变规则格来掩盖错位 |
| R03 阶梯结构 | 踏面水平、立面真实、上下接岸完整；侧面上缘随踏面；通用0.60跨度采用四级、0.15踏深，0.65高差对应0.1625级高；首两关专用几何保留 | 用坡面横线冒充台阶；将完整等角楼梯图拉伸到坡板；以高侧板遮住踏步；照搬首关梯级数到所有关卡 |
| R04 材质尺度 | 顶面、侧面、立面分别映射；重复密度对应物理尺寸；缓存 key 含 profile 和有效选材参数 | 窄分片拉伸纹理、同纹理跨台阶切割、不同关卡共用错误缓存 |
| R05 深度与接触 | 保留实际前后遮挡；原图脚锚贴真实地面；接触暗部独立贴地；物件透明只按现行合理遮挡策略 | 角色永久置顶、关闭全局深度、整个人向上漂、将美术暗部宣称实时阴影 |
| R06 路与装饰 | 岛体、缺口、障碍与落脚点先可读，再布置外缘植物；装饰不新增规则支撑或隐藏机关 | 给中央岩石铺可走底座、用花草掩盖拼缝或错误通路、为了留白删除可选探索 |
| R07 结构稳定 | 普通行走不重建地形；生长只更新受影响连接；固定岛、材质、镜头不跳变 | 每帧重建所有网格、预览时先开放真实道路 |
| R08 章节语义 | 真实水域才有水面；真实光路反映当前物件与朝向；影路区分实时投影和记忆 | 所有池塘/云庭铺整张水板；将供水装饰线画成可走桥；提前揭露洞窟未知道路 |

首关根桥按首关高差显示；连续根桥从真实前驱逐节延伸，复用同源几何与材质显现能力，但不复制首关的预算、按钮布局或根台径向选择。首关回收立即移除消失格几何，并非倒放生长。转庭、升降、平移在离岸时收平外接梯并封边，同一刚体内部梯保留，落稳才按新合法连接生成接岸梯；输入锁、提交、撤销和取消遵守事务边界。具体流程见66号。

灯笼与垂藤只放在真实且安全的固定边缘，排除当前/未来停靠、根路 socket、起点及隐藏、水面、动态模块等支撑；无合适位置可以不放，不设“每关必须几个”的装饰配额。1-2 删除固定格后允许新增指定暴露边面和沿口，原顶面、踏面、立面及 profile 仍受保护，不能借此整体重录首两关几何基线。

## 5. 移动、交互与生命周期规则

| 编号 | 规则 |
| --- | --- |
| M01 通行权限 | `world.tiles/neighbors` 决定合法连接，motor 执行真实胶囊通行；新几何不能绕过未解机关；普通跳跃不能成为越缺口捷径 |
| M02 单一位置来源 | 真实角色根由 motor 写入；Visual 仅负责既定脚底/姿态校准；转动与升降的乘员保持合法局部支撑，不能叠加两套位移 |
| M03 体积验证 | 中心射线通过不等于胶囊能走；上下行、偏心、转弯、停步、反向、双角色和携物都须覆盖 |
| M04 支撑保护 | 不得抽走人物或关键落地物件脚下的路。台阶检查须覆盖实际胶囊脚印、未来邻接消失及支撑高度变化，不能只查人物中心或移动模块。失败事务完整回滚，保持预算、物品和位置；不默认把它们挪到安全岛 |
| I01 原界面 | 复用原 HUD、菜单、工具栏与提示容器。操作模型可因机关而异，但不能借单关优化重做整套界面 |
| I02 操作真实性 | 热区与可见物件同源；同层、距离、角色和可用性由领域查询决定；只显示合法下一步，不自动执行推荐解 |
| I03 输入一致 | 鼠标、键盘和触屏都应完成核心动作；触摸与合成鼠标去重；Enter 优先尊重 GUI 焦点；规划/演奏模式必须说明当前输入作用 |
| I04 小屏信息 | 关键信息不能只放在短横屏隐藏的目标行；沿用原按钮/状态区显示预算、阶段或禁用原因。竖屏沿用现行阻断与横屏恢复语义 |
| I05 分级帮助 | 默认显示意图而非完整解法；玩家主动查看后才逐级给出关系与具体方向；点提示开关、点内容轮换；阶段更新不自动打开已关闭提示 |
| T01 一次提交 | prepare 只预演，commit 校验 revision 并提交一次；动画/材质不得直接写规则；暂停冻结未完成动作 |
| T02 撤销与恢复 | 恢复规则、几何、双角色、物品与合法局部姿态；切关清理过渡、输入和缓存；正式继续/完成纪念/重玩语义分开 |
| T03 存档隔离 | 原生主线、云庭、旧 TS 导入和 1-2 内存试玩各按现行语义处理；不能用试玩内存仓库替换正式仓库，也不以清空玩家进度修兼容问题 |

M01 必须同时验证机关未完成时的实际阻断与完成后的实体连接，不能只验 `ready()` 或通关路线。M04 的普通操作支撑保护不变；68号允许的例外仅为经原根链、原姿态校验的旧布局存档迁移：不足四节的旧岸角色返回现有根尖/根台，四节旧档按确定映射换支撑，不补种、不丢进度，写回版本 2 后不得重复迁移。该加载兼容机制不能用于实时事务中移走占用者来强行成功。

## 6. 模块边界和允许修改范围

- **关卡表现**：新增或调整该关的 terrain/dressing/profile 能力；物件只消费规则结果。独立 profile 需覆盖高度、坐标转换、采样、材质、基础和阶梯契约。
- **共享模块**：只放跨关成立的几何、材质、动作、输入和提示能力；任何共享修改要同时回归 1-1、当前关和受影响机制关。不能在共享函数里堆每关答案。
- **规则与数据**：预算、slots/sockets、机关前提、邻接、能力、完成条件、物品与存档属于受保护范围。表现优化默认不修改；确需纠错或新增玩法时单列设计差异、原有解法影响与迁移方案。
- **1-1**：不主动改图、不换风格、不改流程。共享修改若导致其截图、脚点、接触、布局或操作改变，先修复回归，而不是顺手“统一首关”。
- **正式/试玩**：1-2 的已授权规划实验仅在专用控制器运行；“流程可玩”不能直接推导出可发布到正式旅程。

## 8. 验证入口与已知基线差异

以下是已有工具的用途，执行结果以该次日志为准：

```sh

# 首关合同、真实几何/接触与相机：按实际改动选择
```

上面 `<batch>` 是执行前替换的批次目录名。Godot 不在默认路径时使用已有 `--godot=` 参数或 `GODOT_BIN`。
