# 首关播种时墙面跳变修复与地形过渡预设

日期：2026-11-06。当前实施范围仅1-1。

## 问题与原因

用户报告：向画面左侧播种后，小岛接通楼梯，但其他墙面和楼梯也会突然消失、恢复。画面左侧对应规则方向`down`，不是改变了根芽生长方向。

核对当前Godot渲染后，问题有三个具体来源：

1. 新根芽在动画进度0就被加入绘制列表，透明度虽为0，但墙面邻居查询不看透明度。根台`f:0:0/h0`检测到未来根格`g:root:0:1/h0`后，侧墙由112像素立即变为0。回收时则拖到真正提交后才恢复，形成大块墙面跳变。
2. 楼梯绘制的动作白名单排除了`grow:`和`retract:`。任何播种/回收动画都会暂停绘制全部楼梯，连无关的右侧固定楼梯也消失，动画结束后又突然出现。
3. 固定岛体与30像素厚的根芽板使用同一邻接遮面算法。浅桥被当作整块岛屿裁掉主体墙；浅桥接低一层小岛时，自身侧面也会被拉成48像素厚。这是结构身份混用，不能通过调整透明度阈值消除。

## 本次修复

只修改表现层，规则地块、地图高度、根芽预算、邻接、通关解法、播种入口、连续走动、原相机与存档结构均保持。

- 固定岛结构依据`level.tiles`中的原始地块身份识别。生成的`g:`根板不参与裁除固定岛体侧墙；固定岛之间仍按原高度差遮面。不能仅凭`kind=root`判断，因为其他关卡的固定路径也可能使用这个表面类型。
- 根板侧面最大为它自身的表现厚度；墙砖原角点、材质和世界坐标UV算法不变，不拉伸整座岛墙来配合桥面。
- 楼梯按动画前后状态的端点ID合并：共同存在的连接透明度恒为1，新增连接随新道路渐显，移除连接随道路渐隐。固定右侧楼梯不会因播种动作被全局关闭。
- 前后楼梯集合在动作开始时建立，清除动作时清空；不在每帧重新推导两个规则端点。
- 用户明确删除的`f:2:0↔f:2:-1`、`f:3:0↔f:3:-1`两组楼梯仍过滤，不因合并连接集合重新出现。

`terrain_presentation.gd`集中定义结构遮面与连接透明度，`enabled(level)`当前只对1-1返回true。其他11关继续旧渲染分支，不在本批推广。

## 后续同类问题的处理预设

| 对象关系或动作 | 预设处理 | 验收重点 |
| --- | --- | --- |
| 固定岛连接固定岛 | 原有实体遮面与墙砖UV | 未变化墙面的轮廓、纹理坐标稳定 |
| 临时桥面接固定岛 | 桥面负责自身出现/消失，不反向裁掉主体岛墙 | 桥尚透明时，岛墙不能先消失 |
| 连接两端都存在 | 连接保持原位且不透明 | 无关楼梯不能跟动作开关闪烁 |
| 新增或移除连接 | 仅对应连接随进度渐显/渐隐 | 0与原静态一致，1与提交后静态一致 |
| 撤销、读档或低动态即时提交 | 直接构建相应稳定结构，销毁旧预览缓存 | 不残留未来桥面、旧楼梯或过期透明度 |
| 旋转、升降、影路、水位等其他机制 | 继续原分支；先定义结构身份与移动面规则，再单独启用 | 不把首关根板规则直接套到所有模块 |

以后遇到墙体跳变，先对照同一状态的“静止前→0→极小进度→25/50/75%→1→提交后”，区分规则状态、稳定结构、动态表面三者。不要把“正在参与过渡的绘制元素集合”直接当作“已完成的实体邻接图”；不要使用透明度阈值切换邻接，那只会把跳变推迟到阈值处。

推广时只需在明确的关卡预设中启用公共表现策略，再按该关的真实动作验证。没有验证的关卡保持原分支；不改变规则图来迎合画面。
