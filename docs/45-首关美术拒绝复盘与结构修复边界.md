## 截图与源码暴露的问题

1. **几何问题被当成材质问题处理。** `native_surface.gd` 在每格中心留平台，边缘生成半坡，再沿横向肩部衰减；相邻两格拼成独立窄坡。其折线轮廓、侧肩与高台平面关系没有因换贴图而改变。上一批仅换石材并去掉两处踏边，仍保留三条起伏，视觉上继续像插入平台的斜片。
2. **贴图不能直接证明建模改善。** 同一水平铺地图被映射到斜面，石块在大斜面上拉长；草地按格切换，形成明显方块边界。原砖墙、花床、植物属于细腻插画，粗糙几何轮廓与它们不协调。继续加藤蔓与灯只能增加信息量。
3. **预留入口与尚未生成的路缺少清晰关系。** 原生层为了播种前后稳定，提前为两种根芽预留坡口；截图中缺口未接通时低岛仍有突起斜片。后续应在保留固定墙稳定的同时设计真正的接岸端部，不能用新增永久路或删除未种路的限制来掩盖。
4. **交互浮窗单独存在问题。** `garden_hud.gd` 将浮窗放在目标屏幕位置加偏移，没有检查它是否遮住目标岛。高度公式为 `46 + 49 * 选项数`；但44像素标题关闭按钮、上下内边距、7像素间隔和两枚44像素按钮已需要更多空间，截图因此出现只有两项仍需滚动、第二项不完整。此项尚未修改。
5. **验收门槛选错了。** 原规则、物理与存档测试能证明玩法未丢失；debug/release像素一致能证明包一致。它们都不能证明比旧画面更好。此前将这些结果作为发布依据不充分。

## 下一次实施顺序

1. 用原TS与原Godot画面作构图参照，固定“起点根台—南侧可选观察—回收改道—东岛前排花床—后排遗迹”的关系。先比较轮廓、尺度、落脚点和遮掩。
2. 在独立候选中先做无装饰的1-1结构，使用Godot场景中的岛体、接岸连接和高台部件，明确每段连接对应哪条原合法边。不要把所有高差邻接自动强调为三条相同楼梯；也不能直接藏掉实际支撑或删除原合法通路。
3. 接岸入口、高台顶面、侧壁和通行面作为同一结构处理。人物实际胶囊、脚点与可见承载面共同校验，检查上下、偏心、停步、转向与回程。轮廓没有通过对照前不加植物或新贴图。
4. 修复操作浮窗的实际内容高度，让两个方向完整显示；位置避开角色、缺口与花床。保持原有方向选择、键盘确认与取消规则，不自动选向。
5. 结构与交互均稳定后再恢复原素材的石材、草地与少量装饰；逐项比较，不同时重排地图与重画所有物件。
6. 独立候选先保留对照图和实际走动证据，包含开场、东/南播种、回收与修复。下一版美术在得到明确体验反馈前不自动覆盖4185。
