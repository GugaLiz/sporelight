# 穿模与位置异常根因分析及调整规则

恢复说明（2026-11-12）：用户随后补齐源码至 `5059b55`，完整性检查已通过。现已重新导出并部署 `updated-20261112-release`，当前运行源 `773bc483` /580文件，见 [打包记录](qa-godot-native/repack-20261112/summary.md)。下文39处引用/7份测试缺失及无法重建的结论专指更新前快照；本次重新打包没有实施本文提出的游戏几何修复，也不据此关闭用户的穿模反馈。

日期：2026-11-12。用户反馈多轮调整仍有穿模，随后补充“好像是1-4”。本轮由三个 agent 分别审查碰撞与移动、素材与摆位、测试与版本；以下区分代码可证事实、待复现风险及历史记录。本轮没有调整场景坐标、比例、玩法、碰撞几何或用户存档。

## 1. 当前结论与证据边界

反复出现问题的原因不只是某一组坐标没有调好：**部分可见硬物没有进入碰撞登记，实际位置与逻辑状态存在不同恢复路径，现存路线验收不能独立证明全部可见硬物与运动中段均无侵入。** 继续逐处平移不能覆盖这些缺口。

1-4 是本次优先定位关卡。能确认该关花门门柱的硬物登记遗漏；喷泉盆沿、重杆恢复和双人站位有具体风险链。尚未取得用户异常帧或对应存档，不能宣布已复现本次问题，也不能将首关缺陷当作1-4的解释。

另有一个先决问题：当前工作树不能完整重建。只读计算的运行源摘要为 `f39fc9e5b574b89ce0c53511fd3e5cc6ef2d85100bd088150073572781429145`，497文件；README原来宣称的 `91d4c445` / 580文件不对应当前快照。现存构建元数据未发现匹配当前摘要的包，检查时4222没有监听。此事实不能证明用户游玩的是哪个版本，也不能推断文件缺失的原因。

当前存在39处静态资源引用目标缺失，另缺7份门禁要求的测试本体。例子包括 `native_actor_pose.gd`、`mechanism_props.gd`、`original_prop_ratios.gd`、`original_garden_dressing.gd`、`original_scenery_placement.gd`；部分脚本只留下 `.uid`。根 `AGENTS.md`、项目 `game-scene-quality/SKILL.md` 主文件，以及README引用的若干后续规则/验收文档也不在当前快照中；仅存的项目适配参考文件不能替代它们的完整内容。

因此，本轮依据现存源码分析并增加完整性门禁，不启动旧包冒充当前版本，不把历史“通过”当作当前验证结果。

## 3. 为什么原验收没挡住

1. **遗漏清单被用来证明自己完整。** 路线测试调用与寻路相同的 `prop_physical_point_clear`，未登记的可见硬物自然不会失败。需要从可见硬物反查碰撞登记，再执行独立物理形状查询。
2. **运动中没有同等采样。** [路线测试](../godot/tests/native_route_test.gd)77–78行在 `app.motion` 非空时返回；88–91行累积脚部/支撑误差，201行仅输出，没有对应误差阈值失败判定。统计数量不等于检出了穿模。
3. **少了测试可能仍出现绿灯。** 原 [检查入口](../tools/godot-migration/check-native.mjs)按目录发现当前存在的测试；只剩 `.uid` 的测试本体不会被执行。多个 `--only` 条件中某项消失，其他成功项也可能掩盖它。本轮已增加前置阻断，见第6节。
4. **旧实现参数被当成质量标准。** 首关素材测试锁定 `offset=0.4H`，不是检验实际不透明底边接地；材质测试锁定花坛仅有两子件，也不能代表完整实体接触。这是公共回归缺口，与1-4本次症状分开记录。
5. **版本身份不足。** [运行源摘要](../tools/godot-migration/source-digest.mjs)有意排除tests，因此不能证明测试/fixture未变；浏览器检查只在开始读一次build；[预览服务](../tools/godot-migration/serve-preview.mjs)在variant元数据缺失时回退共享build.json。当前缺失的生产文件和旧报告进一步放大了这个风险。
6. **画面证据有边界。** 现存较早1-4恢复图仍是程序圆台版本，另有完成图被结算弹窗遮住；两者都不能证明后来完整花坛与灯莲的清场画面正确。CPU路线、状态注入、GPU静帧和真实输入必须分别记录。

## 4. 公共排查发现：不能归因到1-4

首关 `1-1` 被 `PropObstacles.LEVELS` 排除，花坛/石灯没有这一套硬底座碰撞保护。认可首关的外观与玩法，不等于允许走入石底座。

另对原PNG只读采样 `alpha>=128`：首关石灯116×158，最后不透明行157。默认 `offset=.4H` 对应源锚点 `.9H=142.2`，底像素中心低于锚点15.3px。首关宽度0.43，卡片向下约 `15.3×.43/116=.05672` 世界单位；按固定相机up的Y分量约0.866换算，卡片底部不透明像素位于同高台面以下约0.04912世界单位。`PropVisualScale.ground_anchor()`特意跳过1-1，而 `native_prop_scale_test.gd`92–93行要求保留旧锚点。这是素材与代码的几何计算，尚非当前GPU复现，也不是本次1-4症状的证据。

移动器的水平二次校正已有端点避障，不能称其毫无防护；高度异常恢复直接设Y、抬阶落点未显式拒绝 `not_walkable_support` 道具体，以及机关乘客中段，仍需完整扫掠与独立查询。机关随动直接写位置属于既有设计，不能仅凭赋值认定穿模。

## 5. 后续调整的强制规则

以下是后续实施与验收合同；除第6节完整性门禁外，尚未全部实现为自动检查。

| 规则 | 实施要求 | 拒绝放行条件 |
| --- | --- | --- |
| R01 版本先核对 | 记录关卡、状态、源码摘要、测试/fixture摘要、包摘要、入口、视口；开始/结束复核服务build和实际资源。测试报告不得跨构建借用 | 复现包、验收包和交付包不能对应同一构建；用户现场版本未知却声称已复现；资源缺失；variant缺自己的元数据却使用共享回退 |
| R02 每个硬物都有合同 | 每实例登记ID、硬/软类别、可见底座、真实支撑、父级、碰撞、点击命中及操作区。门柱、盆沿、机关石脚、可移动物都要纳入；允许明确无碰撞的软叶冠 | 有硬物没有登记、没有明确理由的空碰撞；用关卡白名单豁免整关 |
| R03 同一份几何数据 | 可见硬底座、支撑验证、碰撞、绕行与放置消费同一份实例几何和变换。门洞开放只释放洞口；喷泉移位同步盆体阻挡 | 显示移位而碰撞留在原格；只因中心点有地面就认为完整底座合法 |
| R04 脚锚按素材验证 | 使用实际不透明脚点、完整硬底座和真实表面；竖直角色与倾斜装饰分别计算。保留尺寸风格，纠正错误接地 | 用固定`.4H`、整体抬高、关闭深度或透明化硬物掩盖问题；只锁旧参数不验证最终像素关系 |
| R05 所有位置入口一致 | 默认站位、点击、键盘、跟随、换人、读档、撤销、放置和机关恢复都验证真实体积。motor保持常规位置写入职责，恢复/纠正路径单独记录 | 只默认端点安全；端点合法却校正路径穿过硬物；旧非法pose继续保留动作接触 |
| R06 动作接触持续成立 | 持杆/搬放等状态要求真实接触点；恢复后重新校验，失去接触按既有安全规则取消或走到合法站位，不悄悄瞬移/补状态 | flag成立但手柄距离不成立；移动了身体而动作仍维持旧握点；手动松杆造成支撑丢失 |
| R07 双角色与投影分开验 | 验证实际身体间距与正常镜头中的主体可读性；窄路的让行/排队另有明确规则。完整底座合法、身体不交叠、画面可读是三项检查 | 仅凭两脚点分离或平面矩形不交就宣称画面通过；完成弹窗遮住场景仍当清场验收 |
| R08 动态与恢复必须覆盖 | 起/止和25%/50%/75%，双角色、四角擦边、偏心上下阶、停步反向、开门前后、撤销、重进、存读档；检查真实形状和中间帧 | 机关中段跳过；只验证终态；把脚部误差打印出来却不判失败 |
| R09 独立反查 | 从所有可见硬物反查碰撞登记，用真实胶囊/形状查询检查侵入；误差按正确接触几何设置阈值，记录单位及允许原因 | 同一个漏项清单同时决定碰撞和“无碰撞错误”；用中心高度差直接代替侵入量 |
| R10 验收不改写失败 | 受影响区域有双尺寸正常镜头、清场、真实输入和动态证据；被独立看图否决的候选保留，定向修复后重验对应范围 | 用检查数量替代结论；只看全景缩图；只验首关却推广全关；为过测放宽玩法或旧存档合同 |

## 6. 本轮已经落地的门禁

新增 [check-scene-integrity.mjs](../tools/godot-migration/check-scene-integrity.mjs)，统一 [原生检查入口](../tools/godot-migration/check-native.mjs)在创建输出目录、导入和启动引擎之前调用。该门禁只读，不修复或替换缺失文件。

```sh
node tools/godot-migration/check-scene-integrity.mjs
node tools/godot-migration/check-native.mjs --only=native_route_test
```

- 固定12份空间/碰撞必需测试与原有core清单，`.uid`不能替代脚本；固定关卡、素材及参考fixture输入。
- 检查现存GDScript的字面 `preload/load/extends` 与 `FileAccess.get_file_as_string` 输入、tscn/tres外部资源、project资源、shader的绝对 `res://` include。
- 每个请求的 `--only` 条件必须匹配实际套件；不允许一项失踪却由其他成功项代替。
- 当前应失败：39处缺失资源引用、7份必需测试。失败是对当前快照的正确诊断，不能把它写成游戏回归已通过。

该工具不是GDScript完整解析器，也不检查动态拼接路径、相对shader include或GPU遮挡；Godot导入/实际运行和后续物理/视觉门禁仍必需。完整性通过也不证明穿模已修复。
