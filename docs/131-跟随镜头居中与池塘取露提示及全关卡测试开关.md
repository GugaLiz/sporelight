# 跟随镜头居中、池塘取露提示与全关卡测试开关

2026-11-19，dev 分支。对应用户最新2-1截图与三项要求，沿 GQ-006（镜头）、GQ-030（操作可读性）追踪。

## 修改

1. 跟随视图：桌面不再选择两侧纸卡下方的最大空矩形作为中心，而使用两卡之间、底部工具栏以上的对称中央区域，避免人物落到屏幕下半部。统一镜头尺寸乘1.18，相同对象投影缩小约15.25%，不修改人物／地形／道具的世界尺寸。保留跟随平滑与全景切回；手机镜头同样缩小一级。
2. 2-1核验：原16步路线可以通关，截图中的升水禁用是因为低路清露会被淹没。另确认小苔灵无清露拾取能力，走到清露旁原界面却显示“附近暂无可操作物件”，这是容易被理解为卡死的提示缺口。现在水位／交露的拒绝理由明确清露、淹没原因和露薇；小苔灵走近清露后提供原有的“切换露薇接清露”操作，没有赋予新拾取能力或远程取物。不同持有者和已经交付的状态分别说明。修复进度拆为带回清露／照料睡莲／花园复苏，微光数量不冒充清露任务。附近菜单按最终文字宽度测高度，避免换行初始高度形成大块空白纸面。
3. 全关卡测试开关：`godot/project.godot` 的 `[sporelight]` 下 `testing/unlock_all_levels=true`，本次已开启，官方release也生效；运行时对应 `main.gd` 的 `unlock_all_levels`。设为false并重新导出后恢复正常逐关选择。只影响入口可用性，不伪造通关／收藏／纪事、不保存永久解锁标记；原调试QA开关仍独立有效。云庭仍从更多菜单进入。

截图状态的操作：切换露薇，沿低水位石路走近水滴并选择“接住露珠”；带回浮台交给睡莲；两人同行站在浮台上调到中水位；沿新接通的右侧花岸到花坛旁主动播种。

## 验证与证据

- [修改前原路线](qa-godot-native/pond-follow-20261119/baseline/native-route-before.log)：实际电机执行原16步并通关，61项、946身体样本；因此没有删除水位／物品占用保护来“解卡”。
- [最终六套定向检查](qa-godot-native/pond-follow-20261119/headless-verified/checks.json)：模态418、相机412、选关713、交互优先级655、池塘与测试开关50、原生UI230，共2478项通过。测试覆盖全部15关入口；测试开关关闭后锁定恢复；未交露的中位不接岸、高位不ready、携露可升降、不同持有者、撤销与保存恢复均保留。
- [真实GPU与身体流程](qa-godot-native/pond-follow-20261119/verified/checks.json)：116项、36张图通过；小苔灵带队从清露旁切换露薇后完成，与露薇直接带队两条路线均使用真实电机及E／菜单操作。1-1、1-4、2-1、3-4在1887×912、1280×720、844×390下对照跟随／全景／返回；独立相机套件还覆盖竖屏。人工查看确认中心抬回、15%缩小及紧凑菜单。
- 正式Web隔离4230实际操作：只完成1-1的旧测试存档从1-2地图直接进入2-1；切小苔灵、开启同行、沿低路到清露、新入口换露薇、拾取、同行返回、交露、中水位、走东岸、主动播种，出现通关弹窗。未向页面注入隐藏状态。证据：[角色提示](qa-godot-native/pond-follow-20261119/browser-buddy-guidance.jpg)、[实际通关](qa-godot-native/pond-follow-20261119/browser-completed.jpg)。生产4222用户存档未用于测试。
- 初轮测试与画面保留：`headless-first`测试缺少World引用、随后测试fixture漏加载云庭目录；`gpu-first`的路线被测试宿主夺走窗口焦点中断；`gpu-final`暴露小苔灵没有取露命令，促成本轮角色提示补充。最终自动GPU捕获显式忽略测试宿主窗口焦点事件，网页另以真实输入验收。没有放宽游戏规则。
- `headless-final`保留一项旧UI宽度断言失败：旧布局仅要求宽度≥55%和高度≥30%，新的中央竖向取景区在1280px屏为668px宽。改为验证桌面中央区域占屏≥40%、水平居中且中心在工具栏以上；手机原阈值不变。实际GPU看图后接受新构图，不把旧宽度断言伪称既有缺陷。
- 未改关卡拓扑、世界尺寸、三档水位、清露消耗、伙伴能力或存档格式。未重跑全关通关、性能或可听音频验收；视觉审美待用户试看反馈。2-1全景仍使用原整场景取景，桌面全景主体较小属于既有表现，本轮未将其冒充跟随改善。
