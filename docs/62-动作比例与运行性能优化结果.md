# 动作比例与运行性能优化结果

状态：本轮实现与分项验收完成；性能改善、严格像素比较未通过及剩余峰值分别记录，不声称全设备60FPS或零卡顿。执行计划见 [61](61-角色动作与全关性能优化验收计划.md)，前一轮性能修复见 [60](60-Web加载与机关卡顿排查.md)。

## 问题与修复范围

用户反馈播种/蹲下时人物突然变大，以及 1-3 行走持续卡顿。排查同时覆盖 15 个已实现关卡，保留 1-1 的站立形象、材质、阴影、分辨率，以及全部机关规则、路径、存档读写和备份语义。

| 问题 | 证据 | 实施方式 |
| --- | --- | --- |
| 蹲下、播种人物头部放大 | 同样 256px 画布的动作独立适配高度；站立帽宽 116px，interact 139px，sow 135px | 以帽宽与可见脚底统一动作比例，跟随动画帧变化并处理水平翻转；不修改原图、站立/行走尺寸或碰撞体 |
| 行走反复派生格表 | 1-3 的 90 帧诊断约 1090 次查询 | 每个物理 tick 的只读区间共享格表；会话 revision/世界变化立即重建，tick 结束释放 |
| HUD 交互重复查询 | 15 关 115 个状态原结果全等；查询 381→105 | 同次 context/command 查询共享格表，HUD 复用一次上下文 |
| 跨格存档校验重复构造世界 | 持有 15 关存档时，原 1-3 保存约 88.7ms、跨格约 105.4ms | 仅缓存固定关卡定义下成功的纯规范化结果，每关最多 4 项；输入/返回值深拷贝。保存、校验回调、读回、备份次数不减少 |
| 3-1 可见区域重复派生格表 | 两次不重建地形的跨格 refresh 分别 151/146 次 tiles，visible 占 231/166ms | 单次刷新共享已有只读格表，各降到 1 次；不跨状态缓存可见性结果 |
| 3-4 水面每帧重新派生格表 | 60 次 Stage._process 触发 120 次 tiles，水面占 172/188ms | 重用已验证的静止/运动端点索引，降到 0 次；状态变化保留失效与回退 |
| 首次加载、首次生长阻塞 | 同步 GL 记录指向通用场景 shader 的默认特化预编译；并非图片上传占主要时间 | 构建同版本 Web 模板，只跳过不必要的提前编译，实际 draw 仍使用原引擎特化与 shader；待同 PCK 画面对照和普通入口实测 |

表中 CPU 时间是诊断样本，不是隔离后的最终对照；构建期间的耗时不用于对外性能结论。早期把 3-4 每帧两次残余 tiles 归因于光线是误判，完整扫描证实来自水路固定端点，RuleRayPresentation 本身逐帧 tiles 为零。

## 引擎候选的边界

固定 Godot `4.7.2-stable` / `ed1daf0bf001b61586d9930840f2f1394092c079`，修改仅限 Web 的 `SceneShaderGLES3` 初始化。没有修改 shader GLSL、灯光种类或数量、法线、阴影和贴图。已试过强制顶点光照，虽然启动较快但画面变亮，因此未采用。

模板构建记录、工具链和补丁说明见 [构建说明](../tools/godot-migration/custom-web-template.md)。模板 SHA256 为 `51d3a8bac3b56cb9187a5d3545d9e60ead680ce0ddbe8ab1a20417cb4cfe35c9`；首次构建约 34.2 分钟，编译进程全部结束后才测最终性能。

画面对照使用隔离副本开启 QA 的 release 包，两种引擎必须使用字节相同的 PCK。快照可显式暂停物理接地微调并对齐相机，另通过真实设置控件启用低动态、关闭粒子并隐藏 HUD；材质、灯光和标准 MSAA 保持不变。这类包只用于静态画面验收，不能替代给玩家的普通 release。性能测量使用默认动态/粒子和没有 QA 发布器的正常构建，并分别保留首次动作、重复动作和 reload 记录。

## 最终结果

普通入口使用独立 Chrome 156 / GTX1660Ti / 1280×720 / DPR1，默认画质与动态效果，没有 QA 发布器、没有 GL/CPU 插桩。引擎构建及其他受控 GPU 测试均已结束，旧版与新版串行采样。同一环境的新浏览器上下文不保证清空操作系统/驱动缓存。入口证据为 `full-performance/final-home-baseline/`、`final-home-optimized/`，实际动作复核见 `home-review.md`。

| 普通入口 | 旧版5411b226 | 新版b8980c78 |
| --- | ---: | ---: |
| 首访至加载遮罩消失 | 25.071秒 | 6.727秒 |
| 同上下文reload | 4.273秒 | 2.683秒 |
| 首次生长最大主线程长任务 | 4773ms | 216ms |
| 同轮重复生长最大长任务 | 70ms | 61ms |
| reload后第一次生长最大长任务 | 208ms | 112ms |

这些是同脚本的具体样本，不是多设备平均值。新旧均已人工确认首页进入、真正完成根桥、撤销、重复生长；新版两轮有完整截图。首次初始化和首次动作仍不是零等待。

### 1-3 持续行走

使用无QA的显式关卡诊断入口，三轮各约30秒，实际往返起始岛与中心走廊，随后载人旋转四次返回原方向、重复同一旋转并撤销。它不是普通首页解锁流程；普通首页证据单列上表。

| 样本 | 第1/2/3轮主线程任务占用 | 第1/2/3轮最大主线程长任务 |
| --- | --- | --- |
| 旧版基线 `final-walk-baseline` | 53.7% / 55.0% / 55.0% | 116 / 74 / 64ms |
| 新版首轮采样 `final-walk-optimized` | 42.9% / 38.7% / 41.7% | **934** / 无 / 无 |
| 新浏览器复测 `final-walk-optimized-repeat` | 38.8% / 39.9% / 41.3% | 119 / 68 / 52ms |

新版本持续行走的主线程占用下降约四分之一；不能据此宣称没有任何长帧。首轮新包出现一次934ms长任务，保留原报告且原因未确定。专门GL/CPU诊断 `first-walk-profile/` 未再复现该峰值：首次走路最大147ms，其中两次shader查询约23/66ms；新的完整三轮复测首轮最大119ms。不能把无法重复的934ms归咎于宿主、驱动或任何未确认原因，也不能从最终结论中删掉它。

1920×1080 / DPR1 另测一次约30秒真实行走（`final-walk-full-hd/`）：主线程占用39.0%、最大长任务126ms，无错误。所有行走截图确认实际位移及伙伴跟随；重复旋转后的岸线连接保持正确。

`final-home-profile/` 是另一次有GL/CPU插桩的诊断，不混入上表：第一次生长222ms任务中shader同步查询累计约98ms，重复动作59ms且无慢GL查询；说明仍有实际首次shader与动作计算成本。启动仍有一次约2.19秒的场景shader等待，按需编译优化并未消灭所有必要初始化。

### 渲染与路线

- 15关×4状态、每状态官方A/B及候选A/B，共240张原始全幅截图，使用同一验证PCK。独立人工复核未发现几何、材质、角色、光照、水流或光路的实质性静态回退，详见 [完整画面复核](qa-godot-native/full-performance/template-pixel-all-states/review.md)。
- **严格逐像素比较未通过**，没有改动原`passed=false`。普遍存在同引擎重复截图自噪声；跨引擎单图中位差22像素/921600。1-4完成前/完成后各有同一花边像素差17，其他该图差异为1级，已单列，不能冒称在对应自对照中已复现。没有遮罩人物、水体或修改画质来得到通过。
- 动作逐帧、触屏通关、旋转/升降中段及版本边界见 [浏览器独立复核](qa-godot-native/full-performance/browser-review.md)。正式物理路线和缓存回归见上文，未修改各关胜利条件、路径或存档格式。

最终交付构建为`full-performance-optimized`，运行源`b8980c780eb1a91621bce0775c207b2348a63a10e676f30d2fc8974025532f1f`，492个文件，使用上述scene-demand模板。普通包保留三处QA守卫，**不包含**验证包的物理冻结分支。保留同源官方release对照`full-performance-official`及完整旧版证据。

本轮解决已查明的重复计算和大部分首用编译停顿，动作比例及路径验证完成；偶发峰值、首次短暂停顿和严格像素残差均保留为限制。当前主机空白页约31ms的rAF节奏也不能用来证明游戏达到60FPS。

后续机关落稳建模、全关统一尺度及全景边界调整已完成，4222现由`motion-framing-final`提供；新的运行源码与普通包回归见[64号验收](64-机关落稳建模与全关视觉尺度验收.md)。本篇的历史性能样本及未解决限制保持原记录，不替换成后续版本数据。
