# 守护者关机关因果与实体模型重整

2026-11-15。用户否决101号后仍存在的整关因果问题：左下平台旋转看似接路却不见效果，灯光看不出来源/接收，中央道路必须特定角度才能种植，开花后又无缘由出现地鼠。此次明确修改3-4的规则与模型，不能再用“原路线能通关”证明设计合理。

## 查明的原因

- 最终`ready()`硬编码`inner==1`，但该角度连通北岸与升台、并不接西岸花坛。根固定后已有独立西北归途，因此最终角度锁没有对应种植原因。
- 升台只需历史`rain`，种植却又需当前`water==1`，同一系统的存水与供水语义冲突。
- 左下水庭只有中心0.18/0.35m小槽，真正水传递为跨越8.94m空隙的稀疏水滴，无明确水源、接水嘴和实体管路。
- 光源坐标有规则而无灯体，`light!=1`直接不出光。花坛缩小后的细接收叶在整关镜头不够可辨。
- 完成地鼠来自`_add_mole()`的3-4特殊分支，复用了1-4住民，没有本关任务铺垫。

## 本次玩法合同

保留主角搬镜、伙伴专用水庭、三节前端搭建并固定、运镜上高岸、反射光到花坛、双人归来主动照料。原根预算、角色能力、地形支撑、机关动作、存档字段和赠礼去重不变。

1. 水庭旋转用于对接输水槽。首次接水填满升台储罐（原`rain`），存水不因转开槽口消失。水道对接/断开与罐内已存水分别显示。
2. 中央庭院只改变真实通行关系；花坛不再检查`inner`角度。提示只在实际无归途时建议调整道路，不要求已经到花坛的人再去远端校角度。
3. 种植不再检查`water`即时角度。仍需四阶段结果、当前真实受光、两人会合和主角合法主动照料；未接过水、未送镜接光或伙伴没回来都不能跳过。
4. 灯台四朝向发射实际直光（0西、1北、2东、3南），实体灯嘴同步转动。北向经高槽镜反射的原解法保留；其它朝向照向空处，不能冒充花坛受光。
5. 开花回应来自原花坛及接收花盘，3-4不再生成地鼠；1-4住民保持。

无需新增状态字段或重置旧档；旧96意图依然合法。此前57/98/100/101号的`inner==1 / water==1`最终门槛及只一角出光约定由本次用户授权的因果修正取代。
