# 加载页与首页品牌坐标对齐

日期：2026-11-07。已更新本地正式入口 http://localhost:4185/。

## 问题与原因

“微光苔原”使用同一张648×342的透明Logo图片，并非字体被替换。加载页按vw/vh和独立断点排版，首页则按Godot原生控件尺寸排版，导致切换时位置、比例和标语间距变化。例如1280×720、DPR1下，旧加载图宽448px，而首页居中等比绘制宽约416.84px，差约31.15px。

高分屏还有第二层坐标差异：当前Godot禁用stretch，Web SDK按物理像素确定viewport，而HTML按CSS像素排版。SDK依次对CSS尺寸乘DPR、backing尺寸除DPR取整。比如390px宽、DPR1.25，backing为487px，最终canvas显示宽为389px；仅除DPR会残留偏差。

## 实际修改

运行源仅修改 `godot/web/loading-shell.html`，以现有 `ui/menu_cover.gd::relayout()` 为几何基准：

- 加载Logo采用与首页相同的容器和居中等比显示方式，比较真实图片绘制框，包含透明留白。
- 原生像素排版完成后，再按SDK最终canvas显示尺寸映射CSS；标语容器也采用相同坐标，移除额外字距。
- 移除短竖屏和窄横屏单独覆盖Logo大小的规则；加载文案区域保留既有适配。
- 监听窗口resize与resolution变化，退出加载层时清理监听。无JavaScript时仍有静态排版回退。

原生首页源文件与修改前快照SHA256一致；PCK、WASM、SDK JS、工作线程和四张网页素材均未变化。正式目录仅更新index.html与build.json，不调整谜题、连续行走、关卡、存档和动态封面。此次目标是品牌区域的衔接；加载文案与首页按钮各自排版，背景和动态角色不承诺逐像素一致。旧版320×568短竖屏的角色构图差异属于范围外遗留。

## 测试工具修正与保留证据

旧before-diagnostic按预期发现原版标题宽度差31.15px。首轮final使用启动前100% canvas尺寸作为期望，忽略SDK最终显示尺寸的二次取整，已保留aborted.json说明；修正后final-v2的28组矩阵全部通过。

final-v2的纯CDP动态DPR测试还发现两项自动化副作用：仅设置DPR不派发真实resize/resolution事件，Playwright的CSS尺寸截图还会将模拟DPR恢复为context初始值。此失败不能作为产品缺陷证据。transitions-final改用CDP目标宽+1再回目标宽，实际触发浏览器窗口/分辨率事件，并用Page.captureScreenshot避免重置DPR；逐次断言截图前后DPR一致，两项动态检查通过。没有降低0.12 CSSpx几何阈值，也没有修改生产代码迎合模拟器。

acceptance.json明确汇总final-v2中的28个matrix案例与transitions-final的2例；旧失败报告保留，不改写成通过。

## 后续维护规则

1. 首页Logo素材与加载图必须逐字节一致，不在加载页重新拼字体或裁剪透明边缘。
2. 改首页品牌布局时同步调整HTML布局合同，禁止另加百分比定位和局部断点偏移来掩盖跳位。
3. 更改Godot版本、stretch、canvasResizePolicy或高DPI策略后，重新测实际backing与CSS尺寸，并采集真实控件参考。
4. 比较TextureRect实际等比绘制区域和标语容器，不能只比较图片外层DOM。
5. 分开验证真实引擎启动、几何、截图与输入；测试模拟造成的行为要明确标注。
