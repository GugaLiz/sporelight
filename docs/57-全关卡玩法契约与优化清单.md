## 2. 共同逻辑底线

- 主线各卡片的“机关条件”对应 `ready()`；真正完成还需露薇在花坛同层相邻范围内主动 `repair`，以及两位旅人同层相邻会合。自动跟随必须走真实合法路径。
- 改变机关不能使任一角色、或放在地面的关键物品失去合法支撑；失败操作回滚，不消耗资源、不留下半完成状态。
- 正交相邻、高差允许范围、低拱的角色限制由规则控制。可视面变宽不能产生斜向切角或跨层互动捷径。
- 主线第 1–11 关的沿途微光、休息和观察保持可选；第 12 关的八份赠礼由四阶段各产生两份，不是另一套强制找物路线。
- 每关至少覆盖：初始不可完成、合法流程、关键失败、撤销、存档往返、动作途中暂停/回首页、重开、切到其他关再回来。以下负向与替代路线是在此基础上增加的检查。
- 参考路线用于证明至少一种合法玩法仍成立，不将其命令顺序硬编码进 HUD，也不据此删除其他合法解。

## 3. 逐关契约

### 第 2 关 · 1-2 第一朵花

**现状与核心**：根台 `f:1:1`，中央岩石 `[2,1]`，四节预算，目标接入点 `[3,1]`，花坛 `f:4:1`。上绕与下绕均合法。机关条件是根尖接入目标。正式版逐节选择并生成；试玩先规划完整草稿再执行，不能混作同一存档流程。

**因果链**：观察缺口 → 选择一侧 → 连续四节绕岩 → 道路接通 → 亲自过桥 → 会合并照料。三颗微光、休息和观察可选。四节包含对岸接入节，不能因第三节已邻近某块岸地就绕过接入条件。

**允许优化**：续用文档 53–55 的独立表现；强调根尖、剩余预算、草稿/实体与确认阶段；检查两岸和岩柱的间隙。保留已经调整的后庭花境与原素材。

**禁止改变**：预算、七个候选落点、中央阻挡、两解、主角与伙伴安全回收、最终主动照料。不加花粉钥匙或强制收集。规划按钮不能固定画在根台周围冒充真实落点。

**必验项**：两条完整解；直穿岩石失败；第五节失败；三节不能完成；草稿不开放支撑；实际撤销一节后从根尖续接编号4；占桥不可收回；桌面/横屏确认。正式接入另验部分根桥存档、草稿持久化策略及确认中断恢复。

**下一步**：先做 1-1 → 1-2 连续体验对照，再决定规划实验的正式集成。不要借此改首关。

### 第 3 关 · 1-3 苔藓山谷

**现状与核心**：中心 `garden` 是五格 L 形可旋转庭院，操作点 `m:garden:0:0`；起点西岸 `f:-4:0`，目标北岸 `f:0:-4`。规则 `ready()` 为 true，难点由真实空间连通与抵达花坛承担，并无额外收集锁或“恰好转一次”的独立完成锁。

**因果链**：从西岸登庭 → 人和平台一同转动 → 新出口对岸 → 离庭上北岸 → 会合照料。其它岸边与四颗微光为探索空间。

**允许优化**：首先为旋转模块建立清楚的中心、两条臂和靠岸边；保持固定岸作为方向参照；中段同步人物、伙伴、装饰与碰撞。借用首关材质/脚锚能力，但独立设计转庭外形。

**禁止改变**：L 形通路、离散朝向、乘员承载、合法上下口和各岸探索价值。不能把“转庭”改成传送，也不能增加“必须操作过一次”之类的新标志门槛。

**必验项**：原旋转路线完成；未对齐缺口不可走；不同朝向和往返；两人同乘、停在臂端、中段输入、暂停/撤销/读档无甩人或重复位移；最北侧高差和归途实际可走。

### 第 4 关 · 1-4 鼹鼠的家

**现状与核心**：露薇在 `f:-3:0` 附近扳重杆，小苔灵穿低拱到 `f:3:5` 踏板；露薇到 `f:-3:5` 固定门闩，再取门铃 `f:-2:5`，交给 `f:-4:0` 的家门。花园终点在 `f:-9:0`，不是交铃地点。机关条件为 `latch && home && together()`。

**因果链**：露薇保持 → 伙伴穿低拱压板 → 露薇通过另一条路开永久门闩 → 取铃并交还 → 花门打开 → 接上伙伴进入小花园 → 照料。露薇移动会解除保持；门闩固定后临时保持才不再必要。

**允许优化**：清楚区分重杆、轻踏板、永久门闩与家门；低拱净空对应双方体型；门铃携带、门封移除和鼹鼠回应可读；花门后的目标保持可发现。

**禁止改变**：小苔灵不能替露薇扳重杆，露薇不能穿低拱；临时桥不能提前永久化；未归还门铃不能开花门；交铃不能直接结算。

**必验项**：错误角色操作与未压板通行失败；离杆导致占用失效时完整回滚；开闩后能安全接回伙伴；空手交铃失败；交铃、开门、进入内园、主动完成四个状态分明；门铃/门状态存档一致。

2026-11-12重杆修复补充：原生交互先让露薇真实走到原把手格 `f:-3:0` 的操作位，再提交保持；姿态为原素材的站立侧身表达。换手本身保留保持，露薇实际水平移动即松手（包括同格内、非当前角色跟随），不是等换格才生效；若临时桥或接岸边缘仍被占用，松手与身体位移一起回滚，失败不增加走路撤销点。重复 `use:hold` 仍幂等，另提供明确 `release:hold`；跳跃/变球需先松手，接近可被新的合法点击或手动方向取消。永久 `latch` 后移除旧hold并禁止重新保持，永久通路不随松手回收。原50步因果链和全关参考路线未改，专项证据与存档边界见 [73号](73-第四关重杆动作与保持逻辑修复及验收.md)。

同日距离整理：门闩默认操作位改为拱门侧前方，归铃双人站位分开；家花、地面门铃和三枚拾取显示在原支撑内错开，入口灌木与踏板侧红菇让出轮廓。保留尺寸、原NPC位置、核心/喷泉/灯莲、握杆配套站位和所有规则格；不改变可选收集条件。准备状态看图、实际输入与版本范围见 [74号](74-第四关元素间距整理与验收.md)。

### 第 5 关 · 2-1 池塘之声

**现状与核心**：中央 `float` 为三档水位承载台。低水位能到 `f:0:4` 取清露；在台上 `use:care` 照料睡莲后，中水位出现东岸入口；花坛 `f:4:0`。机关条件是 `care && water == 1`。高水位通向北侧探索，并不更接近完成。

**因果链**：低位离台取露 → 返回交露 → 中位靠东岸 → 两人离台抵达 → 照料。高位与其它岸边保留可选用途。

**允许优化**：标清当前/下一档水位、台上实际乘员、岸线高差和交露后的变化；池水跟随真实语义，不用装饰水遮住固定石路。升降与靠岸使用独立 profile 验证。

**禁止改变**：三档循环、中位完成条件、清露前提、交露消耗、高位探索；不能改成“升到最高就通关”，也不把本关改为 3-3 的分水资源管理。

**必验项**：未交露时中位不接通目标；高位不能直接修复；人物/物品在将被淹没的低路时变化受保护；携露升降、双人乘台、下行、撤销和恢复。

### 第 6 关 · 2-2 涟漪之谜

**现状与核心**：光源 `[0,1]`，固定镜叶 A 在 `f:1:1`，可搬镜叶 B 初始在 `f:4:3`，典型放置槽 `f:1:0`，石壁 `[2,1]`，接收/花坛 `f:4:0`。机关条件是当前 `beam_hits(4,0)`；接光区道路随实际光路出现。

**因果链**：辨认光源与阻挡 → 搬第二片镜叶 → 放置并调角 → 两次反射绕壁 → 花床收到光 → 实际抵达照料。物件位置与角度共同影响结果，不是只点两个开关。

**允许优化**：镜叶编号、固定/可搬区别、拿起/放下/调角动词、光束中断点与接收回应；道具槽只表达可用位置，不自动吸附到答案。没有整张方形水板的需求。

**禁止改变**：A 不可搬、伙伴不能搬重镜叶、光束遇壁停止、持有镜叶不参与地面反射、失去光照后按规则关闭道路。槽位是操作帮助，不能额外把规则中其它合法固定地面放置禁止掉。

**必验项**：正确反射完成；角度不对/拿走镜叶不能继续供光；关键人物或物品占接光路时不能抽路；搬运单件限制、物品安全落点、光束和缓存随位置更新；不把“曾经照到过”当永久开门。

### 第 7 关 · 2-3 雨滴节拍

**现状与核心**：三张动作叶为 `turn / rise / rest`，初始排列已是可用顺序；不是旧版四音符节奏口令。露薇乘 `stage`，伙伴在琴台 `f:-4:0` 操作。升起后转轴受限，提前升起会影响后续转向。北岸门闩 `f:0:-4`，花坛 `f:1:-4`；机关条件为 `latch && together()`。

**因果链**：安排谁乘台、谁演奏 → 观察逐拍转庭/升台/停拍 → 抵达北岸 → 固定会合便道 → 两人会合照料。玩家可以直接试奏现有正确顺序，不能强迫先交换动作叶。

**允许优化**：当前拍、下一动作、平台高低与限位状态；排练、暂停、单步、重排的区别；便道固定后的结果反馈。保留原三槽操作，不另加音乐成绩系统。

**禁止改变**：三拍及升起后不能再正常转庭的因果；演奏中的行动限制；未重置不得改已进行短句；重排恢复试奏前人物和平台，同时保留已取得收集/观察；永久便道只能由开闩动作产生。

**必验项**：默认正确顺序通关；先升后转的失败及安全重排；停拍不改变空间；每拍暂停、单步和继续一致；载人/伙伴演奏、落岸开闩、接回伙伴；重排不会丢已发现内容或重复授予。

### 第 8 关 · 2-4 池塘守护者

**现状与核心**：`boat` 沿 X 在两岸间平移6格；光虫初始在 `f:-4:0`，花坛 `f:10:0`。必须先种蜜花，在近岸邀请光虫登台，载到远岸再邀请授粉。机关条件 `pollinated`，远岸地面在授粉条件成立后开放。

**因果链**：蜜花 → 近岸邀请 → 光虫有真实平台位置 → 载运 → 远岸邀请 → 授粉与花岸出现 → 两人照料。

**允许优化**：蜜花未开/已开、光虫在岸/在台/已授粉的形态；移动按钮明确岸向；角色、伙伴、花和光虫共同承载；移动中维持两岸参照。

**禁止改变**：空船到远岸自动授粉、直接拿光虫、未种花即邀请、未授粉提前出现远岸通路；不把 `pollinated` 永久结果改成每次开船都失效的新资源循环。

**必验项**：未种花和未载虫时邀请失败；空船往返可恢复；乘员/光虫局部位置随台；授粉前不可绕路上岸；邀请与授粉不重复生成实体；暂停、撤销和重新载运成立。

### 第 9 关 · 3-1 微光引路

**现状与核心**：暖灯 `f:-3:0`，伙伴可穿低通道至 `f:3:5` 照孔；光束须到 `[3,3]` 接收位置，露薇才能在 `f:3:0` 打开石窗。花坛 `f:4:0`。机关条件为 `window && together() && 灯仍由某位旅人持有`。

**因果链**：伙伴携灯走低路 → 调整照向接收叶 → 露薇通过暂时光路开窗 → 通路稳定 → 接回伙伴与暖灯 → 照料。开窗后不再要求持续靠灯维持桥，但完成仍要带着灯。

**允许优化**：已发现区域与当前照亮范围分明；灯朝向、照孔、接收叶和开窗回应可读；携灯移动及时更新光束；低拱遵守实际净空。

**禁止改变**：取消角色能力差、全图提前揭示、接收叶未照亮也能开窗、开窗即自动把伙伴/灯传回、丢下暖灯仍可完成。`window` 的永久通路与临时灯路不能合并为一个布尔动画状态。

**必验项**：错误方向/石窗阻挡时开窗失败；露薇不能走低拱；临时光路占用时拿走光的变化受保护；开窗后能合法撤回光与伙伴；未携灯不能完成；探索显隐和存档中的发现记录一致。

### 第 10 关 · 3-2 影子的形状

**现状与核心**：露薇搬日/月影柱，典型槽分别为 `f:0:0` 与 `f:3:-1`；投影由柱子真实位置产生。留影苔只保留一份当前投影坐标 `shadowMemory`，日月切换改变实时影路；花坛 `f:3:4`。机关条件是日、月两种模式通过“当前光照或保留模式”同时存在；实际抵达仍需真实路线接通。

**因果链**：安排柱子 → 留住一段实际影路 → 切到另一时刻 → 两段接通 → 会合照料。先留日影或月影都属于需要保留的玩法方向，不能把参考脚本先日后月变成唯一规则。

**允许优化**：当前日/月、保留的是哪一种、柱子位置、实时影与记忆影的视觉区别；留影失效原因和被替换记忆的反馈。

**禁止改变**：只按模式名画预设正确桥、移动柱子后偷偷改写已保存投影、同时保存两份记忆、拿起柱子仍产生实时影路；不把槽标记升级成领域模型里没有的强制放置条件。

**必验项**：日先/月先的可通行方案；无实际投影不能留影；留影后搬柱不改变旧坐标；换记忆覆盖旧路时保护人物/物品；无柱、单段、错误位置均不能绕过缺口；撤销和存档保留准确影路坐标。

### 第 11 关 · 3-3 共生之歌

**现状与核心**：可旋转分水庭 `water`、水力花台 `lift`、四节根路。真实生长根台在 `f:1:-4`，不能只按装饰标记 `f:0:-4` 推断根尖。高处露珠 `f:8:0`，交露点 `f:1:-4`，终点 `f:0:4`。

**因果链**：让水到根系 → 四节接向花台 → 升台取露 → 下降送回 → 交露令根系稳定 → 转庭重新分水 → 升台并沿新路到花坛。机关条件为 `root && water朝向==1 && lift处于高位`。

**允许优化**：明确“根路已接通”和“根系已蓄水稳定”两种状态；显示沟槽当前供水方向、花台是否有上升动力与安全下降；水和路分别表达，避免把水流装饰画成便道。

**禁止改变**：未稳定时供水朝向0/3才能生长的约束；上升需要当前朝向0/1，但下降仍可安全执行；不能一接通就自动稳定，必须取露并照料；根系稳定后才可重新分水，不能自动把多个需水状态全设为真。

**必验项**：断水生长/无动力上升失败；下降与送露回程可行；四节连接本身不等于稳定；交露消耗和稳定根路不可普通撤回；转庭后目标新路只在对应水向与高台条件成立时出现；错误水向下不能修复。

### 第 12 关 · 3-4 沉睡的守护者

**现状与核心**：内庭 `inner`、三节根阶、载重花台 `lift`、仅伙伴可进入的送水庭 `water`、高处反光庭 `light` 和重镜叶。镜叶初始 `f:1:-4`，高槽 `f:8:0`，终点回到 `f:-4:0`。`light` 当前是旋转模块，虽然数据保留早期 axis/distance 字段，不能因此恢复成平移。

**因果链**：接通三节根阶并固定 → 露薇搬重镜 → 伙伴到送水庭调水 → 水力花台运镜上高处 → 放镜并调整外庭光路 → 留好归途 → 内庭转到正确朝向 → 两人回到中心主动照料。

**完成条件必须同时成立**：`root/rain/star/moon` 四阶段结果，`inner == 1`、`water == 1`、当前 `beam_hits(-4,0)`、两人会合，加上共同的合法花坛操作。`star` 曾经点亮不等于现在仍有光。

**允许优化**：按当前已发生状态表现根固定、供水、载物、光接收与归来；保持全局空间参照；让两名角色各自承担的任务清楚。原四阶段各给两份赠礼的结果保持，不另列一张自动执行清单。

**禁止改变**：根预算变四、伙伴搬重镜、露薇直接走小型水庭、未供水就升载台、装饰水路变步道、曾点亮即永久满足光路、八份赠礼改成地图找物门槛。不能把阶段标志与当前条件混用。

**必验项**：原完整归途；未取水/未固定根时的关键失败；镜叶运送、放置、光束高度与阻挡；亮过再转走光源不能完成；错误内庭/水庭朝向不能完成；伙伴留在水庭不能远程结算；每个里程碑撤销/保存/恢复与赠礼去重。

### 独立关 · cloud-1 风眠拱庭

**现状与核心**：从 `floor:1:7` 出发，转桥台 `floor:4:3`；北庭花种 `floor:4:-3`，东庭终点 `floor:10:3`。桥是北/东两态；伙伴在终点熟睡。完成需要 `cloudSeed` 和合法终点操作，不套用主线两人同走到终点的门槛。

**因果链**：北桥取种 → 回固定庭院转桥 → 东桥到终点 → 种下微光。听风、旧信两处发现可选。

**允许优化**：桥当前连接哪座庭院、携种状态、熟睡伙伴与开花回应；保留云庭自身建筑色彩。

**禁止改变与必验**：未取种不可完成；站桥上不能旋转；伙伴不能被当主线换手角色；取种回程、占桥安全、两态往返、完成回看/旧云庭存档均保持。动态桥来自云庭 world，不因 JSON modules 为空而漏掉测试。

### 独立关 · cloud-2 浮水花院

**现状与核心**：低岸召回点 `floor:5:4`，花台 `lift:6:4`，高岸终点 `floor:10:4`，高度0/3两态。完成没有额外取露或 `care` 条件；难点是合法召回、承载、靠岸和抵达。

**因果链**：台在高处则从低岸召回 → 登台 → 升到高岸 → 走到花池引水。两处故事发现可选。

**允许优化**：花台当前高度、低岸召回与台上升降的不同按钮语义、实际乘员与高岸入口；水色不掩盖接岸。

**禁止改变与必验**：不加入 2-1 的清露任务或第三档水位；不得未登台就瞬移至高岸；实际上下行、偏边站位、双角色承载、台在高处的低岸召回、保存恢复与无法失足的保护须验证。

### 独立关 · cloud-3 星灯归舍

**现状与核心**：伙伴踏板 `floor:3:6`，永久门闩 `floor:8:6`，星桥 `floor:8:5`，终点 `floor:8:0`。伙伴是 `follow/wait/sit` 状态，不能直接套用主线双角色独立操作。

**因果链**：请伙伴守板 → 主角过门开闩 → 返回近处接回伙伴 → 转星桥 → 沿真路共同抵达 → 点灯。两处故事发现可选。

**允许优化**：守板与永久开门的区别、接回地点、跟随者真实路程、星桥朝向和终点会合反馈。

**禁止改变与必验**：未开闩不能召回、伙伴仍等候不能点灯；不得把 `follow` 标志本身当作已经会合，原生存档姿态存在时还检查真实距离；站桥转向/抽走支撑保护、接回往返、旧云庭wait存档恢复与完成后sit表现保持。

## 4. 优化批次与优先级

| 批次 | 对象 | 先解决的问题 | 推广条件 |
| --- | --- | --- | --- |
| 基线 | 1-1 | 保留当前质量；共享变更时作回归参照 | 首关流程/渲染不退化 |
| A | 1-2 | 完成规划实验的教学衔接与正式状态设计 | 两解、撤销续接、正式存档语义清楚后再集成 |
| B | 1-3、1-4 | 旋转承载；双人协作、临时/永久通路 | 分别建立旋转和低拱/门闩的可靠单关样例 |
| C | 2-1、2-2 | 升降靠岸；搬运与实时反射 | 水位/承载、光路/占用保护分别通过 |
| D | 2-3、2-4 | 编排与试奏恢复；平移载运与授粉 | 复用已验证运动能力，保留各自状态机 |
| E | 3-1、3-2 | 未知信息、持灯、影路记忆 | 物品与显隐/投影存档一致 |
| F | 3-3、3-4 | 多系统组合及安全归途 | 前述机制稳定后，再验“同时成立”的完整因果 |
| 独立对照 | cloud-1…3 | 分别对照转桥、升降、伙伴门闩 | 共享能力变化时同步回归；云庭自己的规则与存档不被主线覆盖 |

同一批次也逐关交付，不同时重做几张地图。优化顺序服从教学与共享能力依赖，不代表玩家关卡顺序要改变。
