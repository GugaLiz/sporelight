# 旋转平台纹理身份与落稳连续性修正

2026-11-15，用户指出3-4送水庭每次旋转后板块渲染变化。本轮沿用GQ-005（运动与落稳构建连续性），同时检查共享路径中的旋转、平移和升降。最终证据与服务状态见文末。

## 已确认原因

动画把出发网格随平台转动，落稳后按世界轴重新构建合法接岸几何，节点旋转归零。旧顶面UV也跟着回到世界轴，导致最后一帧地砖方向跳变；墙面按重建后的法线选左右原画，第三章两张墙图不同，变化尤其明显。

旧墙UV还使用当前世界中心，而几何缓存键没有包含该坐标。同一块板若恰好未触发重建，会保留上次纹理相位；接岸条件变化触发重建时则重新取相位。因此连续旋转与重新加载同一状态也可能不同。这不是每次随机抽取了素材，module地面原本始终使用同类石铺面。

第一轮真实GPU原图还发现结构弹格：源端与固定岸同坐标同高的模块末格被逻辑去重，运动查找表虽补了别名，动画几何列表却仍少一格。板块转到临近终点时缺臂末，落稳才补全。首轮自动79项通过不能覆盖这一视觉失败，原39图保留在`gpu-surfaces/`。

## 修复范围

- 主线六个旋转模块：1-3 garden、2-3 stage、3-3 water、3-4 inner/water/light。
- 同类平移/升降：2-4 boat、2-1 float、3-3/3-4 lift，避免墙纹随位移滑动。
- 固定地块保持既有贴图基线；云庭桥目前是纯色铺面/侧墙，不套用主线module身份。其运动仍需回归。

纹理使用零位平台位置、格子局部身份与初始高度作为稳定参考；累计四分之一转用于顶面UV和固有左右墙面选择。动画中的出发网格使用出发参考，落稳新网格使用终态累计参考；参考参数参与几何缓存键，墙材质按朝向缓存，不逐帧重建。

规则格、碰撞顶点、支撑查询、人物承载与机关动作不变。离岸收回外梯、封边，落稳按合法邻接接梯，仍是应有变化；不能为冻结外观而锁死接岸模型。现有模块本体同高，没有内部高差楼梯；外接梯继续按真实接岸方向生成。

结构返修只为移动模块补回源端确实有同高重叠所有者的真实叶片。p=0仍由固定岸独占显示，p>0叶片随本体移动；补叶仅用于锁输入动画的外观，碰撞层为0，不新增规则格/道路或玩家停留点。落稳回到正常去重和实体碰撞。3-3未交露时实际不存在的lift[-1,0]明确排除，不能因其在module.shape里就提前补出来。固定岸始终留在原地；没有抬高板块、深度置顶或删除岸来掩盖重叠。

保留边界：模块扫过原同高岸面时局部仍会交叠；落稳该位置恢复固定岸的草纹所有权，属于接岸边界而不是模块主体换皮。关键静帧未见破洞或明显条纹，不据此声称任意连续帧都无共面闪烁。
