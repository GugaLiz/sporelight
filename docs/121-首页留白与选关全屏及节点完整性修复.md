# 首页留白与选关全屏及节点完整性修复

2026-11-18，`dev`。对应本次五张截图的新反馈；119号历史验收不覆盖此次发现的问题。

## 本次修正

| 反馈 | 核查与最终实现 |
| --- | --- |
| 选关没有铺满 | 原1280×720画布按contain居中，宽屏两边露底色。横屏改为视口大小的逻辑画布，背景铺满，节点、路径和装饰位置随画布延展，角色/植物保持等比；详情卡、章节预览与底部工具跟随布局。竖屏保留地图、详情、章节预览的滚动页面。 |
| 花蕾/开花截断 | 原组合图同时包含后方草平台和前方坑位，矩形裁片带进重复平台；中间轮廓候选还混用了240逻辑画布与256实际纹理坐标。最终放弃植物轮廓裁切，参考现用花蕾/粉花补绘独立透明层，三章节点共用，根颈对准同一个完整石圈的土面，只排除埋入土中的裸根。花瓣和叶片无轮廓裁切，石圈前景沿真实坑口曲线绘制。 |
| 发光虫形象不一致 | 直接使用首页的`menu-fx-redrawn/firefly.png`实际同源图；透明翅膀轻扑、虫体轻浮。暂停、减少动态及粒子关闭继续生效。 |
| 首页主按钮背景变形 | 整张纸面拉伸改为五段横向绘制：两端圆角/叶饰与中间菱星保持原比例，仅拉伸两段空白纸面。实际Button、文字、点击与焦点导航保留。 |
| 首页右侧太紧 | 桌面面板最大宽460→500，按高度增加分组留白和行距，标题32px，按内容真实最小高度垂直定位。首次仅开始，续玩时继续在上、重玩在下且弱化；小横屏/竖屏保持紧凑、可滚动。 |

同时修正宽屏节点位置延展后命中框仍按原876宽度夹紧的问题；真实指针覆盖1-3和最右侧1-4，锁关只能查看详情，不能进入。

主要实现：`godot/ui/chapter_map.gd`、`chapter_map_effects.gd`、`chapter_map_node_art.gd`、`menu_cover.gd`、`cover_button_art.gd`。本次未改变解锁、收藏、纪事、关卡规则或重新开始的保存语义。

## 素材与尺度

- 使用内置 image_gen 工具，依据现用组合稿分别生成独立透明花蕾和花朵，保留生成alpha。项目消费文件：[花朵](../godot/assets/images/menu-node-plants-20261118/bloom.png)、[花蕾](../godot/assets/images/menu-node-plants-20261118/bud.png)；完整提示词与参考角色见[生成记录](qa-godot-native/menu-layout-polish-20261118/asset-prompts.md)。世界关卡花坛没有替换。
- 石圈原图256×256→140逻辑像素，坑心源坐标(128,195)；坐姿臀点源坐标(128,159)。植物1280×1280透明画布：开花82×82、花蕾60×60逻辑像素，根颈归一化(.49,.765)。这组值仅适用于选关插画，不是世界尺度。
- 发光虫画布38×38逻辑像素；人物坐姿沿用119号完整人物稿及臀点配准。植物与人物的大小不随宽屏位置扩展而被横向拉长。

中间失败保留于`gpu-candidate/`、`gpu-candidate-2/`、`gpu-delivery/`、`gpu-rim-review/`、`gpu-final/`、`gpu-coordinate-fix/`、`gpu-accepted/`及`gpu-isolated-plants/`。其中名为accepted的早期目录仍有叶片裁线，**不作为最终美术通过证据**；最终为`gpu-reviewed/`。边缘延展shader、矩形植物裁切及手工叶冠轮廓均已从生产实现移除。
