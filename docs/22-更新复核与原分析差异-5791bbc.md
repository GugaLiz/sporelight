## 5. 本轮发现的新增问题与风险

### N01：3-2 有效替代状态下的目标与提示误报（P2，规则层已复现）

复现：按 `tests/garden2Solutions.ts` 中 3-2 解法，安放两柱、保留日影并切至月光；在首次前往 `f:3:4` 前，返回 `f:0:0`，执行 `take:sunPost`，再沿路走到 `f:3:4`。

内存转译加载实际 `GardenWorld` 与 `gardenJourney` 的结果：

```text
ready = true，together = true
安放日月柱 = false
两段影路相接 = true
两位到花床 = false
next = 要求重新搬日影柱放入起点日影槽
act('repair') = { ok: true }
```

留影保存几何后可取走原柱是既有合法规则，`tests/garden2.test.ts:188–189` 已覆盖。新 `presentation.ts:16` 却要求两柱仍在固定槽内；`:21` 又将前置步骤作为到达花床条件，`:25` 因此退回放柱提示。错误发生在播种前，实际通关仍成功，不应描述为无法通关。

建议：将教学里程碑和实际通关条件分开，按留影/连通真实语义判断；新增该替代状态的提示一致性回归。这次只报告，没有修复业务代码。尚未进行该状态的完整浏览器 UI 复现。

### N02：常驻提示可能过早透露解法（P2，体验风险）

`presentation.ts:25` 默认调用 `w.hint().message`，`GardenGame.ts:104` 常驻展示；点击不可达处也会附带提示。引导更明确，但部分解谜步骤会自动展示。建议默认只给目标和当前障碍，玩家主动请求时再升级到具体操作；通过首次玩家测试决定提示强度，不把此风险直接当成已证实的体验退化。

### N03：“留下看看”撤销外观与行为可能不一致（P2，静态发现）

`GardenGame.ts:103` 的撤销禁用仅检查 locked/canUndo，但 `:76` 拒绝 completed 状态执行撤销。漫游解除 inert 后存在“按钮可用却无动作”的路径。建议统一可用性条件并补浏览器回归；本轮未做专项 UI 复现。

### N04：新表现层带来额外性能和维护成本（需测量）

- `presentation.ts:29–31` 每个命令通过新建世界试执行判断可用性，属于 UI 刷新成本，不能误称所有命令每帧均克隆；可按状态版本缓存。
- 主渲染 `render.ts:107` 动画中每帧新建世界、`world.ts:75` 重算 tiles、`GardenGame.ts:132` 每帧热区计算等旧热点仍在。命令 HTML 去重是局部改善。
- 新雨滴/涟漪有粒子和低动态降级，但主循环暂停仍重绘，需测连续游玩帧时间、功耗与发热。
- 系统低动态已覆盖菜单与部分 CSS，主 Canvas 仍主要读用户 lowMotion，策略不统一。
- 光球/萤火虫 PNG 各为 1254×1254，实际通常只绘制约 42–86 逻辑像素；每张理论 RGBA 约 6 MiB，不等于实测进程内存。适合另生成运行缩略图。
- 菜单 DPR 上限没有限制总画布像素，超宽/4K 高 DPI 需设置像素预算并测量；目前没有证据证明实际卡顿。
