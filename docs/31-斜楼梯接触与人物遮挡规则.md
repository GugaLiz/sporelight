# 斜楼梯接触与人物遮挡规则

> 状态更正（2026-11-06）：本文记录的 `8a7186fd` 压短梯段与局部投影分片方案已被用户实际试玩拒绝，不能作为后续关卡的推荐实现。下文及其测试结果保留作历史；新实现、失败复盘及复用规则见[文档32](32-首关原生深度与移动表现优化记录.md)。旧测试证明内部一致，没有证明自然观感或上岸后的完整移动体验。

日期：2026-11-06。对象为1-1右侧根桥上岸楼梯。

本文初版仅整理原因和待实施规则，当时没有修改运行代码。用户随后要求按实际台阶、人物脚底和遮挡关系继续处理，本轮已经实现共享梯段、局部站位、脚锚及入口通行带绘制，并完成下文列出的验证及本地导出。

本轮只对`g:root:1:0/h0 ↔ f:2:0/h1`启用新的梯段与接触；文档30的固定墙稳定、连接渐显及原玩法继续保留。

## 修改前问题

截图位置对应`g:root:1:0 (1,0,h0) → f:2:0 (2,0,h1)`。它是规则允许的邻接通路；穿模发生在表现层，不能通过修改地块、加路、减少高差、自动跳跃或绕过播种来处理。

沿低格中心到高格中心定义纵向位置`u=0…1`，横跨梯宽定义`v`。

| 检查项 | 修改前实现 | 造成的表现 |
| --- | --- | --- |
| 人物高度 | `_interpolate()`按`h=u`线性升高 | 脚底低于多个踏面，被阶面切过 |
| 四阶实体 | 跑程`.1… .9`，高度依次`.25/.5/.75/1` | 人物走的斜线与实际画出的踏面不是同一条路径 |
| 高台边界 | 完整高格顶面从`u=.5`开始 | 第三级`.5… .7/h.75`已经进入高台`h1`实体，后半梯与高台重叠 |
| 双人站位 | 共享格露薇横移`+8px`，伙伴`−24px` | 纯屏幕横移同时改变沿梯及横梯位置；伙伴横梯偏移约`.343`格，超过`.29`半宽 |
| 绘制顺序 | 整梯固定depth=`2.04`，人物depth=`1+u+.50/.51` | 在`u≈.54/.53`时整组楼梯从人物前面突然换到后面 |

以修改前四阶为例，刚进入`.1/.3/.5/.7`时，线性脚底低于踏面约`7.2/9.6/12/14.4`个设计像素。窄屏缩放`.92`后仍约`6.6…13.2px`，会明显切到脚和小腿。相机投影会改变屏幕位置，但不是上述几何与排序矛盾的修复入口。

原人物素材还叠加了露薇`+7px`、伙伴`+4px`的绘制基准补偿。本轮已在接触区域统一身体脚锚，避免把这些补偿重复叠加到实际落脚点；区域外保留原素材绘制方式。

## 当前实现

### 1. 一份楼梯描述同时负责画面和接触

新增`godot/presentation/world/stair_surface.gd`。`build()`严格检查关卡、连接ID、端点坐标和高度，只为当前右根桥返回描述；`corners()`生成踏面，`contact()`查询脚底高度与状态，`stairs_depth()`给出静态梯段深度，绘制与人物共用这些数据。

人物接触只从真实规则地块中查找已经接通的根芽；不存在的根芽不能产生接触、可走通路或动作。两组用户已经要求删除的后排楼梯继续过滤。固定入口绘制分片使用独立的艺术描述，不能混入这套规则查询，见第5节。

### 2. 先消除楼梯与完整高台的实体重叠

本轮已经采用四阶铺至高台边缘的几何：`u=.10… .50`，半宽`.29`；每阶长度`.10`，高度为总高差的四分之一。`.50…1`是在原高台顶面上走向格心，阶梯不再延伸到高格实体内部。

这只调整当前连接的表现几何，不改变两格的规则位置、高度或通行关系，也没有搬动花床、平台和植物。高台完整墙深与墙砖仍保留；局部入口处理是同一墙面绘制的层次分片，并非挖空或删除主体墙。

如其他关卡采用嵌入式楼梯，则必须显式定义入口槽、台面开口和内壁；不能让完整实心台面与更低的踏面同时占据一处。不能直接把本例参数当成所有楼梯的通用长度。

### 3. 脚底走踏面，抬脚阶段单独表示

阶缘为`.10/.20/.30/.40`，每个阶缘前`.03`格使用平滑曲线抬高四分之一高差；到`.40`达到高台高度，其余阶段保持对应踏面或落脚区高度。`contact()`分别返回`landed/lift`、目标阶、实际支撑阶、高度、离地量及穿入量，不能把抬脚阶段当成已经踩实。

上行与下行查询同一条从低到高的接触曲线，方向相反。跳跃叠加在接触基线上，滚动和归队使用同一支撑面；规则步长、动作提交时机和连续行走方式不因此改变。

### 4. 双人站位使用楼梯局部坐标

`GardenView._station()`在根格及高台落脚区使用沿梯`u`和横梯`v`站位，替代原来的纯屏幕X偏移。两人共享端点时采用前后错位：

| 人物 | 低端落脚区 `(u,v)` | 高端落脚区 `(u,v)` |
| --- | --- | --- |
| 露薇 | `(-.08,-.06)` | `(1.08,-.06)` |
| 伙伴 | `(-.32,.06)` | `(.80,.06)` |

独行时横向为0，低端`u=-.08`、高端`u=1`。低端脚点在第一级前方，高端脚点在原高台范围内；跨梯时根据两端站位插值，再用实际`u`查询脚高。不会仅通过缩小屏幕X偏移伪装进入梯宽。

静止、进入根格、起步、回头、到站、清除动画和读档共用站位查询。接触区域外的端点把原屏幕站位换算为世界点，再与接触区域端点插值，避免在动画开关时才切换人物位置。具体连续性仍按后文的最终验收检查。

### 5. 支撑顺序与真实前景分开判断

右桥梯段现在使用静态`low.x+low.z+.04`，不再采用高端最大深度，也不随人物进度交换整段图层。高台通行带的一小部分原绘制放在低端深度`+.02`的支撑层，通行带外仍按高台原深度绘制。

通行带由`StairSurface.cover_polygon()`给出固定投影凸包：沿梯`u=-.40… .70`、横向`v=±.34`，按接触高度采样并向屏幕上方延展90个设计像素。`Landscape.floor_tile()`只对1-1的`f:2:0`按该多边形分出inside/outside；两部分合起来仍覆盖原顶面和墙面。墙砖UV按原坐标求值，原外轮廓线按相同mask分段，不给新裁切边描线。

这份分片是`f:2:0`的恒定艺术网格：未播种右根时也使用同样分片，播种、回收和运动进度不会开关网格。构造它所用的虚拟低端只生成艺术mask，没有添加到`world.tiles()`、寻路、连接集合或人物接触解析中；真正楼梯及人物接触仍要求实际根芽存在。

恒定分片解决了“alpha刚大于0时才换三角网格”的边界跳色。它不等同于旧版本未分片画面的逐像素复原，也不是一套提前揭示路线的系统；完整场景里的线索和前景遮挡仍需实际验收，不能只依据地形隔离图下结论。

人物没有全局置顶，整座岛墙没有移动到人物后面，花床、植被和其它地形继续原排序。全人物置顶会穿过真正前景，删除墙面会改变空间和隐藏关系，改路线或自动补路会改变解谜选择；这些都不能作为接触问题的修复手段。

### 6. 逻辑位置、接触位置和身体位置分别命名

| 数据 | 用途 |
| --- | --- |
| 逻辑锚点 | 规则地块、寻路、相机原有插值 |
| 接触点 | 踏面支撑、地面脚环/影子 |
| 身体脚锚 | 接触点加局部站位、美术脚锚校准和跳高；身体、携带物、保护框与诊断共用 |

相机继续原逻辑插值，身体使用`actor_ground_point()`和`actor_screen_footpoint()`。接触区域不再重复叠加原`+7/+4px`偏移，人物、携带物、脚环和保护区域共享接触位置；屏幕身体脚锚与保护框扣除当前跳高，地面脚环保留接触基线。诊断额外报告实际接触状态，而非只根据旧字段名称认定踩实。

### 7. 保留现有播种过渡规则

文档30中的固定岛墙规则、连接ID并集与透明度仍是前提。根芽和其楼梯一起渐显/渐隐，固定墙面及无关右侧楼梯稳定；不得通过重新裁掉主体墙来解决人物遮挡。

新增的楼梯实体、站位和入口分片目前只在1-1右根桥启用。后续关卡应按各自入口几何接入并验收，不能全关统一增加人物高度或复制本例mask。

## 实施中发现并修正的问题

最初的局部分片沿用了“裁出新多边形后按渐变bounds重新算UV”的方式。原墙面的渐变先在原四角clamp UV，再按原三角形插值，四个角不属于同一个affine UV平面；新顶点重新clamp会让整块墙的色调改变。

现已保留原四角UV及原三角化，逐个原三角形裁切并沿各自UV平面插值，避免重新计算材质。中间版本全帧对比曾有5298个像素变化、最大通道差25；修正渐变后仍有约300个边界像素差、最大25。不能把这个中间结果记录成完全复原。

最终采用上文的恒定艺术分片，确保播种前、0、极小进度和后续阶段使用同一网格，避免动作开始时发生这类光栅差异；这与“当前画面和旧未分片版绝对像素相同”是两件事。
