# 1-1 规则提取与后续关卡接入

> 2026-11-10 状态索引：本文记录首关提取时的实现。“仅首关注册 profile、1-2 使用 fallback”已由文档 53 的接入更新。后续工作以 [全关卡现行规则](56-全关卡优化规则与首关验收基线.md) 和 [逐关契约](57-全关卡玩法契约与优化清单.md) 为入口；下面的历史验证记录保留。

本轮范围：整理并重构当前原生 1-1；不改变素材、布局、谜题、存档格式，不制作 1-2 新地图。1-2/1-3 仍使用原生默认表现。以下是现行行为契约，不是所有关卡必须照搬的解法。

## 一、主流程与可选探索

| 阶段 | 玩家行为与结果 | 必须保持的约束 |
| --- | --- | --- |
| 入场 | 从 `f:0:0` 根台开始，显示花床复苏目标 | 不自动播种，不提前展示具体解法；固定地图 19 格 |
| 选择 | 在根台选择向东或向南生长 | 只有 1 节预算，不能同时保留两条路；方向必须由玩家确认 |
| 主线 | 东桥 `g:root:1:0` → 右岛 → 后排阶梯 → 上平台 `f:3:-2` | 花坛在上平台；下方旧位置不提供种植操作 |
| 完成 | 在花坛执行 `repair`，完成花园复苏 | 不以收齐孢子为前置条件；伙伴会合/动作提交沿用现有事务规则 |
| 探索 | 南桥 `g:root:0:1` → 南岛；收集、观察 | 可选路线，不替代主线，不自动完成关卡 |
| 改路 | 两人安全返回固定地面，再收回、重新选择 | 占用桥时不能收回；禁止用渲染状态绕过领域校验 |
| 回退与恢复 | 撤销、回主界面、继续、读档 | 撤销恢复拓扑；离开取消未提交动作；存档保存逻辑坐标与合法支撑格 |

主流程的数据和判定仍由 `content/levels.json`、`GardenWorld`、`GameSession` 负责。本轮没有修改这些文件。目标和三级提示文案继续由现有 `GardenJourney` 提供，避免另造一套任务进度。

## 二、地形与材质规则

| 规则 | 当前 1-1 数值/行为 | 所属模块 |
| --- | --- | --- |
| 高度 | 每层 0.65；起点 0、右岛 0.65、后平台 1.30、南岛 -0.65 | `first_garden_profile.gd` |
| 岛间距 | 右岛物理坐标向东增加 0.65；桥跨度 1.65；逻辑坐标不变 | profile 的双向坐标映射 |
| 阶梯 | 东/南梯范围 0.58–1.48，后梯 0.41–1.31，均 6 级 | profile 配置 + `stair_geometry.gd` |
| 踏面 | 每一级严格水平，阶缘处按所属区间取高；边条两端属于同一踏面 | `native_surface.gd` |
| 立面 | 相邻踏面高差形成真实竖直面，不用斜贴图模拟 | surface 共享几何 |
| 梯底 | 连接桥底沿两端平台连线连续倾斜，厚度 0.20；上轮廓仍逐级 | surface 的连接桥截面 |
| 碰撞 | 可见踏面、立面与碰撞来自同一高度定义；禁止视觉单独抬高掩盖穿模 | surface + movement |
| 地面 | 原铺地贴图，根路用苔藓，指定草地格保留草地，其余山谷铺石 | profile 选材 + `terrace_materials.gd` |
| 侧面 | 原铺石颗粒配合墙面坐标；按物理长度连续展开，避免窄分片拉伸 | `garden_island_stone.gdshader` + surface |
| 楼梯纹理 | 平面、立面分别校正原斜视图 UV；UV2 描述真实面，不重复整幅楼梯图 | profile 的素材采样 + surface + `garden_stair.gdshader` |
| 连接梯变化 | 石缝、颗粒变化由稳定级数/石块种子决定；不随帧随机闪动 | 现有 stair shader |
| 景物 | 花坛、植物、灯笼、藤蔓的位置和比例为关卡专属；不参与寻路 | `first_garden_dressing.gd` |

`StairGeometry` 只负责离散高度、平滑脚底包络、踏面局部 UV；不认识关卡 ID。`NativeGardenSurface` 通过 `terrain_profile` 注入获得高度/采样/UV，不再直接加载首关。`TerraceMaterials` 构建分面材质，纹理加载和缓存仍归 stage，避免重复加载或延迟编译回退。

注意：当前 surface 的连接桥截面支持沿 X/Z 的轴向单格连接，profile 内的石材采样对应当前 142×147 原素材。未来弯桥、任意斜向桥或多格连续根路，应先扩展明确的轴线/端点契约，不能直接复制首关坐标推断。

## 三、行走、防穿模与任务动态

- 通行合法性由领域邻接图决定，移动器执行真实胶囊碰撞和跨格提交；视觉 profile 不能新增通路。
- 首关开启全宽通行与实体台阶跨步，取消旧坡道肩部走廊约束。其他关卡保持原走廊逻辑。
- 沿楼梯方向速度系数 0.62，横向维持正常速度。可见脚底以 0.10 物理单位在阶缘前后过渡，取真实踏面上包络；停步恢复地面接触。
- 角色保持竖直深度平面并补偿投影高度；不关闭深度测试、不始终置顶。行走转向保留左右脚动画相位。
- 根路生成统一从高端向低端揭示，通过材质裁剪呈现延伸。动画期间不缩放楼梯、不重建固定岛屿；动作结束恢复原材质，取消时清理临时状态。
- 常规生长 0.68 秒；减少动态模式生长和收回为 0.44 秒；拿放 0.32 秒，观察/发现/朝向 0.24 秒，转动/阀门/升降/节拍 0.62 秒，种植完成 0.75 秒，默认 0.36 秒。
- 时长由 `NativeActionPolicy` 统一查询；预览、校验、提交、取消依旧归应用事务协调，未提交的桥不能走。完成动作结束后恢复普通站立，不残留低头姿势。
- 首页预热一帧继续保留：仅渲染准备，不恢复人物或音频；完成后停渲染。快速点击“继续”时，迟到回调不能把活动视口关闭。

更完整的角色约束见 [50-原生角色楼梯接触与防穿模规则](50-原生角色楼梯接触与防穿模规则.md)。

## 四、交互、提示与界面状态

`NativeInteraction` 是无副作用的目标解析和邻近操作分组器：

1. 解析明确目标、标记、根台、物件、模块或当前格，调用 stage 提供的坐标转换。
2. 筛选物理平面距离不超过 1.65 的操作，以目标格分组。
3. 观察/发现组附加 0.35 的距离排序权重，避免抢占身旁机关。
4. 可用状态与禁用理由原样来自领域查询；返回项复制后才替换显示标签。
5. 根路即使只有一个选项也保留原有上下文语义；选项键盘焦点与确认仍由 HUD 管理，GUI 优先消费 Enter/手柄确认。

提示导航抽为 `HintNavigation` 状态转换，HUD 仍是可见状态的唯一来源，应用只保存当前提示级别：

| 操作 | 结果 |
| --- | --- |
| 点击提示按钮，当前隐藏 | 显示上次阅读级别 |
| 再点提示按钮，当前显示 | 隐藏，不推进内容 |
| 点击提示内容 | 0 → 1 → 2 → 0 循环，不暂停游戏 |
| 进入关卡 | 级别归零并隐藏 |
| 普通 HUD 刷新 | 不重新打开已隐藏提示 |
| 已完成 | 各级内容由 Journey 显示关卡结语 |

提示继续放在底部按钮上方，文字居中，不增加模态窗口。手机竖屏阻断和横屏恢复原暂停状态、HUD 布局稳定后相机更新、首次移动不重新取景等既有协调逻辑不重复搬家；它们已经是公共应用/HUD 行为。

## 五、模块边界与后续 1-2 接入

| 层 | 责任 | 不应承担 |
| --- | --- | --- |
| Domain/Session | 地图、根路预算、邻接、任务完成、撤销和存档 | 材质、纹理 UV、动画时长 |
| `level_presentation_profiles.gd` | 选择关卡的地形、装饰与独立表现能力 | 修改玩法或给所有关卡强加首关能力 |
| `first_garden_profile.gd` | 1-1 坐标、高度、采样格、选材 | 操作提交、HUD 状态 |
| `stair_geometry.gd` / surface / materials | 可复用数学、共享几何/碰撞、分面材质 | 首关 ID 判断、具体解法 |
| `first_garden_dressing.gd` | 1-1 固定场景装饰与花坛绘制 | 通路或任务条件 |
| NativeMovement | 输入、真实移动、合法支撑跨越 | 按关卡 ID 选择台阶行为 |
| Interaction / ActionPolicy / HintNavigation | 可复用交互查询、时长、提示导航 | 存档、自动选解法、重复任务状态 |
| Main / HUD / Journey | 事务协调、控件焦点、文案、状态展示 | 复制公共地形数学 |

仅 `1-1` 注册新的表现 profile；其他 ID 返回空配置，明确使用旧 fallback。更换关卡时同步切换 profile，并测试 `1-1 → 1-2 → 1-3 → 1-1`，防止缓存、坐标变换和能力串关。

后续优化 1-2 的顺序：

1. 先记录岩石绕路、根尖连续生长、预算、撤回、可选收集和完成条件，建立现状测试。
2. 单独设计 1-2 terrain/dressing；复用材质与阶梯规则，但保留其连续根路拓扑，不复制首关东/南二选一文案和单节限制。
3. 按需求逐项打开全宽通行、脚底包络、角色深度、生成动画等能力；自定义 profile 须满足采样、height、坐标往返、foundation、stair_spec、UV 与 material_spec 契约。
4. 新材质缓存 key 须包含影响外观和地形的配置身份，避免不同 profile 共用错误缓存。共享静态配置仅作只读使用。
5. 回归所有可通关路径、失败操作、撤销和读档，再做桌面/手机横屏截图及性能对照；最后才接入用户预览。
