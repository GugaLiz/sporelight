# 微光苔原 · 开发落地方案

> 2026-10-20更新：以下为首版记录；当前关卡规则及本轮验证以[玩法差异化改版](05-玩法差异化改版.md)为准。

版本1.0 / 2026-10-19。与产品文档配套，具体完成和验证结果以验收记录为准。

## 架构

延续Vite + TypeScript，无新增运行时框架。DOM负责页面、HUD、弹窗、可访问交互；Canvas 2D负责路径、角色、植物、光线和粒子。1280×720逻辑坐标以contain缩放，节点位置与DOM交互层同一坐标源。

- `src/app/game/levels.ts`：12关的节点、连线、机关、收集及奖励，纯数据。
- `src/app/game/model.ts`：纯逻辑状态机，移动可达性、机关条件、收集、撤销、存档恢复、评分。
- `src/app/game/CanvasGame.ts`：渲染与输入适配，移动插值、跳跃、动态效果；不决定存档结构。
- `src/app/game/audio.ts`：用户手势启用Web Audio，音乐/环境/音效独立音量，失焦静音。
- `src/app/save.ts`：v2读写、字段校验、v1兼容和存储失败处理。
- `src/app/createApp.ts`：页面路由、生命周期、暂停、结算、自动存档。
- `src/app/scenes/*`：页面渲染；`src/styles/journey.css`提供首版的新UI层。
- `scripts/prepare_assets.py`：已有PNG统一尺寸、alpha边界裁剪、图集、清单和预览；不覆盖源素材。

## 游戏状态

`node`为玩家当前节点；`collected`为节点ID集合；`activated`为机关ID集合；`angles`记录反光叶角度；`completed`防止重复结算。关卡运行时配置不进入持久存档，保存关卡ID和最小状态。撤销使用状态快照，节拍相位只作为运行时参数。任何有效移动/交互后保存，重来丢弃当前局但保留历史最佳。

路径图是无向图；带`gate`的边只在对应机关激活时通过。点击远处可达节点时使用BFS得到路径，逐段移动并收集。点击未连通节点应解释下一步，而不是让角色穿越虚空。键盘按屏幕方向选择邻接的可行节点。

机关类型：grow（直接生长）、lily（打开并触发跨边跳跃）、reflect（3角度循环，正确角度激活，之后固定）、rhythm（3秒周期开放1.5秒，低动态永远开放）、light（点亮）、sequence（必须按配置顺序；错误无状态损失）。播种不消耗孢子，避免缺资源软锁。

## 关卡内容制作

普通关的主路以机关分段，支路放可选孢子。最终关采用四向分支、8孢子与4个仪式节点，所有收集区域在仪式前可达；终点由最后机关锁定。必须用自动解法检查每个机关在其锁住的边之前可达，最终关没有“要通关才能获得最后孢子”的循环依赖。

## 资源管线

源：`assets/images/sporelight_complete_assets_png`、`assets/images/material/world_01.png`、`world_02.png`和`assets/images/main/`。对大图按区域裁切并处理边缘连通的浅灰棋盘背景；对透明PNG读取alpha包围盒→保留边距→按比例缩放→底部锚点对齐到统一256×256画布。输出到`assets/images/production/`，用图集清单保留来源、输出尺寸、alpha状态与字节数。背景从无UI的主菜单图适配为1280×720，章节色调是后期变体，不能称独立AI绘制。

生成的sprite atlas用于美术核对和未来批处理；首版渲染可直接使用独立PNG，避免图集裁切坐标误差。开发素材总览页列出实际输出。未清理的拼图、带棋盘格的素材不直接进入游戏。

新AI绘制建议按`docs/03-素材制作规格与提示词.md`逐资产生成并检查；当前工具不可用时留下明确状态，禁止假称图片已经生成。备选CLI必须用户明确选择且本地已配置key，不能从其他应用提取凭据。

## 生命周期与异常处理

- 进入游戏创建model+renderer；离开销毁RAF、键盘、指针、计时器与音频监听。
- 打开设置冻结游戏，保留快照；关闭从原位置恢复。resize只更新缩放不重建场景。
- 隐藏标签页停止推进节拍/动画；恢复时重置时间差，避免瞬移。
- 写存档失败返回false并弹出一次提示，继续内存运行。
- 输入名统一去首尾空格并转义HTML；非法存档字段逐项回退，不将未知结构展开到运行对象。
- 完成回调只触发一次，记录本局真实数值；重玩不覆盖更高最佳成绩。

## 实施顺序

1. 产品需求、规则冲突决议、12关表和验收定义。
2. 素材审核、加工导出、manifest、预览与缺口登记。
3. 纯逻辑model和关卡配置，自动解法验证。
4. Canvas视觉和交互层，页面与完整流转。
5. 存档、撤销、设置、音频、响应式、无障碍。
6. 类型检查、构建、逻辑回归、浏览器操作与截图，记录剩余差距。

## 运行与部署

需要Node.js 18+（建议使用环境提供的新版本；当前系统PATH的Node 14不满足Vite 5）。安装依赖后执行`npm run dev`，默认127.0.0.1:4173；`npm run build`产生dist；`npm run preview`预览构建。部署为静态网站，无后端与数据库。当前资源URL以站点根路径为基准，部署到域名子路径前需要统一改写资源base。

性能预算作为后续发布指标：关键首屏压缩传输目标<8MB；首屏主要图片解码后可交互；主流桌面目标60fps、移动目标30fps。现有完整素材目录体积较大，正式部署前应只发布引用资源并做压缩；未经过性能测量不能将预算写成已达成结果。
