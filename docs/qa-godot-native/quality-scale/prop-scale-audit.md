# 机制道具、携带物与脚锚尺度候选

2026-11-11。此表为当前实现候选及 CPU 原图测量，不代表 GPU 比例已验收。普通镜头、桌面/小横屏画面由本轮最终集成另验。主角、伙伴和1-1原脚锚保持。

## 测量方法

直接读取原PNG，主体阈值为 alpha≥128，包围盒使用 `[x,y,width,height]`（像素）。软边不作为主体尺寸，拾取光晕由效果专项独立处理。世界宽为包围盒宽×pixel_size；此处宽高是图像平面尺寸，不把它当成地面占地。携带物按同一主体比较；镜子的地面底座与可携镜面明确分开。

主角站立原图256×256、主体框 `[70,21,116,215]`，pixel_size=.00625，图像平面主体宽.725、高1.34375。动作姿态原校准保留。伙伴使用原128×128合成纹理、.0062及原脚锚，不因装饰调大/调小。

## 紧裁地面素材脚锚

下列图片的alpha128框均等于全画布，最后一排实体像素中心为 `height-.5`。非1-1通过白名单将offset设置为`(0,(height-1)/2)`，使该像素中心落到Sprite根处。原先统一`height*.4`会把底部埋入支撑。Dressing仍决定宽度与真实地面位置；本helper不另加Y位移。

## 机制花与萤火虫

旧机制花在未激活时为紧裁`flowers`（名义宽.67、主体高.639），激活时为bloom上部裁片（主体高.293），造成54%的高度跳变且裁口缺真实脚。当前候选采用完整`flower`→`bloom`、共同256画布、名义宽.67，复用完整等角脚锚与接地shader，仍只有一个无碰撞Sprite。

| 状态 | alpha128框 | 当前主体宽×高 |
| --- | --- | --- |
| 未开花 | `[16,50,224,182]` | .58625×.47633 |
| 开花 | `[16,42,224,190]` | .58625×.49727 |

两态同一位置、脚锚与底座图，花开后自然增加约4.4%高度；核心花坛独立的1.16/.98/.90宽度不改。2-4 plant/invite仍共用同一视觉，不增加第二朵或新增规则支撑。该完整小花坛候选需确认与同格轮台和植物的视觉关系。

萤火虫bug原图256×256，alpha128框 `[73,108,114,110]`；原名义宽.4实际主体仅.178×.172。当前主体宽.28、高约.270，主体中心悬于支撑上.28，保持昆虫悬浮语义，不借用地面脚锚。此候选只作用于bug，不改伙伴蘑菇。

## 验证入口与边界

新增 `native_prop_scale_test.gd` 从原PNG独立测量alpha框；核对15关规则快照与角色尺寸、首关锚点保护、白名单实体脚像素、两态花体比例、实际take/drop/plant/care、撤销与读档，以及同物件地面/携带主体相同。镜面模型另核对边框、背叶及底座分离。

同轮还使用 `native_actor_pose_test`、`native_mechanism_props_test`、`native_prop_alignment_test`。开发中失败的 `props-candidate`（测试自身float32精确比较和隐藏core空值）保留；早期仅携带尺寸候选的`props-scale-final`已被“地面/携带一致”方案替代。

“同尺寸”候选 `props-consistent-size/checks.json` 四套共4,258项通过且源码稳定（actor_pose606、mechanism_props279、prop_alignment3073、prop_scale300）。之后增加持物资源缓存、日/月柱手中色彩，并补实际手持旋转和缓存复用检查；最终 `props-cached-final/checks.json` 三套共3,664项通过且源码稳定（279+3073+312）。缓存版没有重跑actor_pose，不把两批拼称同一次四套验收。

携带模型只在关卡、持物身份或方向改变时重建；普通刷新复用镜框资源。最终GPU与交付以本轮正式记录为准，不能把这些CPU检查称为全部画面通过。

## GPU发现后的2-4共享船格例外

全关候选GPU在`all-element-scale/mechanism-details/1280x720/2-4-use-invite/clear.png`发现：`slide`、`plant`、`invite`共用`m:boat:0:0`，控制轮遮住花与登船光虫。新增例外仅把2-4 slide的底座、杆、轮及随轮符号显示子节点偏移`(.45,0,-.45)`；不改变父mark、tile_id、交互中心、花虫高度、深度、尺寸或碰撞。偏移跨出中心格的部分仍完整位于3×3同高船面内，不能套用于单格机关或其他轮台。

新`native_ferry_prop_layout_test`按原图alpha128框与控制器mesh AABB实际投影比较，覆盖两尺寸14种静态状态、0/25/50/75/100%移动和撤销。570项通过，最小横向间隙：花与控制器.08972世界单位、虫与控制器.21426；底座9点始终由同船真实表面支撑。实动作与撤销比较采用严格存档加载后的规范化fixture，保留初版raw JSON数值类型比较失败日志，不改fixture或规则来通过。

`all-element-scale/boat-clear-headless`内指定四程序mechanism279、motion_cache9087、prop_alignment3073、prop_scale312全部通过（12,751项）；该批总报告仍保留新专项初稿失败。修正测试输入比较后的独立`boat-clear-layout-final/checks.json`为570项最终通过、源码稳定。两批运行源码相同；修复后的实际画面、触屏流程和横移动画由最终集成重新采集，不能以投影计算替代GPU原图检查。
