# 主线装饰位置只读审计（2026-11-11）

范围：1-1…3-4。未修改运行代码、尺寸、原元素数量、地形或规则。诊断脚本 `mainline.gd`、200 条初态/参考完成态记录 `mainline.json`。已实际查看 accepted-stroll 的 12 关桌面全景、1-3 普通 completed-clear；对照 landmark-stroll 的 2-2、2-3、3-4 全景。历史图用于定位，不能充当新位置的验收图。云庭由其他负责人覆盖，本报告不冒充 15 关全部检查完成。

## 核心结论

1. 当前问题首先是**恢复尺寸后仍照搬旧二维位置，落点算法只判支撑，完全未保留通行/交互/核心/邻近装饰空间**。`find_placement` 按源坐标距离排序，找到第一个平脚候选就返回；没有路线、出生、实际 planter 基座、未来停靠或可见轮廓输入。它甚至允许 `abs(tile.h-authored.h) <= 1.01`，不是严格同高算法。多数旧 `±.24` 边沿偏移原封不动。不能靠扩大搜索或所有元素统一推到格子中心解决。
2. **脚部模型自身过窄**。`SOURCE_FEET` 用最后 5% opaque 行，`foot_radius` 将这一条宽度转为对称小方形。真实建筑底座并不只占最后几行：arch 最后5%宽73px，最后15%宽179px；stone-lantern 58→114px；light-tower 151→272px；river-rock 64→108px。灌木则37→109px、粉花35→130px（植物外伸应区分根/叶，不能把全部叶片强行当碰撞）。拱门另一根柱脚较高，底行只看到前柱，现有半径不能证明两柱都落地。要按具体素材地面接触结构，而不是简单改成统一15%。
3. 200 条记录用现有半径增加到11×11支撑采样后**未发现落空**，未发现初态角色中心重合。这说明“再多采样当前小脚印”仍会全部通过，不足以解释并关闭用户反馈。
4. 读真实 `core_planter.ground_footprint_center/span`，已找到6关装饰与核心基座占地重叠（下表）。这些不能用核心交互原点代替检查。
5. 中心到合法邻格的线段，加角色半径.16，与装饰现有脚半径相交，产生大量**路中穿插风险**。这不是“谜题不通”的判定，外围格可能允许玩家绕行；它准确解释为何不带装饰碰撞的角色会走穿植物/灯。必须结合该关真实访问路线、停靠和普通画面决定移位，不能把所有边沿装饰都判死。

## 建议实现顺序与边界

1. 先以1-3为落点样板：不动size，建显式实例覆盖表；记录源位置、最终脚锚、支撑、移位理由。将道路/机关/站位/完整基座考虑放入选位，不再纯 nearest-flat。
2. 同步明确建筑完整底座、拱门双柱、菌脚/根簇/叶冠的不同规则；宽脚与窄脚切勿统一。必要时用局部足迹多边形，不能伪造地板。
3. 优先修六个已检出的核心交叉点，再处理每关路口、接岸和边沿视觉问题；1-1保留基准，不批量洗牌。
4. 每批都保留当前认可尺寸，测密集真实支撑、实际完整几何占地、出生与完成姿势、玩法关键路径和所有相关运动端点；最后看普通/全景及小横屏，判断是否仍遮人物、台阶或机制。

没有跑新GPU，也没有把自动风险计数当成已确认视觉错误数量。当前11×11支撑通过只证明现声明小脚印没有掉出地板；6个核心交叉是按实际矩形测得的独立位置问题。
