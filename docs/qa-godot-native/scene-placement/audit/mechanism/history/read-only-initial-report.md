# 机关、核心、收藏、云庭位置只读审计

范围：15关初态与参考完成态，共30状态、197个mark/item根、42个云庭装饰根、21个当前可见主线核心。只写 `.tmp` 诊断/证据，未修改运行时、尺寸、地图或碰撞，未运行GPU。数据见 `position-audit-mechanisms.json`。仅验证的落地中心不能代替完整底面或画面可读性。

## 已证实的问题与应对

1. **机关站位与实体底座共用格中心。** `mechanism_props._instrument` 除2-4外的底座中心为root原点、半径.19；`actor_rest_offset`没有机关格策略，点击终点也是格中心。1-3 `mark:turn=m:garden:0:0` root=(0,0,0)，角色到此时默认rest也是(0,0,0)，并非机制在漂移。2-1初态主角直接在阀门底座中心；诊断测得距离0。应保持规则根/环中心不动，将机关可见支座在同一真实甲板内固定偏移，或给人物建立可达同格站位，且一并覆盖点击、跟随、旧默认姿态。候选偏移(-.25,0,-.25)与人物中心距离.354，必须再验证底座半径、台阶高度以及GPU；不能把此候选直接当已通过。2-4已有(.6,0,-.6)偏移，距离规则根.849，但仍落在原3×3甲板，不能机械回中。

2. **后移花坛的显示锚与交互根本来就不同。** 1-3核心规则root=(0,.65,-4)，完整底座中心为(-.6,.65,-4.53)，卡片局部位置(-.082732,.02299,.051374)。这是为角色留出原平台前侧而稳定后移，不是世界映射重复偏移。全部21个可见主线核心的声明完整底面支撑均通过。1-4偏移(1.2,0,-.7)、2-4(.35,0,-.7)、2-3/3-1(-.6,0,-.7)、3-4(-.4,0,-.4)应各自核对，不能统一回零。现在只有1-4通过源alpha图点击映射到原core支持；其余后移花坛的花朵点击仍走底下投影地块。建议在保留1-1现行入口的前提下，为其余真实偏移核心复用透明像素/遮挡感知物件选择，交互命令及合法距离仍由原规则决定。

3. **平面支持验证与位图底座投影不完全同义。** `IntegratedGardenProps.planter`把(.27,.012,.34)整体按width/1.16缩放，脚offset固定102；接触补片及声明底面中心的z=.07没有随比例缩放。1-3相对基准因子1.916，位图局部Y=.02299，而补片Y仍.008。这是明确可定位的两套脚锚计算，不足以单凭数值断言肉眼悬空。应在锁定宽度/投影比例下测图片底部实体边缘与补片中心，再仅改锚点/补片位置；不要把完整底座卡片直接改成竖直，原等角底座的画法与普通花草不同。1-1这些值是认可基准，保持原样。

## 检查正常或需避免误修的部分

- **1-3转轮本身接地、朝向成立。** InstrumentBase底部与真实台面误差约1e-9；根就是m:garden:0:0。轮面基向量来自固定相机，细环是竖立机关轮，不是地面圈。NearbyInteractionRing另以surface局部网格贴真实踏面，角色进入才出现；其位置不应移到轮心或整个花坛前沿。
- **随动链没有发现错绑。** 当前 `native_motion_cache_test`9,087项、`native_prop_alignment_test`3,108项（34动作）均通过，包含源surface、运动中根与环、落稳。props根由 `_surface_for_support`绑定source实体，云桥在ID变化时走origins映射；不是简单按after终态贴图。改位置时偏移应在物件子节点且持续保留，不可每帧把root改到别的格。
- **收藏是有意浮动。** 原spore维持35px尺寸，真实surface根+Y .42±.045，光晕Y .018；它不是应压到地上的摆件。1-3 spore-0与rest同时在f:-5:-1，所以那里存在“花束+光球”叠置，需在锁定大小下为可选收藏设置局部避让。现bell同格偏移(-.18,0,.18)仅影响1-4且是既有设计；若新增其他避让，中心必须仍落该支持，移动台偏移应随对应surface变换。
- **云庭物件root与前脚不可混用。** `_card`用源foot沿FRONT移动，保留原屏幕位置和真正落脚。cloud-2池root=(10,1.95,3)，卡片前脚=(11.03448,1.95,4.034483)，是正确的前沿语义；plant_large前脚=(8.586206,1.95,3.586207)、arch=(3.465517,0,3.465517)、bench=(.413793,0,7.413793)。42根中所有地面物件的前脚中心都有同高真实面；瀑布是唯一不需地面脚支持的悬挂例外。不能把它们统统拉回root造成池子后半穿地。仍需GPU核对人与物、物与物关系和整脚宽度。
- **云庭鸟已有同高位置例外。** source(11,3,h3)→root(11.2,4.4,h3)，卡片前脚(11.06207,1.95,4.262069)，避免被原池前壁全挡；不宜为了“原坐标”回退。云升台绿色标记是原top材质随surface移动，不应另挂地面平片。

## 1-1应保持的已认可位置

`FirstGardenDressing`所有原位、Terrain.to_physical映射、核心f:3:-2→(3.65,1.3,-2)、核心width1.16/shift0/局部(.27,.012,.34)/offset102、根台(.16,.012,.16)、GrowthAnchor(.16,.10,.16)、原交互环格中心+Y.025，以及现行人物脚锚均保持。1-1不属于应批量套新机关/装饰位置的目标。

结论：本审计能证实“人物/机关重合”“显示根与交互根偏移”“两套核心脚锚计算”的具体来源；没有发现所有机关整体坐标系错误或运动根错绑。用户截图顶部蘑菇/灌木/灯花的脚锚与落点应合并presentation的装饰审计后确定最终修正。GPU结论归主验收，不用以上数值通过关闭用户位置反馈。
