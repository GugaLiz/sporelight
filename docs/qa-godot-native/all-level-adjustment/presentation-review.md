# 渲染专项自审

2026-11-10。以文档 56/57 的玩法保护规则为前提；本专项不修改关卡定义、规则、碰撞、存档或首关几何。

## 改动与理由

- 1-3 至 3-4、三座云庭显式启用表现能力，保留原动态地形、坡槽与真实胶囊通行。新增的共享配置不是首关台阶参数模板。
- 完整原图花坛替代原先裁剪植物与程序小底盒，适应一格落台的宽度为 0.90，使用原脚锚和独立接触暗部；山谷、池塘、洞窟和云庭分别调色，材质按章节及源图缓存。
- 角色竖直深度避免图片后倾插入高地，同时保持原人物投影大小、脚点、等待/熟睡姿态和真实遮挡。
- 动态花园的坡面接入相邻道路同章原铺石纹理，保持碰撞面不变。旧首关、第二关和未知配置与新章材质缓存隔离。
- 少量原植物只放在可见固定岛的平坦边缘，避开机关、物品、收集点、窄路及动态支撑。移除旧随机直立藤蔓挤占通路的观感。

## 评审发现与修正

首轮洞窟装饰采用 `crystal`，与 3-2 的可搬日/月影柱复用外形，会形成假交互暗示。已改用原 `blue-flowers`，同时移除晶簇专用尺寸分支，并新增“装饰不使用影柱源图”检查。该小修订需以最终构建的新洞窟截图确认，不把首轮截图当作修订后的证据。

另外，独立代码审查指出原有转光庭动画起步即显示目标态光束的可能性，已交主 agent 与机关/GPU专项复现和处理；不将最终端点正确当作动作中段也正确的证据。

- 首轮新增测试曾因测试访问缺省 `tile.kind` 和假设熟睡伙伴未缩放而失败，已修正测试输入/对照方式，保留 `presentation-initial` 日志。
- `presentation-candidate` 的稳定源码检查：角色深度 24948 项、章节表现 260 项、首关合同 93 项，共 25301 项通过。
- 装饰语义修正后，章节表现专项增至 295 项，直接 Godot 运行通过；最终统一检查与最终 GPU 证据以本批次总报告为准。
- 章节测试对比启用/关闭表现能力时每个真实碰撞面的顶点、变换和坡度，确认表现改动不改变支撑；检查花坛脚锚、章节材质缓存、可见性、安全装饰与世界快照不变。
- 角色深度测试覆盖全部注册后续关的固定/动态支撑，校验实际投影、脚点、深度测试与重复更新，不把此测试当作完整通关路线替代。

## 真实触屏流程后的交互修订复审

后续真实触屏路线发现：3-1 已开窗时，脚下禁用的“已经安定了”挡住旁边合法的照料；云庭的单项摸伙伴动作也可能挡住同范围观察。交互修订后的冻结摘要为 `0e920007a200c6bc248c7eec777932b8edbfb985dd831984bcbecd12748889f6`。前节 6f83 的画面证据对应渲染修订版本，不能冒充本次交互版本已经重新跑完真实触屏流程。

独立代码复审通过：

- 默认仍按原距离与观察惩罚选组；仅默认组全部禁用时，才寻找包含可用非 `observe/discover` 实质动作的替代组。远处可选观察不会抢走脚下机关的失败原因。
- 合并同一 1.65 范围内的各组选择，首选组在前，多项打开既有菜单。保留禁用原因、组内顺序及其它可用目标，解决单项伙伴互动遮住观察或终点的问题。
- `world.commands()` 已按 ID 去重；一个命令只归属一个目标组。HUD 后续合并亦按 ID 去重，没有重复执行入口；合并前仍经过领域合法范围/角色查询和原物理距离过滤。

- `main._primary()` 与实际 primary 输入处理均按选择数量决定打开菜单，接口一致。1-2 末岸同时靠近花坛和观察时会打开既有菜单，两个合法目标均可达。
- “选择附近操作”的临时问号编码已核对修正。最终专项记录见 `final-interaction-headless/checks.json`；8 套 945 项执行断言通过，运行源摘要稳定。此处没有重复运行测试，也未修改运行代码。
