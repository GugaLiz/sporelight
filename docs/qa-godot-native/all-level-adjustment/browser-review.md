# 浏览器验收记录

本记录将状态恢复截图、实际输入通关和人工画面判断分开。浏览器全部使用独立 Chromium context，不读取或覆盖用户旅程。内置浏览器执行工具不可用，已按 browser skill 排障要求检查后使用项目 Playwright 工具。

## 基线

- `root-weaving-playtest` 构建使用正式入口 `?qa=1`，没有 `playtest` 参数；源码摘要 `b2786fabf6dd9982a0af42d776c6e8494be48e45c55e39a4ba1fda6de171f802`。
- 15 关 × 1280×720 / 844×390 × 4 个状态，共 120 张 GPU 截图；支撑、接地、HUD 可见性检查通过。初态、机关中间态、完成前、恢复已完成状态来自已有 fixture；这些截图不是通过实际输入通关的证明。
- 当前 1-1 花坛位于 `f:3:-2`，完成前/后截图明确采用当前花坛姿态，不改写旧 fixture。
- 人工发现：正式 1-2 中央方砖底座容易误读为通路；1-3 以后花坛偏小、部分装饰占据通行中心；2-3 编排台缺少动作顺序信息；未接收光线伸到远处空背景。
- 2-4 在授粉前不生成远岸属于既有玩法规则，不作为渲染缺陷修改。

## 输入测试工具修订

- `check-native-browser.py` 增加加载遮罩消失等待、`--touch` 真实触屏动作选择与机制结果核对；`--mechanism-command` 可选定已有动作采集动画中段。
- 触屏第一次冒烟误把单动作动画提交前的短暂状态当成弹出菜单，造成找不到按钮；实际动作已成功执行。测试改为等待动作稳定后判断，1-3、2-3 在旧构建上的完整触屏按钮路线均通过。失败与修正结果保留于 `input-harness-smoke/`、`input-harness-smoke-fixed/`。
- 手机尺寸的离屏路径必要时仍由真实方向键遍历，不能宣称全程仅触屏或已做真机验证。
- 1-1 常规 authored fixture 的旧终点不适用于当前验收；真实浏览器使用现有 `first-garden` 模式，覆盖当前终点、主路与南侧探索、回收、撤销及重载。
- 首关手机的 optional 探索曾误触南向生长按钮：目的地 `f:-1:0` 的投影中心落入实际 23px 的「+」热区，先生成南桥再转入走路 fallback，直到下一次显式生长才暴露。仅等待镜头稳定不足以排除 UI 遮挡。最终工具按真实 `growthChoices`/按钮热区预检，留出 2px 余量，记录截图并使用真实方向键走该段；走路前后另核对 growth/turns/water/mode 不变。未修改首关几何或交互。两次失败证据保留，成功复测单列 `accepted-first-garden-touch-safe-target/`。

## 性能诊断与限制

`performance-comparison/` 在 1280×720、3-4 初态，以旧版/样式版/样式版/旧版顺序串行采样。使用既有 `--level=3-4` 启动参数，不启用 QA 发布，不改玩家存档。四轮 rAF 中位间隔约 31.16–31.24ms，P95 约 31.60–31.63ms，没有观察到这批场景改动带来的明显回退。它是当前主机无头 Chrome 的短时浏览器节奏对照，不是 GPU 耗时、60fps 或真机性能认证。真实输入测试中的 QA 发布开销不能直接当作正常游戏帧率。

手机尺寸采用浏览器触屏模拟；菜单工具在必要时可用滚轮显示可见控件，首关明确保留键盘辅助段。因此只报告已记录的真实输入及覆盖，不宣称纯触屏真机全流程认证。
