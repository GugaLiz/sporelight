## GPU反馈后的核心状态与空间修正

实际查看候选`3-4/arrival.png`、`3-4/restored.png`与`1-3/restored.png`，确认巨核心遮住主角、完成后核心缩小/几乎消失，以及整花床淡出产生人物/花坛重影。对照原站`reference-stroll/1280x720/3-4/final-canvas.png`，不能沿用此前CPU通过来关闭问题。

**末关尺寸突变原因**：3-4完成回程根路会再次添加`f:-4:0`；`GardenWorld.tiles()`在坐标去重时优先保留被占用的记录。角色恰站核心格时，原固定地块因此被标成`kind=root`。此前底座检查排除root，将真实原固定核心台面拒绝，最终回退宽.9。修正检查原`level.tiles`及sanctuary中的固定身份、当前位置/高度和实际surface，不再因重复记录的kind而缩小核心；生成的根路仍不会被当作额外固定支撑。

布局候选现在按真实台面上远离镜头的方向排序，并始终不依赖当前角色位置或completed字段，防止行走/开花导致花床追着人移动。完整源图、原尺寸和脚锚不变；`IntegratedGardenProps`添加`core_planter`、画布宽与底座范围metadata供stage辨认核心，未在helper关闭深度或添加透明遮挡特例。stage整体淡出处理归主任务。

**3-4空间冲突不能掩盖**：源宽3.03046对应完整底座约2.09×2.09，所在岛是3×3，保持全支撑时只允许中心偏移约±.4。原初始主角位于岛中央核心格，完整2.09方底座无论如何摆放都覆盖这个中心；仅移动完整核心无法保证角色胶囊与底座占地分离。需要明确选择保留源比例且接受真实遮挡/重新规划站位，或采用较小完整源图作为明确比例例外。不能用全图淡出、关深度或假台面假称矛盾消失。较小候选1.7、偏移(-.85,0,-.85)只作为待验证备选，不自动启用；它保持完整图片，但不保持原150px/70px比例。所有候选仍需GPU与现有装饰相互遮挡检查。
