# 原版池塘环境层：实现与 CPU 验收

日期：2026-11-11。原版来源为已核对线上 JS/CSS 哈希的 `landscape.ts` / `pondWeather.ts`，复用 Godot 已移植的 `GardenEnvironment.build_pond_geometry` 和 `residents`。本报告仅覆盖独立池塘环境层，不代替最终 GPU 画面、路径或性能验收。

当前源资产比例与逐实例账本见 [final-source-inventory.md](final-source-inventory.md)，其末表单列池塘生态，避免把岸边PNG、睡莲、芦苇、青蛙误计进104条地面装饰。canvas/70与alpha可见宽/70分开记录，均是源码/PNG解析值，本补充没有重新执行人工屏幕像素测量。

## 接口与集成

新增 `godot/presentation/native/original_pond_environment.gd`，类型 `OriginalPondEnvironment extends Node3D`。由舞台创建一次并挂在场景根下，独立于会因道具状态重建的 `_props`。

- `refresh(stage)`：在关卡或实际 tiles 集合变化时创建/替换环境；相同内容保留节点和 mesh。非 pond 关隐藏本节点。
- `update(stage)`：读取 `stage._garden_effects.water.global_position.y`，只更新环境根 Y、缓存水面 shader 的时间和青蛙姿态/眨眼纹理。没有逐帧造网格、搜岸线、扫描 PNG 或 SVG 栅格化。
- 必须在 `fx.refresh/update` 后调用环境对应接口，以使用当帧实际水高。旧 `GardenWater` 保留为 **隐藏的 PlaneMesh 载体**，供现有水高和天气 `mesh.size` 接口使用；不要将环境 ArrayMesh 直接赋给 `fx.water`，也不要同时绘制旧矩形。
- 四个 pond 关都应有载体。缺少载体时模块只提供原版水高兜底：2-1 `(-.55+water*.18)*.65`，其他 `-.5*.65`；最终以实际载体为准。

本模块没有 CollisionObject、CollisionShape、规则地块、可走支持面或机制交互节点，不改变存档和玩法。

## 已恢复的内容

1. 取原 `pondBank` 点、原 sin/cos 扰动，每段 6 个平滑采样，再从 70×35 px 等距投影反算真实 X/Z，三角化为 **不规则水面**。2-1 / 2-2 / 2-3 / 2-4 分别为 288 / 216 / 252 / 216 个水面顶点，没有矩形托盘或竖直包边。
2. 水材质保留原四段色值、water-pigment 0.4 混合、林地倒影 0.055；小幅时钟扰动由同一个缓存 shader 完成。草岸、苔团和两处后岸按原绘制顺序位于水面下，内半边由真实水面遮盖，外侧形成不规则岸缘；浅岸暗线/亮线沿同一轮廓。
3. 岸石、蕨、后侧灌木采用原索引种子；图像宽度为 `原px×√2/70`，使用已量取底脚锚，保留完整原 PNG。两处后岸灌木分别为 bush 53 px、berry-bush 44 px。
4. 原网格 seed 决定睡莲与四枝芦苇，排除靠近真实地块的位置。睡莲是无碰撞水面贴图网格，并裁切在有机水面内，不能因中心在水中就让叶边悬空。芦苇使用原曲线、21/33 px 茎长、5 px 顶穗与原色的缓存 SVG 纹理。
5. 青蛙保持原候选数量 2/2/1/2，每只都有完整 44×21 px 叶座；身体、双腿、眼丘、眨眼与小叶采用原矢量元素的缓存 SVG。开眼/闭眼两张纹理在 refresh 阶段预热，update 仅切换引用和轻微浮动。这里恢复的是矢量轮廓和尺寸，不声称与 Canvas 柔光渐变逐像素相同。

## 与原坐标的必要差异

原 `residents` 只检查附近地块与机关扫掠区，没有检查其自身水面轮廓。2-1 第二候选 `(6.6,4.8)` 实际在原有机水面之外，不能在 3D 中让叶座和青蛙悬空。因此保持数量和图像尺度，在原水面内找最近可容纳完整叶座、避开地块和机关的水袋，记录在实例 metadata：

- 2-1 第一只：`(-6.7,4.9) → (-6.55,4.9)`，完整叶座内收 0.15 格。
- 2-1 第二只：`(6.6,4.8) → (5.53934,3.73934)`，移到真实水面内；没有扩造水面或物理支持。
- 2-3 第一只：`(-6.7,1.9) → (-6.55,1.9)`，完整叶座内收 0.15 格。
- 2-2 与 2-4 青蛙位置保持原坐标。

源点和实际点完整记录在 [native-pond-headless.json](native-pond-headless.json)。水位和授粉导致实际 tiles 变化时，环境重新计算近岸排除区一次；水高动画本身只平移缓存根节点。

## 定向验证

新增 `godot/tests/native_original_pond_test.gd`，使用无渲染舞台 fixture、真实 GardenWorld 和纹理资源运行。命令：Godot 4.7.2 `--headless --path godot --script res://tests/native_original_pond_test.gd`。

结果：**686 项，0 失败**。覆盖四关源岸线/装饰/青蛙数量、非矩形三角水面、完整叶座在水内、原图比例、无碰撞与规则/存档不变、实际载体高度跟随、重复 refresh 缓存、跨眨眼时刻不生成新纹理/节点、2-1 水位及 2-4 授粉来回后仅按实际地块变化重建一次。

后续C08连续闭合miter岸线、全生态缓存 `presentation_bounds()` 及接缝验证已把同一测试扩展为 **28,534项、0失败**，完整证据记录在 [池塘返岸与岸线回归](pond-transition-and-shore-regression.md)；686是本模块初次完成时的历史数量，不是当前最新检查数。原17/10/1.5px岸线宽度保持，最终GPU视觉状态仍由集成验收记录。

尚待集成者完成：舞台接入后的 GPU 画面（特别是草岸遮挡、青蛙/叶座接触、水面透明排序、全景镜头覆盖）以及正式包帧时和路径回归。CPU 检查不构成这些项目的通过证据。
