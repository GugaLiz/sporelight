# 1-4 花门、喷泉与 1-4 / 3-4 鼹鼠补充恢复

2026-11-11。此批为原站元素恢复后的定向补充，不覆盖此前 106422 项证据，也不将 CPU 结果写成 GPU 验收通过。

## 来源与实现

- `src/app/garden2/render.ts`：门框、门封均使用完整画布宽 112 px；喷泉调用尺寸 92；鼹鼠调用尺寸 58，逻辑偏移为 `(-1,+.3)`。
- `src/app/garden2/gardenArt.ts`：喷泉按 `92/90` 缩放，主盆半径 43、上盆半径 19；两条二次曲线射流、7 水滴、3 波纹；苔叶、花瓣、真实 stone 纹理保留。
- `godot/presentation/native/original_sanctuary_dressing.gd`：整图注册、原站比例换算、真实支撑和显式例外。喷泉 SVG 在 CPU 一次生成 416×384 纹理，暖帧不扫描像素。
- `original_fountain_effect.gdshader` 与 `native_garden_atmosphere.gd`：两条连续射流各 18 段，原控制点与水滴轨迹；波纹以源顺序遮挡柱座。保持正常深度测试，使用已有时钟、暂停、减少动态、粒子设置；没有复制第二套射流。
- stage 仅新增 helper preload，并替换 `_add_sanctuary`、`_add_mole` 的内部绘制。全景边界由主任务新增的实际 Sprite 轮廓联合计算覆盖，普通相机密度未在本批调整。

门封与框使用相同脚锚、像素尺度及位置，不将门封自身透明图的下缘另行贴地。`home` 后门封移除，撤销恢复。两项比例例外已写入节点元数据，未声称原尺寸完全等比还原。

喷泉的原位置 `f:-9:-2` 在规则中一直为 `solid`。该标志表示不可走，并不表示它没有真正实体台面；其自身固定地板是合法建筑支撑。最终仍在这个原阻挡格内，只平移 `(+.05,+.05)`，高度不变。因此没有在别处放喷泉、却留下原处隐形阻挡的问题。花门 `f:-6:0` 的 `solid` 随 `home` 变化，逻辑、碰撞、存档与核心 `(1.2,0,-.7)` 显示偏移都未改变。

喷泉曾考虑上层落点；最终未采用，也没有保留跨高差迁移。此前宽门与喷泉方案误用交互原点检查核心避让，后改为读取真实 `ground_footprint_center/span`，检出了交叉。失败记录保留在 [native-sanctuary-layout-before-fix.json](native-sanctuary-layout-before-fix.json)，最终方案不使用该失败布局。

3-4 鼹鼠曾试前左 `(-4.1,1.05)`，但其完整脚部与核心实际底座仍相交约 .07；最终未采用。当前前右落点的脚部 x 区间为 `[-3.325,-2.515]`，在核心实际右边界约 `-3.355` 之外；使用完整方形包络验证，另以真实角色胶囊验证完成站位分离，不能以脚中心不重合替代这些检查。
