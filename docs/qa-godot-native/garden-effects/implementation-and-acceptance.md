# 原生动态效果补全与验收

## 对照来源与范围

对照本仓库 `src/app/garden2/render.ts`、`landscape.ts`、`pondWeather.ts`、`gardenArt.ts`。效果只读取世界状态，不能改变可达性、碰撞、通关条件、角色位置或存档。既有 RuleRay 光线、机关供水、水滴与环境微粒继续复用。

| 效果 | 实现与边界 |
| --- | --- |
| 孢子 | 原资源、轻微悬浮、脚下光环、少量闪光；跟随实际支撑面变换；拾取消失并短暂散开；撤销恢复 |
| 地表落水 | 按原版最高、最右、南边外露且无机关标记的固定地块选取唯一源点；不从移动庭院、根桥、升降台造水；洞窟不添加 |
| 水面 | 原有真实水体覆盖范围；水位随阀门交易平滑插值；无水体处的地表落水终点为薄雾，不新增池塘 |
| 雨 | 仅池塘章节；前景、背景有真实深度分离；真实池面上单点下落、同点扩散水环，避开已占据地格 |
| 湿铺装 | 仅池塘章节按原版铺装种类、位置种子选点，锚定可见地面；移动地块随支撑面移动 |
| 圣所 | 仅原有圣所；两股弧线喷流、七颗水滴、三道盆面水环；四只蝴蝶在圣所花丛间停歇、飞行 |
| 核心花床 | 调用原有 ready 判定；仅可修复或已完成时发光，未复制关卡通关条件 |
| 完成反馈 | 已完成状态且开启粒子、非低动态时显示十六颗上升金色微粒 |

`particles` 控制雨、拾取粒子、蝴蝶、喷泉水滴与完成微粒。`dynamicLight` 控制孢子光环和核心光晕。`lowMotion` 冻结水面、涟漪、孢子与蝴蝶姿态并关闭移动粒子。暂停使用 stage 的同一视觉时钟；不使用 shader 内置 TIME。所有透明效果保留真实深度测试，无碰撞体。

## 缓存约束

`native_garden_effects.gd` 和 `native_garden_atmosphere.gd` 在刷新世界时建立材质、网格、源点、支撑面引用。动画帧只更新变换、可见性、shader 参数；不查询整板、不创建资源。拾取粒子只在拾取事件创建，生命周期结束销毁。

`ready(world_tiles = [])` 新参数只将已有板传给 together，原无参调用和判定保持一致。平台到达终点后的渲染刷新复用交易开始缓存的精确 destination board；插值用缺失端点别名不纳入该板。

## 首轮 GPU 截图发现及修正

离线检查主 agent 的 `visual-restoration/full-gpu/1280x720` 截图，确认并修复：

- 雨丝斜向拉长：相机 billboard 非均匀缩放使用了世界轴 `Basis.scaled`，改为 `scaled_local`。新增断言确保雨丝两个平面轴与相机轴一致。
- 天空边缘孤立水环：雨落点限制在真实池面中央 60%（避开羽化边缘），并要求距真实地块 1.3–2.8 单位。
- 无池塘瀑布末端硬圈：实际 water 不存在时环强度为 0，仅薄雾；存在时使用 0.25 的浅纹，落雨撞击环减至 0.35。

修正后 headless 专项 2113 项通过，GPU 最终效果仍由主 agent 重导出后检查。

## 性能风险与浏览器入口

暖帧不查询整板或创建网格/材质，但 76 个独立雨片仍产生透明绘制提交；共享资源不等于保证合批。池塘约有 100–140 个额外透明提交，圣所包含 36 段喷流、7 颗水滴、8 片蝶翼，应实测低端 WebGL 的提交和透明叠加成本。若最终预算不满足，可将前/后两组雨改为 MultiMesh；本次冻结时未额外重构。

`tools/godot-migration/check-art-restoration-browser.py --url <URL> --output <directory>`：隔离上下文，真实鼠标/键盘验证锁定预览禁止进入、章节返回、地图入关及计数；桌面额外验证孢子区域帧差、暂停不变、真实移动拾取和 Z 撤销。只用公开 QA bridge；仅拾取前置使用 snapshot。截图与帧差供视觉复核，不把动态区域差异视为美术质量证明。脚本已通过 Python 编译检查，子 agent 未运行浏览器。
