## 2. 比例和恢复边界

- 主线源格投影 70×35 px，完整画布宽 P 对应 `P×√2/70` world；再按 PNG 实体 alpha 轮廓判断可见宽。云庭单独用 58×29 px 和 `√2/58`，不可共用主线系数。
- 1-1 保留已认可的专用比例与位置。1-2 保留 revision 2 的安全映射和核心例外；普通主线核心源宽 110 px、3-4 源宽 150 px，不能强行等大。
- 原站“身体旁叶包中的缩略携带物”已由 `original_carry_art.gd` 表达。地面实体、固定底座、叶包图示分别核对，不把小图示再放大到整个镜体。
- 硬基座与花叶分开：石灯/岩石/晶体/镜座/建筑底座不可进入；叶冠正常部分遮挡不是整株硬墙。候选碰撞仍需证明点击绕行、伙伴跟随、实际操作站位和所有合法道路成立。
- 不以新增装饰数量代替丰富度；已恢复的每件物体首先要看得见、落在真实支撑上、没有永久遮住两位角色或操作主体。未找到原站来源的新对象不得标为“恢复”。

## 5. 代码复核发现与后续证据

初次读取时 `native_prop_obstacles.gd` 已在机制分工中扩展为除 1-1 外的 14 关，并包括硬装饰、机制实体基座和云庭建筑。此处仅确认实现范围，**并未确认所有新基座通过路径回归或画面验收**。初读时主线 arch/lotus-pool 遗漏候选已发给机制负责人；后续实现已增加 1-3 拱门、1-4/2-3 门闩两柱及 2-1/2-2/2-3 莲池石盆，独立柱脚保持门洞。机制 agent 的 audit03 记录 425 项 CPU 检查通过，完整路径和最终 GPU 仍以整合批次为准。

本轮新视觉证据待整合版本提供。最少要有桌面 1280×720 与小横屏 844×390 的实际原图，以及相同源码下的：初始/默认操作/关键中间态/完成态、未解阻断、合法往返、撤销恢复。新加硬碰撞必须包含连续顶向硬基座、点击绕行、伙伴跟随与旧非法脚点恢复。图像来源准备状态与实际输入分开标注；动态效果需有不同时间帧和暂停冻结证据。

历史 72/74/75 的通过仅覆盖各自源码。新问题或新共享代码出现后不可凭旧报告直接关闭；最终结果由独立原图复核记录补充。
