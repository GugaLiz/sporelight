## 1. 是否需要调整

需要，但现有离散规则、逐格移动、单人换手和稳定快照很适合跨端复用。优先保留 GardenWorld、内容和规则测试，建立平台适配层；没有必要仅因支持手机和 PC 就重写全部玩法。

已有基础：键盘/鼠标点选、44px 方向按钮、小屏与矮屏 CSS、跟随/全景镜头、DPR 上限、减少动态、隐藏页面暂停模拟、音频手势激活、本地续玩和错误提示。

缺口：Android/iOS/桌面外壳、平台存储、系统返回、音频中断、窗口失焦、系统安全区、手柄、真机性能/内存/耗电、签名/安装/更新流水线。

## 2. 技术路线决策

| 路线 | 适配价值 | 成本与限制 | 建议 |
| --- | --- | --- | --- |
| Web + Capacitor | 复用 TS/DOM/Canvas，接入 Android/iOS 原生能力 | WebView、存档、安全区、插件与生命周期仍需验证 | 移动端优先做样板 |
| Web + Electron | 内嵌 Chromium/Node，桌面渲染环境相对一致 | 壳体积/内存增加，需持续更新运行时和限制权限 | PC 优先做样板 |
| Web + Tauri | 系统 WebView，适合重视包体和系统集成的团队 | 多 OS 的 WebView 引擎不同，增加兼容测试；引入 Rust 工具链 | 与 Electron 实测比较，最终二选一 |
| Web/PWA | 继续浏览器分发、试玩与快速迭代 | 需额外离线缓存/版本更新设计，平台集成和发行渠道有差异 | 保留 Web；PWA 按分发需求投入 |
| 规则保留，换 WebGL 渲染 | 可能解决经实测确认的 Canvas 绘制瓶颈 | 需重做渲染、资源组织、遮挡/命中一致性 | Canvas 优化不达标时做单关实验 |
| 迁移 Godot/Unity 等 | 更适合明确的 3D、复杂物理、引擎编辑器驱动生产需求 | TS、DOM、渲染、测试与工具链迁移成本显著 | 触发条件成立再立项，不能承诺无损直接导入 |

官方依据：[Capacitor](https://capacitorjs.com/docs)、[Electron](https://www.electronjs.org/docs/latest/)、[Tauri 的系统 WebView 差异](https://v2.tauri.app/reference/webview-versions/)、[Godot 平台能力](https://godotengine.org/features/)。这些来源证明工具能力，不证明本项目性能一定达标。

### 2.1 如何做出最终选择

先用 1-4、2-2、3-3、3-4 建立负载样本，第一版封装至少包含最复杂的 3-4 和完整菜单/设置/存档流程。比较：

1. 最低目标设备上的帧时间、输入反馈、解码内存和 20 分钟发热。
2. 同设备的冷启动、安装体积、关卡切换、后台恢复和离线稳定性。
3. 存档/音频/手柄/系统返回等必要平台能力能否可靠实现。
4. 团队维护成本：是否熟悉原生工具链、能否持续升级运行时。
5. 新关卡制作效率：瓶颈来自规则硬编码还是渲染能力，不能混为一谈。

若资源裁剪、缓存与停绘后达到预算，继续当前栈；若主要瓶颈仍是渲染，先单独替换渲染层；若产品明确转向另一类游戏或编辑器工作流成为主要瓶颈，再比较完整引擎迁移。

## 3. 共享核心与平台服务

```text
内容 + 规则 + 存档 schema
          ↓
GameSession / CommandDispatcher / ProgressStore
          ↓
Canvas 与 UI / 音频 / 提示与动画
          ↓
PlatformServices
  Input / Storage / Lifecycle / Viewport
  Haptics / FileExport / Fullscreen / Diagnostics
          ↓
Web 实现 | Android/iOS 实现 | Desktop 实现
```

| 服务 | Web | 移动容器 | 桌面容器 |
| --- | --- | --- | --- |
| 存档 | IndexedDB 等事务存储；兼容旧 localStorage 迁移 | 设置使用轻量原生键值；关卡档使用文件或数据库 | 用户数据目录文件/数据库 |
| 生命周期 | visibility、focus/blur、pagehide | App 前后台、返回键、系统回收/音频中断 | 窗口失焦、最小化、关闭、更新重启 |
| 输入 | Pointer/Keyboard/Gamepad | 真触屏、系统手势、外接输入 | 键鼠、手柄、焦点导航 |
| 视口 | CSS 可视区域、dvh、缩放 | 安全区、方向、软键盘、系统栏 | 窗口尺寸、DPI、全屏、显示器切换 |
| 反馈/导出 | 能力检测、浏览器下载 | 原生震动、文件/分享能力 | 文件保存、截图、可选手柄震动 |

原生权限只暴露明确的方法，核心规则不直接调用平台 SDK。Electron 使用隔离的渲染环境、窄 IPC 接口和 sandbox/contextIsolation 等安全配置；参考 [官方安全指南](https://github.com/electron/electron/blob/main/docs/tutorial/security.md)。

## 4. 移动端交互与布局

### 4.1 横竖屏策略

建议以横屏为完整空间阅读体验，竖屏保持可完成所有核心流程。现有项目已经支持两种方向，不建议未经试玩直接撤销竖屏支持。

- 横屏：地图与上下文操作区并列，底部保留移动/互动/换手，提示避开主要目标。
- 竖屏：角色跟随镜头，顶部简短目标，下方可收起的上下文面板，常用操作控制在 3–4 个，其余折叠。
- 全景：用于理解连接关系；操作后可回到跟随，不在全景强迫点击过小石板。
- 平板/折叠：按可用宽度布置，不只按设备类型；展开、旋转、分屏不能重建关卡状态。

### 4.2 安全区与文字

源码证据：`index.html:6` 没有 viewport-fit；`base.css` shell/stage 使用 100vh；没有统一 safe-area-inset 处理；`garden2.css` 多处固定 top/bottom、小屏 9–11px 文本。具体遮挡尚待真机复现。

实施：统一可视高度与 inset 变量，提供 100vh fallback + 100dvh；在容器允许全屏内容后配置 viewport-fit，并让关键 UI 避开刘海、挖孔、Home Indicator 和 Android 系统手势区。Canvas 背景可延伸到边缘，操作区应安全。

为正文、提示、按钮分别设最小可读字号和用户缩放策略，不将整页缩小当作响应式方案。先验证中文与英文长度变化，再扩展语言。命名页还需要软键盘遮挡、提交焦点和超长输入测试。

### 4.3 输入

- 推荐点击地块自动寻路，方向按钮作为精确控制；保留逐格默认，长按连续行走可做可选设置。
- 普通地块热区当前高 `35*scale`（GardenGame.ts:98），不保证全部达到 44px；将可点击范围与美术形状分开，拥挤时用邻近选择或上下文互动。
- 采用统一 Move/Interact/SwitchActor/Undo/Hint/Pause 命令；避免触摸与兼容鼠标事件重复提交。
- 操作影响预览必须支持触摸；悬停只作为 PC 增强，不能成为了解规则的唯一方式。
- 支持左右手布局或按钮位置预设；长按需处理 pointercancel、弹窗、失焦和旋转。
- 当前屏幕上的“E/T”提示需按输入设备变化；外接键盘/手柄时实时切换。

## 5. PC 体验与发行

### 5.1 必要桌面体验

键盘和鼠标各自能完成开始、设置、选关、游玩、提示、撤销、通关、重玩、退出；手柄若作为首发卖点，菜单和弹窗也必须完整可导航，不能只让角色能移动。

增加键位重映射、控制器连接/断开处理、焦点环和设备提示；区分窗口全屏、最大化与浏览器 Fullscreen API。测试 16:9、16:10、超宽窗口、4K 和 125%/150%/200% DPI，场景按可用空间布局，不简单放大 1280×720。

失焦暂停作为可配置行为；切回时清空持续输入，防止粘键。窗口尺寸与 UI 缩放单独保存；不要让存档里的 fullscreen 布尔值替代系统实际窗口状态。

### 5.2 平台范围分批

建议先 Android + Windows 验证；iOS 若属于首发范围，必须从样板期并行纳入 WebKit 真机，不能等最终阶段才接入。macOS/Linux 根据发行承诺和设备/构建资源推进，不能用 Windows 通过推定其通过。

iOS 需要 macOS/Xcode 构建环境、设备和签名配置；当前 Windows 工作区不能替代该验收。[Capacitor 环境要求](https://capacitorjs.com/docs/getting-started/environment-setup)。

Steam 等渠道的成就、云存档、覆盖层、控制器适配属于后续渠道任务，不是当前已具备功能。是否接入由实际首发渠道决定，无须提前搭建账号服务器。

## 6. 生命周期、音频与保存

当前 `createApp.ts:243` 有 Web visibilitychange；GardenGame 暂停只停止模拟，仍继续绘制。需要统一暂停原因集合，避免关闭设置时意外解除后台/失焦的暂停。

| 场景 | 预期行为 |
| --- | --- |
| 设置弹窗 | 停止推进、保持焦点、保存有效状态；已完成漫游也能调设置 |
| 动画中后台 | 保留上一个已提交稳定状态；恢复后继续或取消动画，规则与画面一致 |
| Android 返回 | 先关弹窗，再暂停/上级页面，最外层才退出 |
| 系统终止 | 恢复最近已持久化的合法状态；不能只靠退出事件保存 |
| 音频中断 | 独立处理 AudioContext 与平台音频状态，恢复不叠音、不重复建播放器 |
| 低电/低性能 | 使用经验证的画质档或限帧，向用户提供清楚选择 |
| 桌面最小化 | 停止不必要绘制和热区生成，恢复后重置帧时钟 |

[Capacitor App](https://capacitorjs.com/docs/apis/app) 提供前后台及 Android 返回事件；平台接口仍需由应用规定导航和提交语义。

移动长期存档不要只依赖 localStorage。官方说明其可能被系统清理，Preferences 适合轻量键值，大量/高频数据应考虑数据库：[Capacitor Preferences](https://capacitorjs.com/docs/apis/preferences)。

每次有效动作即排队保存，关键节点立即 flush，保留最后有效备份。跨设备同步属于独立功能：先有统一 schema、冲突规则和导入导出，再评估云服务。离线首发无需强制登录。

## 7. 资源与性能预算

当前构建成功，JS gzip 80.55 kB、CSS gzip 26.72 kB；真正突出的发行规模是全部 publicDir 素材约 89 MiB。Vite publicDir 的整体复制行为见 [官方资源说明](https://vite.dev/guide/assets)。

先完成运行时资源 manifest，移动原图/历史备份到制作目录并更新加工脚本。不能只按源码字符串 grep 就删除资源，因为存在动态拼接和 CSS 引用。应结合构建引用、场景清单和完整游玩请求记录确认。

| 项目 | 拟定预算/门槛 | 测量方式 |
| --- | --- | --- |
| 主流设备 | 目标 60fps，p95 帧间隔约 16.7ms 级 | 复杂关卡连续采样，记录抖动/长帧，结合 CPU/GPU 时间 |
| 最低设备 | 稳定 30fps 档，p95 约 33.3ms 级 | 同场景、同画质、同操作序列 |
| 输入反馈 | 可见反馈目标 <100ms | 从触摸/按键到首个反馈帧，不要求整个动画 100ms 内结束 |
| 本地冷启动 | 目标设备可操作 ≤3 秒 | release 包无网络依赖，排除安装时间 |
| 关卡切换 | 缓存命中目标 ≤1 秒 | 关键资源就绪、可操作为终点 |
| 内存 | 连续 20 分钟及进出关卡 30 次，无无法回收的持续增长 | 记录 JS heap、WebView/进程内存与图片解码；基线后锁定数值上限 |
| 功耗/发热 | 暂停/后台显著降负载，连续游玩不因热节流长期失守帧预算 | 真机采样，记录设备/电量/环境/画质 |
| 包体 | 去除确认不必要资源，建立每次构建增量报告 | 基线 89.33 MiB Web 目录，原生壳另计；优化后再定绝对上限 |
| 离线 | 已安装包首启与重启断网仍可完成主线 | 网络禁用，检查所有必要资源本地可用 |

以上是讨论起点，不是本次实测成绩。正式门槛由首轮最低设备样板校准，不以理论值替代可玩性判断。

## 8. 无障碍与本地化

保留现有 aria-label、状态播报、减少动态和焦点处理。补充地图的语义导航：避免让数十个无区别的“走到这块石板”成为键盘/读屏唯一入口；提供目标/机关列表与方向描述。

颜色之外使用线形、图标和标签区分水/光/记忆影路；静音可完整解谜；系统低动态偏好可作为初始值，用户可覆盖。文字抽取到资源表，Canvas 文本也纳入本地化，国际化不是给 Language 类型增加枚举即可。

## 9. 发布验收矩阵

| 维度 | 必测范围 | 通过条件 |
| --- | --- | --- |
| Android | 最低目标 + 主流机，手势/三键导航、横竖屏 | 控件不遮挡、触摸真实有效、返回层级正确 |
| iOS | 小屏 + 刘海/灵动岛类屏幕、系统键盘、锁屏 | WebKit 渲染/音频/文件/生命周期通过 |
| 大屏 | 平板、折叠展开、分屏 | 进度不重置，地图与面板布局合理 |
| PC | 承诺支持的每个 OS、窗口/DPI/全屏 | 安装、启动、操作、退出、更新均通过 |
| 输入 | 键鼠、真实触摸、手柄（若承诺） | 无死角，无串输入；弹窗焦点可退出 |
| 存档 | 旧版、损坏、空间不足、部分失败、更新、强杀 | 不静默覆盖有效档；错误可知，备份可恢复 |
| 生命周期 | 后台 30 秒/5 分钟、来电、音频切换、系统终止 | 稳定恢复；不重复提交，不叠音 |
| 内容 | 12 主线 + 3 样章、结算/图鉴/纪事/回看 | 规则与进度一致，旧档差异明确 |
| 包与更新 | 签名 release、覆盖安装、版本升级、资源缺失 | 资源/代码版本一致，存档保留，失败可恢复 |

现有 `check-garden2-mobile.mjs:5` 是固定 390×844 的 Chromium viewport，未配置 isMobile/hasTouch，使用 click。它是有价值的布局/UI 回归，不能当作真实移动触摸、iOS 或原生包验收。
