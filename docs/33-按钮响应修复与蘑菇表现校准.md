# 按钮响应修复与蘑菇表现校准

日期：2026-11-06。

后续“回到花园”问题及扩大功能复核见[返回花园与全功能复核](34-返回花园与全功能复核.md)；本页历史结果和覆盖边界保留。

用户反馈移动轨迹已有改善，但蘑菇外观仍显得奇怪，并明确要求先验证全部按钮，再继续处理造型。本次按这个顺序执行：先修复并验证按钮响应、命令与界面覆盖，再实施首关的伙伴2D合成、独立地面影子、水平朝向与共面微深度偏移。原人物素材、移动路径和解谜规则保留。

本文是阶段记录。已知结果与正在执行的最终矩阵分别列出，不能把单个pilot通过写成整体验收结束。

## 1. 按钮原有问题

旧运行源码`53056130…`的基线检查共10例：7例通过、2例失败、1例没有形成有效覆盖。两个真实问题集中在动画中的方向输入和跨动作提交的按钮按下：当前动作完成前，新选择可能被忙碌状态丢弃；HUD在状态同步时重建按钮节点，也可能让按下与抬起不再落在同一个按钮上。

因此“画出了按钮”“触发过pressed”或“静止时能点一次”都不足以证明按钮在正常游玩中可用。还必须覆盖动画中、提交边界、最新选择覆盖旧选择、暂停/失焦/切关和设置导入等生命周期。

## 2. 当前响应合同与修复

| 范围 | 实施合同 | 防止的问题 |
| --- | --- | --- |
| 动画中的规则动作 | 保存最新一次按钮意图，当前合法动作提交后重新解析并验证；队列不直接保存旧状态下准备好的规则事务 | 点击被吞、旧动作在错误地图状态执行 |
| 长动作中的方向按钮 | 明确点击的方向存入`pending_button`并等待当前动作合法提交；键盘轻点仍使用原160ms短缓冲 | 在0.78秒生长动作早期点击方向后，选择被键盘缓冲的到期机制丢弃 |
| 最新选择 | 新的明确按钮或方向选择覆盖等待中的旧意图，并清理冲突的自动路线/输入 | 旧点击在用户改主意后仍继续执行 |
| 重复生长/动作 | 当前动作与重复请求相同时只反馈正在完成，不追加同一动作；重复grow不能在状态改变后被重解释为回收 | 双击播种造成长出又收回 |
| 暂停、失焦、切关 | 清除等待动作及输入，恢复后不重放暂停前残留意图 | 回到游戏后自行移动或互动 |
| hint、mode等非规则显示命令 | 可直接响应，不等待规则动画提交；不把显示设置当作地图事务 | 玩家感觉提示或模式按钮完全无响应 |
| HUD按钮身份 | 以稳定`command_id`复用现有节点，只更新文案/状态；移除真正消失的命令 | 按下期间节点被重建，抬起事件失去目标 |
| 同消息反馈 | 同一条反馈再次发生仍更新显示，不因字符串相同而吞掉回应 | 连点或重复无效操作看起来毫无响应 |
| 首次从地图打开设置 | 使用真实当前设置初始化界面，保存时merge变更 | 设置页默认数据覆盖实际用户配置 |
| 导入后的设置应用 | `_apply_settings()`统一更新continuousInput、safeCamera、画面与音频；应用导入数据不再调用写盘型设置保存 | 导入后镜头/输入仍旧，或立即覆写导入进度 |
| 桌面全景按钮 | 已经展示整园时禁用并给出说明；小屏跟随场景才允许切换 | 没有实际画面变化却表现成一个“坏按钮” |

这些调整不新增解法，不修改种子预算、连接、互动距离或人物轨迹。规则动作依旧经过现有命令准备、合法提交和状态更新；显示命令直接响应也不意味着允许它绕过暂停、锁定等应用状态。

## 3. 自动化验证方法及失败记录

浏览器验证使用真实鼠标/触摸事件点击实际HUD与叠层，读取实际按钮节点和命令身份；不以直接调用规则方法替代按钮验证。当前脚本还增加以下约束：

- 通过新的`qaSequence`确认获得本次请求之后的状态，避免拿上一帧QA数据定位按钮。
- 滚动依据按钮真实祖先ScrollContainer的可见矩形，重新获取实际坐标，不能对错误容器发送wheel后假设按钮已进入视口。
- 输入后回读文本内容，确认输入确实到达Godot控件，再继续确认或导入。
- 自动导入样本使用ASCII形式的Unicode escape JSON，并验证解析后的值与预期Unicode文本等价，避免自动化键入通道本身丢失中文被误判成产品数据错误。
- 长生长动作的新增用例记录真实DOM `pointerdown`的可信标记、命中控件、`moving`、`revision`和动作时间；方向点击必须实际落在原动作提交前，并在浏览器时间及动作时间都经过200ms后仍保持待执行。重复主操作、提示和模式也必须在同一未提交动作内取得实际反馈，迟到的点击不能计为覆盖。

## 5. 浏览器测试的明确边界

已经验证的鼠标/触摸点击和可读回的输入，不代表以下路径已测试：

- 中文IME组合输入；
- 操作系统剪贴板读写与原生粘贴快捷键；
- 原生文件选择窗口及其平台权限；
- 手指拖动形成的触摸滑动/惯性滚动。

ASCII Unicode escape JSON验证的是导入后的实际数据语义，不能代替中文IME、系统剪贴板或文件对话框测试。脚本滚动祖先容器验证的是按钮到达及点击路径，也不能代替真机手势手感。

## 6. 蘑菇表现：已实施的最小修复

### 6.1 首关按逻辑水平移动方向选择朝向

原`GardenView`通过`Iso.raw(last)-Iso.raw(first)`选择朝向，这个差值包含高度。以同一`+X`水平方向为例，旧行为如下：

| 运动 | 旧朝向选择使用的投影差值 | 旧结果 |
| --- | --- | --- |
| 平走 | `(35,17.5)` | 侧面素材 |
| 上一级 | `(35,-30.5)` | 背面素材 |
| 下一级 | `(35,65.5)` | 正面素材 |

这会让上坡、平地和下坡之间突然切换人物视图。本轮已在`GardenView._travel_facing()`给1-1明确使用水平XZ四向：`+X→right`、`-X→left`、`+Z→front`、`-Z→back`；高度不参与视图选择，没有水平位移时保留原朝向。原方向素材及步态clip继续使用，只改变首关选取视角的依据。

其他11关仍执行原`CharacterMotion.facing_for(Iso.raw(last)-Iso.raw(first))`分支。三尺寸路线检查已核对首关相同水平方向在平地与高差边上的一致性，以及其他关卡保留旧朝向的边界；计数和固定场景回归范围见第4.2节。

### 6.2 伙伴原程序绘画先在透明2D视口合成

伙伴由`CreatureArt.buddy()`逐层绘制身体、帽子、纹理、眼睛、腮红等程序图形。原Canvas按顺序合成这些层；此前直接录制成多个原生深度材质片段时，伙伴内部图层也参与深度和透明混合，可能出现脸、帽和身体相互切割。

新增`BuddySurface`使用128×128透明、禁用3D的`SubViewport`，内部仍调用原`CreatureArt.buddy()`，绘制尺寸92。`GardenView`以64设计像素宽度和`112/128`脚轴显示其纹理，形成2倍采样；同一个视口纹理实例跨动作复用，更新姿态时重新绘制，离开首关深度分支后停用视口更新。

身体、帽子和半透明细节先形成一张完整的动态纹理，再参与世界深度。原轮廓、颜色、纹理、呼吸、走动、等候、开心、眨眼及滚动绘制继续使用。`CreatureArt`只新增默认开启的`draw_shadow`开关；原有调用保持原默认行为，合成视口复制`look`后关闭内部影子，不修改调用者的姿态字典。

伙伴合成图的脚轴固定在`(64,112)`。站立、走动与等候的原画绘制点为`(64,107)`；滚动为`(64,97)`，给原球体旋转留下固定余量。滚动仍沿用原`time/220`旋转和低动态下的零角度。这些调整只发生在合成画布内，不改变人物世界脚点，也不按每帧alpha包围盒反复吸附地面。

该合成路径只在1-1原生深度、接触脚点分支使用。其他11关继续直接调用原伙伴绘制。

### 6.3 影子单独绘制在接触高度的地面上

1-1伙伴的影子已经从合成图中移出。`GardenView`先选择`ground`平面，以人物当前接触高度绘制影子，再切回人物`billboard`平面绘制完整伙伴纹理。跳跃的画面位移继续应用于人物图像，地面影子留在地面接触位置。

这恢复了身体与地面影子的各自绘制职责，仍由原生深度处理人物、地形及其他场景元素的遮挡关系。

### 6.4 人物共面时沿视线施加微小深度偏移

首关原生深度提交人物对象时，`begin_object()`传入`0.001`的对象级深度偏移。`DepthPaintTarget`将其限制在`±0.001`，与原有微小绘画层间距一起沿视线方向施加。偏移保持屏幕投影位置，用于分离人物与接触地表共面时的相等深度，完整人物纹理继续使用原生alpha深度预处理。

这不会改变`actor_ground_point()`、路线XZ、台阶支撑高度或镜头锚点。地形、花草和人物仍保留各自世界深度；本轮没有把全场人物放到界面层绘制。

### 6.5 素材脚锚与保护范围

主角PNG仍为原256×256图片，绘制宽度115和固定`236/256`图像脚锚保留。此前测得alpha≥128脚底大致为idle-front235、idle-back/side234、walk-side约230…231，对应约`.45…2.70`设计像素的素材差异。本轮**没有**按clip重设主角脚锚，该诊断仍是后续独立复核项，不能写成已经校准完成。

本轮保留原PNG与球体素材、原伙伴程序图形、既有行走/滚动/跳跃轨迹、恒定世界站位、脚点和台阶支撑方程、镜头路径、关卡地块与楼梯/石坡布局。种子预算、分支选择、连接规则、互动距离、收集与零收集通关、存档格式和解谜路线均不因外观处理改变；没有为追求画面整齐而铺开隐藏路线或取消探索遮挡。

新增外观测试已完成12组独立原2D绘制与合成纹理的GPU配对，检查完整可见颜色、透明边缘、角落和身体内部alpha，并核对51个角色纹理别名的原文件哈希。`headless`分支仍明确跳过像素验证；其通过结果与本次GPU结果分开列出。隔离纹理一致、有限深度像素检查及正常场景定格不能证明所有遮挡状态、人物间距舒适或美术效果已经得到用户验收。
