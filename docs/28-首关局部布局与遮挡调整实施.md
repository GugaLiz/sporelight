## 实际调整

1. 花床显示宽度收至82、纵向缩至原来的0.78，向原格内后侧偏移；后方装饰缩小并退到外角，前方落脚面更容易辨认。没有移动规则地块，花床点击区域、光圈和标签共用新的视觉锚点。
2. 首关台面、左右侧墙、每级台阶分别绘制，在合法楼梯入口裁出局部缺口；承托人物、花床、装饰的表面先于其对象绘制，保留无关前景应有的遮挡。
3. 公共楼梯连接helper生成可逆脚底轨迹，人物在碰到阶面前抬脚。普通行走、归队、滚动和跳跃均接入，跳跃弧线叠加到台阶轨迹；两个人物在楼梯上平滑收拢队形。相机仍使用原有的逻辑插值。
4. 标签优先选择附近不重叠的位置，必要时用细引线连接对象。新编排和渲染明确只对1-1启用；公共helper可供后续关卡按需接入。

`src/`、`godot/core/`、`godot/content/`、`godot/services/`相对基线均无改动。

## 性能采样与限制

修改前4187与修改后4185顺序独占采样，均为正式Web包、QA桥关闭。环境为本机RTX4090D、Chrome156 headless、DPR1；每种尺寸分别采样静止与键盘移动约4秒。

| 尺寸 / 状态 | 修改前p95 | 修改后p95 |
| --- | --- | --- |
| 1280×720 静止 | 8.415ms | 16.610ms |
| 1280×720 移动 | 8.440ms | 16.670ms |
| 1920×1080 静止 | 16.655ms | 8.430ms |
| 1920×1080 移动 | 16.625ms | 16.665ms |

全部样本中位数约8.335ms，两组均满足本次p95≤16.7ms的目标，均无浏览器错误。720p尾部帧时本轮上升、1080p静止则下降，存在采样波动，不能据此宣称性能提高或完全没有回退。修改前720p移动有1帧约50ms，修改后有1帧约33.4ms。该数据来自rAF间隔，不等同GPU耗时，也不能代表低配电脑或手机真机。

证据：[修改前采样](qa-godot-migration/first-level-layout/performance-before/checks.json)、[修改后采样](qa-godot-migration/first-level-layout/performance-after/checks.json)。

固定状态像素相同不等于所有动态场景已遍历；本批连续运动验证聚焦1-1。技术检查已经完成，是否达到用户期望的舒适度仍需实际试玩对比。其它关卡后续如需采用新编排，应逐关配置和验收。
