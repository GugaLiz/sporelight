## 三、逐项详细说明

### 🔴 B-01 确认生长机制不可读（最高优先级）

**现象**
底部主按钮文字会在 `选择生长方向` / `收回根路` / `根路 1/4` / `在这里坐一会儿` 之间来回变，玩家无法判断"点它 = 确认生长"还是"= 取消"。1-1 的确认逻辑是靠"点击对岸让角色走过去"反推出来的，无任何提示。

**复现**
1. 进入 1-1，按 E（或点底部主按钮）→ 弹出"向东生长·1节 / 向南生长·1节"。
2. 点一个方向 → 底部变"收回根路·E"。
3. 此时没有任何"确认/生长"按钮，按 E 反而收回；只有去点对岸才会走过去。

**根因定位**
- `godot/application/main.gd:350` —— `KEY_E: _on_command("primary")`，E 固定映射到 `primary`。
- `godot/application/main.gd:451-467` `_primary()` / `_context_primary()` 决定 primary 的 id。
- `godot/application/main.gd:974-978` —— 主按钮 label 由 `command.label` 拼 `· E`，**label 随上下文变化**。
- `godot/application/native_interaction.gd:52` —— 当只剩 `retract` 时 label 变"收回根路"，**覆盖了"让根桥生长"**。
- `godot/prototypes/root_weaving.gd:86-91` —— `_native_interaction_context()` 里"让根桥生长 / 规划根桥 X/Y"的 label 被上面的逻辑盖掉。

**修复建议**
1. **给"确认生长"一个独立、固定的入口**：`plan.ready()` 为真时，底部出现独立的 `✔ 生长根桥` 主按钮（不要复用 `retract` 的槽位）。
2. 主按钮文案**不要随状态乱变**，用固定三态：
   - 未规划：`规划根桥`
   - 规划中（未 ready）：`继续规划 X/4`（禁用态或直接隐藏）
   - 已 ready：`✔ 生长根桥`
3. `收回` 单独做成次级按钮（如长按/一个小图标），不要占用主按钮。
4. 在 `native_interaction.gd:52` 处确保 `weave:confirm` 优先于 `retract` 被选为 primary。

**验收标准**
- [ ] 规划出合法路线后，底部出现**明确的"✔ 生长根桥"**按钮。
- [ ] 点该按钮角色自动沿路行走并生长，无需点击世界目标。
- [ ] "收回"不再是主按钮文字。

### 🔴 B-02 可生长点（`+`）在第一次规划后消失

**现象**
1-2 中，进入规划后能看到 `+`；点掉第一颗后，**新的 `+` 不再显示**，玩家不知道下一步能点哪里。只能反复按 E 重置重来。

**复现**
1. 进入 1-2，点"选择生长方向"→ 出现两个 `+`。
2. 点其中一个 → 根路 0/4 → 1/4。
3. 此时找不到新的 `+`，无法继续规划。

**根因定位**
`godot/prototypes/root_weaving_stage.gd:80-103` `draw_context()`：
```gdscript
for socket: Array in world.level.roots[0].sockets:
    var id := "g:root:%d:%d" % [socket[0], socket[1]]
    if id in world.state.growth.root: continue   # 已生长的跳过
    ...draw + ...
```
问题：`+` 的显示依赖 `world.state.growth`（**已确认**的生长），而规划中的 `draft/plan.commands` 只画在 `_polygon` 预览里，**没有推进 socket 的高亮**。所以第一次规划后，前端 socket 视觉上消失。

**修复建议**
1. `draw_context` 里把 `draft`（`plan.commands`）也纳入"占用"判断，**让前端始终显示"下一格可生长点"**：
   ```gdscript
   var occupied := world.state.growth.root.duplicate()
   occupied.append_array(draft)   # draft 也视为已占
   for socket in sockets:
       if "g:root:%d:%d" % [socket[0], socket[1]] in occupied: continue
       _draw_plus(socket)
   ```
2. 或更直接：**高亮"当前路径末端相邻的全部合法格"**，用呼吸动画 + `+`，确保任何时刻都有清晰可点的下一步。

**验收标准**
- [ ] 任意规划进度下（0/4、1/4、2/4、3/4），画面上**始终**能看到下一步可点的 `+`。
- [ ] 点击 `+` 立即在对应位置出现预览石板。

### 🔴 B-03 根路预览石板不可见

**现象**
底部计数显示"根路 1/4"，但画面上看不到那块预览石板（或极淡到看不见），玩家无法确认已规划的内容。

**根因定位**
`godot/prototypes/root_weaving_stage.gd:88-95`：
```gdscript
for i in range(draft.size()):
    var at := target_position(draft[i])
    canvas.draw_colored_polygon(_polygon(draft[i]), Color(0.68, 0.80, 0.47, 0.65))  # 65% 绿
```
- 颜色 `(0.68,0.80,0.47, 0.65)` 在暖黄+苔绿背景上对比度低，**极易与草地/石板融为一体**。
- 同时 `draft` 数组来源可能是空的（`view.draft` 未与 `plan.commands` 同步），需确认。

**修复建议**
1. **提高预览对比度**：用暖金描边 + 半透明填充（如 `Color("f8e2a2", 0.85)` 描边 + `Color("a8c06f", 0.5)` 填充），并加轻微发光/脉冲。
2. 在预览石板上**画序号 1/2/3/4**（代码里已有 `draft_number`，确保启用）。
3. 校验 `view.draft` 与 `plan.commands` 的同步时机（`_sync_hud`）。

**验收标准**
- [ ] 每规划一节，画面上出现**清晰可见**的编号预览石板。
- [ ] 预览颜色与已确认石板有可区分（虚/实、亮/暗）。

### 🟠 B-04 收集物（金色微光球）点击热区偏移

**现象**
点击金色微光球**本体无反应**，必须点它"正下方那一格"才能收集。

**根因定位**
`godot/core/garden_world.gd:109` / `:832` 收集判定基于**格子（tile）**，而金球是**浮在格子上方的贴图**，视觉中心与判定格中心有纵向偏移。

**修复建议**
1. 收集判定改为**像素距离命中**（角色/点击点与球体的屏幕距离 < 半径即收集），或
2. 提供**更大的点击热区**（球体包围盒外扩 20~30px），或
3. 做成"角色走近相邻格自动吸附收集"。

**验收标准**
- [ ] 直接点击金球本体（哪怕偏上一点）即可收集。
- [ ] 收集后立即 +1 并播放反馈。

### 🟠 B-05 休息点"劫持"主按钮

**现象**
站在"在这里坐一会儿"（rest）上时，底部恒为"在这里坐一会儿·E"，即使想继续规划根桥也被挡住；此时方向键经常不响应，容易卡死。

**根因定位**
`godot/application/native_interaction.gd:52` 附近的焦点选择：observe/rest 类交互会抢占 primary，且 `rest` 位于根台附近，玩家规划时很容易站上去。

**修复建议**
1. **rest/observe 降级为次级交互**（长按 E 或单独小按钮），**不占用 primary 槽位**。
2. 站在 rest 上时，若存在可推进的 `weave:plan/confirm`，**优先显示根路主按钮**。
3. 修复 rest 状态下方向键输入被吞的问题（`_physics_process` 里 `input_router.clear()` 的条件）。

**验收标准**
- [ ] 位于休息点时，主按钮仍是"规划/生长根桥"（或至少同时可见）。
- [ ] 休息点可正常走开，方向键不丢失。

### 🟠 B-06 E 键多义导致误操作

**现象**
同一颗 E 在不同状态分别是：打开方向面板 / 收回根路 / 休息 / 确认。玩家极易按错。

**根因定位**
`godot/application/main.gd:350` `KEY_E: _on_command("primary")` —— E 永远走 primary，而 primary 的语义随上下文漂移。

**修复建议**
1. 拆分按键：`E = 交互/确认`（语义固定为"前进/确认"），`Backspace/Z = 撤销`，`Esc = 暂停`。
2. 若保留"收回"，改用独立键（如 `R` 重来）。
3. 底部按钮显示对应的**键位提示**，且键位与语义**一一对应**。

**验收标准**
- [ ] E 始终 = 确认/交互，不会变成"收回"。
- [ ] 撤销/重来有独立按键且 UI 有提示。

### 🟡 B-07 两套规划交互并存

**现象**
1-1 是"弹出方向面板（向东/向南）"，1-2 是"直接点 `+` 号"，同类操作两种交互，学习成本叠加。

**修复建议**
统一为**一套**：推荐"直接点 `+` 号 + 高亮下一步"，因为它更直观、更符合等距地图。移除方向面板或将其作为辅助。

**验收标准**
- [ ] 所有根须关卡使用同一种规划交互。

---

### 🟡 B-08 提示文案缺方向性

**现象**
提示"岩石挡住了直路，周围还留有空隙"——有氛围但无方向指引，玩家仍不知往哪走。

**修复建议**
在氛围文案后追加**一句方向性**提示，例如：
> "岩石挡住了直路。试试先**向上**绕，再折回右侧。"

**验收标准**
- [ ] 每条提示都含明确的下一步方向或操作。

---

### 🟡 B-09 回退提示语易误解

**现象**
"回到刚才的稳定时刻""叶片合拢休息，可以重新安排方向"——玩家会怀疑"是不是白做了"。

**修复建议**
回退时明确"撤销了什么"，如：
> "已收回 1 节根路（剩 0/4），可以重新规划。"

**验收标准**
- [ ] 回退提示明确说明撤销的数量与当前状态。
