## 2. 实现与保护边界

- `chapter_garden_dressing.gd` / `chapter_surface_materials.gd`：目标融合、章节调色与原坡面材质；缓存区分章节及旧/新策略。
- `mechanism_props.gd`：只读现态生成琴台、门闩、留影、照料与升降反馈；动画只移动已有指针，不重建网格。
- `rule_ray_presentation.gd`：逐段裁剪显示范围，保留反射转折；前后光路变化时等待动作完成再显示目标连接，撤销/暂停/清理都有测试。
- `isolated_rock_spire.gd`：正式1-2与规划试玩共用原岩柱表现；旧试玩路径保留兼容入口，无碰撞体。
- 3D文字显式使用已有Noto字体；默认Web字体不含部分原符号，改用已验证存在的「转」「日」「月」与方向符号。
- `native_interaction.gd`：附近多对象进入原有操作菜单；默认目标全禁用时可转向合法实质动作。保留原1.65距离、观察权重、动作ID及领域可用性查询，不替玩家执行命令。

[保护范围核对](qa-godot-native/all-level-adjustment/protected-contracts.json) 对照上轮25个关键文件指纹：20个完全不变，5个属于本次明确的表现接线、标签与附近操作菜单变更。关卡定义、core、services、原图片与fixture的Git差异为空。没有修改资源预算、邻接、角色能力、完成条件、存档格式或旧参考数据来迁就测试。

## 3. 修复过程中发现的问题

1. 旧/新坡面材质缓存键相同，会受先后进入关卡影响；已按表现策略隔离，并测试首关→后续→未知关。
2. 升降指示提前显示目标档；改为连续随动，验证正反方向、暂停与动作清理及节点身份稳定。
3. 末关光庭旋转中段提前画出目标反射束；真实GPU截图确认后，修正为对齐后显示，保持规则判定不变。
4. Web默认字体不支持部分机关符号；使用项目字体并逐字检查，统一日/月表达。
5. 洞窟新装饰晶体与解谜物相似；换成普通蓝花，避免增加假交互对象。
6. 真实触屏复测发现3-1已经打开的窗口遮住附近合法的照料操作，以及cloud-2/3单项伙伴互动使可选观察进不了菜单。保留原距离与观察权重，仅在默认组全禁用时优先附近可用的实质动作；菜单纳入范围内其他对象，并保留不可用原因。首关仍明确选择生长方向，不自动长桥。

早期测试中还修正了测试自身对睡眠伙伴姿态、缺省tile.kind、水位防淹前提和浏览器动画提交时机的错误假设，未放宽游戏保护。候选检查和失败证据保留，不能以最后通过结果抹去过程。

首关横屏的可选探索测试还暴露自动点击定位问题：去`f:-1:0`的投影中心落入南向生长「+」的23px真实命中范围，测试先误种根路、再走方向键回退，后续才报生长不可用。只等待镜头投影稳定不能解决控件重叠。验收工具改为先检查生长控件及HUD热区，受遮挡的地面目标直接记录并用真实方向键行走；保留失败目录，不修改首关地形、规则或点击热区去迁就测试。手机证据因此明确属于触屏操作与方向键遍历混合验证。
