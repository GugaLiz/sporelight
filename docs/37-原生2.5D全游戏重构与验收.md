## 实现分工

- 原生世界：真实地形、碰撞、坡道、正交镜头、角色精灵、机关与材质。
- 运动与应用：CharacterBody 连续行走、合法跨边、伙伴、平台、动作事务与输入路由。
- UI：紧凑目标与资源、情境操作、分级帮助、多屏幕、页面来源与焦点。
- 集成：云庭规则/旧档、独立浏览器验收、构建、规则回归、性能与画面审查。

角色碰撞根由同一个 motor 控制；Visual 子树负责动作和图片。规则仍控制预算、通路、能力、站位和当前因果，导航与物理不能自行打开道路。

## 关键改动

1. 全关卡共用原生 Stage，使用固定正交相机、原生平台/坡道/碰撞及原图片角色；旧 Canvas 排序不再作为默认表现。
2. 连续移动可在单元内停下和转向，实际跨边后才提交角色支撑 ID。
3. 伙伴沿合法路线真实行走；同一支撑内的局部位置进入存档和撤销。
4. 种路预览、生长、可走与回收具有明确阶段；未完成的预览不产生可走通路。
5. 交互来自当前附近对象，根台先选方向；默认提示不再输出解法。
6. 桌面移除常驻方向盘/命令卡，触屏单独处理；低横屏优先保留游戏视区。
7. 页面记住真实来源，区分首页、地图、继续和回看；手柄和键盘均遵守 UI 消费。
8. 云庭保留转桥、升降、花种、伙伴压板/门闩、会合与故事发现，并复用公共组件。
9. 已保留的旧云庭原文可以转换为实际可用进度，当前原生进度不会被再次覆盖。

## 已发现问题与修复规则

| 发现 | 处理原则 |
|---|---|
| 同一格图片堆叠与坡道不贴地 | 可视面、支撑采样、碰撞使用同一空间定义 |
| 墙纹理过密与不连续 | 按世界尺度铺设，不能每格缩入整张墙 |
| 原花床图片带等角底座，产生二次透视 | 原生底座与原图片植物区分开使用 |
| 每次状态变化可能重建网格 | 仅拓扑/材质变化更新，可见性与效果独立刷新 |
| 行走后伙伴停在准备回收的桥面 | 停稳后沿合法路线进入安全支撑，保留占用检查 |
| 交叉坡槽被胶囊判为墙 | 修改真实地形肩部和落台，不通过瞬移身体掩盖 |
| 规则支撑已变，旧 runtime 姿态仍称旧支撑 | 事务内清除失效姿态，实际 motor 在同物理批次重采 |
| GUI 与手柄 A 重复执行 | UI 先处理，世界只接收未消费事件 |
| 子页关闭丢失地图来源 | 返回来源栈与明确页面协议 |
| 提示条/局部菜单出现让镜头重构图 | 安全视区只由常驻 UI 定义 |
| 暂停页滚动/跳跃只改文案 | 必须接真实持续视觉状态/有时长动作，不改变合法通路 |
| 偏心进入窄坡后碰侧肩或转向锁死 | 坡宽减去胶囊半径和余量形成真实通行带；以正常速度走回平落台再转向，不能瞬移或强赋 Y |
| 连续运动的小数坐标写盘后误报失败 | 对同一份完整精度 JSON 字节建立规范解析基准，再严格验证临时文件和提交文件；不放宽规则或支撑 ID 的比较 |
| 水轴先跳到终态、跨空连线像桥 | 浅槽绑定模块的实际变换；资源传递用稀疏水滴与节点标识，机关对齐后才显示新连接 |
| 主按钮出现字体缺字方框 | 在显示层处理装饰符号，保留原规则命令和 ID |
| 介绍文字直接给操作顺序 | 原生入场显示自然目标，具体方向进入玩家主动请求的分级帮助 |

上述规则适用于所有关卡，差异通过关卡数据和支撑定义表达。不能把针对一个截图的像素偏移作为公共方案。

## 验证方法

- 保留旧规则参考，验证核心玩法因果和替代路径。
- 新 motor 回放实际经过完整参考路线，不用 world.move 替代真实物理移动。
- 真实 PhysicsServer 射线独立检查可见地形与碰撞，不用固定“penetration=0”标签作为证据。
- 浏览器使用隔离上下文；QA 只准备场景与读状态，操作通过真实键盘、鼠标和触摸。
- 画面由实际 GPU 截图逐轮检查，未通过的候选继续修复。
- 记录导出源摘要，避免混用旧页面与新检查结果。
- 性能报告注明本机和浏览器，不把屏幕模拟当作手机真机。

## 本机性能与边界

正式 release、无 QA 遥测；本机 Windows / Chrome 156 / RTX 4090 D，1280×720、1920×1080 各取静止与持续按键样本。帧间隔中位数约 16.665–16.670ms，P95 为 16.86–16.89ms，四组采样无超过 33.4ms 的帧，无浏览器错误。实际初始场景为 3-4，不是在首页采集。

[性能原始报告](qa-godot-native/acceptance-final/performance/checks.json)的 `passed` 只表示采集完成；严格 P95≤16.7ms 预算的 `meetsTarget=false` 如实保留。rAF 是页面帧节奏，不是 GPU 计时，也不是手机性能或全部设备 60FPS 认证。release 不暴露遥测，持续移动是否正确由独立真实路线/运动检查补证。

当前完成的是统一操作、渲染、交互和保存的运行基础。人物仍使用既有图片，水滴是因果表现而非流体模拟。真实手机、实体手柄、长时间游玩、无引导真人体验及未采样走位仍需后续试玩；不能承诺绝对不存在任何穿模或所有玩家都觉得有趣。

## 失败记录与修复闭环

- 首轮 GPU 的墙纹过密、坡面拉伸、花床二次透视和圆盘被拒收，修复后重新采图。
- 实际行走发现伙伴停桥、交叉坡槽和偏心侧肩卡模；修了真实支撑和通行体积。早期 `final-browser-gameplay` 的 1-2 失败图保留。
- 第四轮名为 `final-headless` 的报告因运行源变动 `stable=false`，不是本次交付证据。此前 `acceptance` 的 48a0 源报告也保留，但以本文件列出的 `acceptance-final` 为准。
- 回首页测试先修复脚本滚动/QA 序列等待，再暴露并修复实际小数坐标保存失败，未靠放宽保存比较通过。
- 最终画面又发现 `✧` 缺字、介绍泄露顺序和水轴先跳终态；修复后重新冻结，重跑全量并重导正式包。
- 正式包首轮 `release-smoke` 错误假设 Shift+Tab 会从首控件回环到首页按钮，实际未激活返回；该失败报告保留。观察设置页实际按钮后，用真实滚动和点击重验，结果见 `release-browser`，并人工确认首页、刷新和继续的语义。
- 性能工具首次被 Node fetch 的保留端口限制阻止，改用 HTTP 元数据读取后验证持续行走工作负载；最终正式性能重新独立采集。
