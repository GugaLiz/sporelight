## 2. 分工与顺序

| 角色 | 所有权 | 责任 |
| --- | --- | --- |
| 主 agent | 本计划、应用衔接、stage必要接线、集成与最终记录 | 先落实计划；审查核心逻辑不变；按下表阶段推进，冻结候选后统一导出 |
| 地形渲染 agent | profiles、新增章节 dressing、对应专门测试 | 从1-3开始按章节检查；复用目标融合/角色深度，保持原通行几何；以截图决定装饰密度 |
| 机关表现 agent | 新增独立机关表现模块及对应测试 | 按关卡顺序修复状态与画面不一致，所有表现只读真实规则状态 |
| 独立验收 agent | 新增验收脚本与证据 | 改前/改后截图；桌面和横屏；独立审查实际路线与可见状态，发现问题交回修复 |

并行的是调查、互不冲突的模块和测试准备；共享文件单人写入。按顺序启用和审查关卡改进。不得在导出/最终验证期间继续修改运行源，也不以 agent 自报通过代替集成验收。

## 4. 每阶段验收门槛

1. **改前证据**：现有源码问题或实际截图；标记已有缺陷，不用猜测替代分析。
2. **最小候选**：先修改本关表现，只读规则；新增共享能力按关启用。每个改动对应具体问题。
3. **自动检查**：有意义的表现状态测试、独立物理网格/碰撞检查、相关菜单/事务/存档检查。已有规则快照保留原样。
4. **真实路径**：以真实角色胶囊和应用命令完成主线12关及云庭3关；检查身体/脚点支撑、动作后最终位置和实际完成。参考路线不是全部合法解证明，特别机制另测负向与替代解。
5. **实际渲染**：1280×720、844×390分别查看初始、机关关键状态、完成前与完成后的GPU截图；抽查运动中段和真实鼠标/键盘/触摸。状态恢复截图与真实输入通关分开记录。
6. **退回修复**：穿模、黑屏、错误遮挡、丢支撑、非法捷径、无法完成、阶段表达错误均阻止通过；先修复再重跑受影响检查。
7. **最终冻结**：导出包与源码摘要一致；完整报告列明关卡、变化、证据、通过项和未验证范围。首关不回退；不宣称真机或全平台验收。
