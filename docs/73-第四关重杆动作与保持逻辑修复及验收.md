# 第四关重杆动作与保持逻辑修复及验收

2026-11-12。针对用户1-4重杆动作/逻辑新反馈实施，遵循项目内game-scene-quality Skill和57号关卡契约。**本次重杆修复开发验收完成，4222已更新**；72号场景位置通过记录不能覆盖这次新问题。

用户原图：[异常蹲姿与远离重杆](qa-godot-native/heavy-lever/key-evidence/2026-11-12-feedback.png)。截图用于识别现象，未将图中文字作为开发指令。当前保留已认可尺寸、素材、原地形与楼梯；不重做关卡或改变解谜顺序。

## 原因与修复

| 已确认原因 | 当前行为与实现 |
| --- | --- |
| hold直接强制播放普通interact拾取蹲姿，没有持续操作姿态 | 有效持杆使用独立hold_lever状态，复用原idle-side图片及原站立尺寸/脚锚；拉动/松开时真实杆臂连续插值，站立手侧与握球对齐 |
| 邻格可发起交互，却没有真实走到把手旁 | 原生use:hold先验证，再沿合法地面走到原f:-3:0操作位，实际到达才拉动与提交；点击新合法目标/手动方向可取消接近，尚未到达不开放桥 |
| 规则只在换格时清除hold，原生同格位移不改变格ID | 第一段真实水平位移便预演并提交显式RELEASE_HOLD事务；包括非当前露薇的实际跟随移动，静止输入或无意碰撞漂移不作为松手 |
| 单改hold会让桥上伙伴失去支撑，或出现身体已走开但保持还在 | 同时检查规则占用与真实胶囊/岸沿；失败恢复本次身体位置、保留hold与桥，不插入失败走路检查点；成功后同一物理帧刷新邻接 |
| 永久latch后遗留hold，且仍可能重新扳杆 | 开闩清除临时hold，恢复旧档时剔除废弃hold，永久开闩后不再提供/接受use:hold；永久道路保持 |
| 球形/切换可覆盖持杆视觉，重复操作语义不清 | 开始保持先站起，换手仍保持；切回持杆者清除滚球显示，保持时跳跃/变球提示先松手。重复use:hold维持原幂等语义，明确release:hold单独提供 |

核心流程保持：露薇保持→小苔灵过临时桥/低拱→小苔灵压板→露薇固定门闩→归还门铃→开门接回伙伴→进入小花园主动照料。小苔灵不能替扳重杆、露薇不能穿低拱，门铃与最终修复条件不变。

## 空间、素材与保存边界

- 操作位仍在原把手格同高台面内：露薇局部偏移(+.38,0,-.08)，伙伴(-.32,0,+.26)。由真实电机到位，不传送绘制位置；未改逻辑格、碰撞保护或接岸阈值。
- 原杆臂长度保持.47，铰点、底座和尺寸不变。初轮保持角使握球靠近颈部，被独立复核否决；最终方向为(.33,.303,.14)归一化，握点降至可见手侧。只更新已有臂/握球变换，不每帧重建网格。
- 原侧身素材提供站立接触表达，没有新增精细手指或骨骼抓握动画。正常深度、角色脚锚与大小保留。
- 同格松手前记录原生身体姿态；撤销同时恢复桥与原站位。合法held存档可恢复；latch+hold旧档只清除过期临时标志。未重置用户旅程、收藏、设置或其他关存档。
- 交付沿用http://localhost:4222/的origin；自动浏览器使用隔离环境。测试仓库是内存实现，不读取或清理用户存档。

生产改动集中在garden_world、GameCommand/GameSession、main、native_movement、native_garden_stage和mechanism_props；测试/取证工具单列，levels.json和原路线fixture本次不改。
