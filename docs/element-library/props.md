# 道具与布景复用合同

覆盖主线 1-1～3-4。此次只抽取现有定义并接入原渲染器；保留玩法、碰撞规则、地图实例位置和已调整比例。3-4 保留当前旋转版本，不重新设计流程。

## 运行时入口

- `godot/content/prop-elements.json`：花坛状态槽、完整画布尺寸、脚锚、真实底座、各关明确例外、原始布景脚点、拾取物体积与自然道具裁剪数据。
- `godot/elements/prop_definitions.gd`：读定义、像素到世界单位换算、花坛显示与接地尺度、语义判别。
- `godot/elements/element_assets.gd`：统一资源槽与主题替换；自然水轮、升降架、根盆、日月石已消除独立 preload 资源旁路，主题 revision 变化会刷新 AtlasTexture 缓存。
- `renderer_adapters`：原生机制渲染器登记。它们是不同签名的适配器，不是可直接互换调用的通用工厂；lightwell 为每个 stage 持有的实例，其他按其既有入口调用。

定义修改在下次启动加载，也可显式调用 `PropDefinitions.reload_definitions()` 后刷新舞台。公开 `definitions()` 返回副本；内部 `section()` 是只读共享引用，渲染器不得修改。`reload_definitions()` 保留既有表引用并更新转换缓存，递增 revision；自然图裁剪缓存同步失效。主题路径替换由统一资源提供器处理；不在每帧解析 JSON。布景原始实例坐标仍在 `original_garden_dressing.gd`，避让算法及逐关目标仍在 `original_scenery_placement.gd`；这些是关卡布局，不应被一键换皮抹平。

## 同类元素与规则

| 元素类别 | 复用内容 | 必须保留的差异 |
| --- | --- | --- |
| 终点种植花坛 | `flower` / `bloom` 双状态、完整画布、脚锚、底座和接触阴影 | 1-1 宽 1.16；3-3/3-4 宽 1.65；各关真实平地支撑和后侧留空 |
| 普通任务花坛 | 与终点共享双状态图和接地定义，按历史 55 px 完整画布换算 | 独立交互状态与较小尺寸；不能仅凭 `kind=flower` 实例化 |
| 3-3 根盆 | 同一家族 `root` / `root_settled`，自然图裁剪及可见体积 | 与终点花坛语义不同，不能套石质花坛碰撞；根生长锚与照料盆共用视觉 |
| 水轮 / 升降架 | 统一自然素材槽、裁剪、脚点、测量比例 | 模块真实转动/升降状态由玩法层控制；3-4 原尺寸例外继续有效 |
| 日石 / 月石 | 成对自然石外观、裁剪与脚点 | 模式、携带、放回、插槽是玩法状态；外观不授予能力 |
| 花草、蘑菇、石灯、石头 | 资源槽、画布、脚点、接地宽度、硬接触区 | 装饰石灯不是光源；装饰蘑菇不是宠物；藤蔓悬垂不使用地面脚点 |
| 可携带物 | 可见物体包围盒、手持中心锚和各类尺度 | 日月石落地/手持两种比例有原设计差异；镜叶保留专用镜面朝向 |
| 镜面、摇杆、门栓、乐谱机关、光源接收器 | 登记现有适配器，资源替换走统一槽 | 程序建模、运动插值、碰撞及交互契约仍由专用渲染器实现 |

花坛 `reference_canvas_width=1.16` 对应底座 `0.80×0.80`。显示锚、接地阴影和碰撞元数据从同一份定义推导。支撑检查添加 `0.03` 留白，并采样已有平坦固定地面；不生成假支撑，不把楼梯、动态桥或装饰视为花坛地面。换图不能让花坛在完成前后跳位。

## 必须区分的同名语义

| 关卡/实例 | 实际语义 | 编辑器应如何表示 |
| --- | --- | --- |
| 全部 12 关 `core` | 终点种植 | 引用 `planter-terminal` |
| 1-4 `home` | 归还铃铛 | 交互锚，不放第二个花坛或石底座 |
| 2-3 `stage` | 乘客站位 | 随平台的印记，不放岸上障碍 |
| 2-4 `invite` | 共享种植点邀请 | 指向 `plant`，不重复画盆 |
| 3-2 `freeze` | 影子记忆机关 | 专用记忆机构，不当种植 |
| 3-3 `care` | 根盆照料 | 自然根盆，空/填充两状态 |
| 3-3 `root` | 根生长逻辑锚 | 指向 `care`，不重复画盆 |

编辑器应保存 `elementId + instanceId + support + transform + ruleBinding`。显示元素定义不保存任务完成 flag；实例也不复制公共图路径、脚锚、底座参数。确有逐关比例例外时记录命名原因，而非偷偷覆盖共享默认。

## 全局替换方法

替换全部普通石质花坛时，修改统一主题中的 `flower` 与 `bloom` 资源槽。两张图片保持同画布和脚锚。自然根盆属于另一语义家族，修改 `symbiosis-root` 与 `symbiosis-root-settled`。水轮、升降架分别使用 `symbiosis-wheel`、`symbiosis-lift`；日月石使用 `shadow-sun-stone`、`shadow-moon-stone`。

资源提供器拒绝画布尺寸不一致的仅路径替换。尺寸相同也不代表脚锚和底座相同：新美术若改变透明留白、脚位置、底座或轮廓，必须同时修改元素测量定义，并检验两个状态、真实支撑、完整碰撞与近处通道。此时应作为完整元素升级，不能靠放大 sprite 或关闭深度测试掩盖。原图生成 manifest 保留为来源记录；运行时裁剪/脚点以 `prop-elements.json` 为准。

## 验证与尚存边界

显式热重载只接收既有 schema 结构的测量修改；新增家族/字段需重启。负底座、非法字段类型、越界自然图裁剪、缺失渲染器入口会在发布新 revision 前拒绝。`resources` 默认路径修改也需重启；会话内换路径使用统一主题 `resource_overrides`，不依赖测量 reload。

`native_prop_library_test.gd` 遍历 12 关实际 terminal renderer，替换共享花坛槽后检查每关更新、脚锚/尺寸/碰撞元数据及玩法快照不变；同时验证自然贴图缓存更新、特殊 flower 标记不会误分类。该测试不验证新图的美观程度，也不能证明任意新素材天然适配。

此次未把每个程序网格改造成纯 JSON 图元，也未提供可视化地图编辑器。新增编辑器可复用已有资源、测量和语义数据；新增机制能力仍需玩法层实现及负向通路测试。未经 GPU 同机位比较，不将 headless 测试表述成画面验收通过。

生态层也要跟随共享资源 revision：池塘水面、岸边花草和浮叶在主题替换后重新绑定材质，普通移动不重复重建。草地专用 shader 按草地语义选择，不能用图片文件名判断。布景接地定义 reload 后，布局求解缓存必须包含定义 revision，重新验证真实支撑与通道；否则换大底座会错误复用旧位置。`native_element_cache_test.gd` 的 77 项覆盖上述热更新、恢复、无重复重建及玩法快照不变；原池塘 28,550 项通过，证据 `cache-semantic-final/checks.json`。
