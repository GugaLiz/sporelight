## 基础约束与资料归属

| 范围 | 统一要求 | 详细依据 |
| --- | --- | --- |
| 元素大小 | 区分装饰、伙伴、拾取物、机制与建筑；比较可见主体相对角色和真实地块的比例，不用整张PNG或相同scale值代替视觉尺寸 | [Skill尺度合同](../.agents/skills/game-scene-quality/references/scene-contract.md) 第1节 |
| 贴图 | 原素材、章节风格、砖缝/纹理密度、分面UV与真实物理尺寸相匹配 | 同上第2节；56、67号 |
| 地图与物件 | 逻辑→物理映射、支撑高度、脚锚和父变换一致；模型/碰撞/通路分别核验 | 同上第3节；56、68号 |
| 楼梯显隐 | 采用1-1已确认的真实台阶质量和生命周期语义，保留各关独立的梯级、跨度与高差 | [66号](66-全关实体楼梯与显隐统一计划及验收.md)；Skill第4节 |
| 装饰与效果 | 灯、水流、花草及拾取效果保持职责和可读性；不遮住解谜信息、不创建假道路、不以移除效果换取性能通过 | Skill第5节；67号 |
| 验收 | 自动检查、实际看图、真实输入和性能分开；检查范围随改动扩大，证据注明源码与设备 | Skill第6节；56号 |

具体操作方法以 Skill 参考为单一维护位置，项目特殊数值、关卡契约及例外仍归原专项文档，不再复制成多套互相冲突的规则。

## 每次比例调整必须产出的尺度表

以下是持续使用的记录格式。原70号装饰/道具表是历史候选；现行比例以71号原站身份、源宽、透明边距与例外为依据，当前位置和最终画面/通路结论见76号。候选参数不自动成为用户认可标准。

| 字段 | 记录内容 |
| --- | --- |
| 对象身份 | 素材名、语义角色、所在关卡/支撑ID，区分伙伴蘑菇与装饰蘑菇 |
| 图像与锚点 | 图片宽高、可见主体包围盒及alpha阈值、脚锚，光晕另列 |
| 世界尺寸 | 实际渲染宽高、局部台面宽深、父变换与支撑高度；明确单位 |
| 对照条件 | 构建/源码、视口、DPR、正常/全景、相机、场景状态 |
| 比例与证据 | 主体/主角高度比、主体/局部地块占比、同条件原图及基准关对照 |
| 决策状态 | 当前实测、调整候选、已认可；允许的差异及原因，不把候选写成确认值 |

首关是已确认参考，但不把其坐标、层高、单节根路和所有物件具体尺寸强加给其他关卡。优先比较相同语义、相同素材及相同观察条件。普通镜头统一不代表元素相对地图的比例合适，尺寸也不能只靠相机缩放修复。

## 后续补充方式

用户新增问题时，先查是否属于已有编号。属于同类就补充复现和适用范围；新的类别按当前最大编号顺延。复杂案例可在台账后追加详细条目，至少包含：

- 现象、预期和影响对象；用户证据或可复现步骤。
- 已知原因与待确认部分；对应Skill规则或项目例外。
- 修复范围、玩法/存档影响和所需验收。
- 状态：待定位→待修复→待验收→已解决；关闭时附构建/源码、实际输入及画面证据。

临时文件中的截图需在必要时复制到仓库证据目录，用相对链接保存；不要只引用某台电脑的Temp文件。新证据不能覆盖旧失败截图。记录规则不等于修复游戏，历史关闭也不等于用户已认可新的美术比例。
