# 视觉与空间合同

以下是检查方法，不是跨游戏统一的美术数值。先读取项目已确认的设计，再选用相关章节。

## 1. 元素尺度：测可见内容，不测透明画布

区分角色/伙伴、可拾取物、机制道具、装饰蘑菇/植物、灯具、建筑和环境水流。同一张蘑菇图可能承担不同角色，不要求它们等大；各类别应有明确可读性和视觉层级。

对本次修改的类别建立简短尺度表，记录：素材与角色、可见轮廓包围盒、脚锚、世界尺寸、所在支撑物理尺寸、普通视图的投影尺寸、参考图、状态（当前实测/候选/已认可）。避免只保存无单位的 `scale`。

- **透明边距**：宽为 W 的 PNG，实际可见宽为 B，名义宽 w 的实际可见世界宽约为 `w × B/W`。不同素材不能仅因都设为0.32就声称同尺寸。软光晕与实体轮廓分开量，记录所用 alpha 阈值，不用发光边缘代替主体。
- **局部比例**：比较道具可见宽/所在台面局部宽、道具高/主角可见高；对于加宽地块，同时比较沿两条地面轴的占地，不机械随加宽比例拉伸道具。
- **屏幕比例**：等角视图沿地面轴测相邻格投影距离，与道具投影轮廓配对；高度另以角色作参照。透视视图选相近深度的参照，不能直接比较远近像素。
- **镜头分离**：普通游玩、跟随、全景分别验收。缩放镜头会同时改变地图和道具像素大小，不能修复两者的比例失衡。大地图优先使用合适的跟随与独立全景，不能为塞进一屏把角色和所有元素缩成点。
- **跨关对照**：相同视口/DPR/相机模式下并排看已认可基准关与代表关，覆盖高低台、宽岛/窄桥、不同章节。固定世界尺寸只证明实现一致，不证明视觉和谐。
- **双人默认站位**：照料、操作、跟随落稳和恢复旧档分别检查两人的脸、身体与脚点。平面没有重叠不代表投影可读；不能让伙伴长期只露帽沿，或让原尺寸花坛遮住整个操作者。优先在现有合法支撑上设置真实分离的停靠点，并用真实跟随走到该点，不加仅供显示的偏移。
- **可见性测量**：帽顶不等于脸；蘑菇等特殊造型按实际眼睛/脸部区取样，不能统一拿图片顶部40%当头脸。源图射线测量只覆盖参与计算的遮挡物，角色相互遮挡、墙体和GPU深度仍须独立看图。正常下半身前景遮挡与硬底座穿入分别记录，不把二者混为同一阈值。
- **地面与携带**：先确认当前认可的携带语义。实体直接拿在手中时，对照同一可携主体的尺寸、朝向和身份颜色，并把固定底座留在地上；若认可基准明确以叶包/背包中的小图示表示携带，则保留包体、系绳、小图示和角色比例，不强行要求图示与地面实体同大。放下后恢复真实地面支撑，规则中的身份/角度不因缩略表达丢失。用户选择原站基准时，优先于此前自行制定的“地手实体同大”方案。
- **状态切换**：开花、修复等状态共用的底座保持尺度和脚锚；分别测量各状态素材的主体与裁切范围，避免更换图片后整件物体突然放大、缩小或跳位。
- **尺寸决策**：优先复用认可基线；没有标准时做候选样张并明确待确认，避免凭空制定“所有蘑菇都是一格的30%”。可独立推进候选制作和验证，不为例行参数选择反复请求许可。
- **原版恢复**：用户指定旧版本为标准时，逐实例核对身份、数量、状态条件与原格占比；先核实参考构建。原代码的完整画布宽须结合透明边距还原，不能将该宽直接赋给裁切后的主体。二维绘制顺序移植到真实深度后，必要移位须留在合法同高支撑内并记录理由；平面容不下原宽时明确登记局部例外，不能补地块改变谜题或偷偷缩小后声称完全等比。完成态清场截图保持完成状态，不为恢复移动而把开花改回花蕾。

完成条件：主体在目标屏幕能辨认，视觉层级符合角色职责，与人物/岛体协调；没有为了显眼而遮住落脚点或让装饰像可拾取物。相同比例的错误实现不能成为新的合格基线。

## 2. 贴图与材质

- 保留已确认素材和章节风格。墙面、顶面、立面、踏面使用适合该面的映射，不能把整张等角楼梯图拉伸到坡面或用地砖小裁片冒充墙画。
- 根据实际物理面长宽核对纹理重复密度、砖缝大小、接缝、方向和透明边。网格变宽时检查 UV，不能只放大几何。
- 缓存 key 包含影响输出的素材、profile、尺寸及映射参数，避免跨关共享错误材质。
- 在真实GPU画面检查滤波、mipmap、透明排序、闪烁、模糊和亮边。原图尺寸或材质断言通过不能证明贴图实际清晰。
- 替换表面材质时核对网格的绕序、背面剔除和透明模式。不能因纹理存在、碰撞可走就认定顶面可见；新材质默认值可能让整块平台消失，需实际看低位、运动中与落稳画面。
- 纹理丰富度与真实几何分开：保留原画细节，不以厚描边、假阴影或装饰条掩盖模型缺陷。

## 3. 地图、支撑、对齐与遮挡

- 逻辑格身份和显示物理坐标不同；经过项目映射取真实台面，再以表面高度采样放置脚锚。区分 local/global，检查父节点变换。
- 默认站位按电机真实到达、恢复和入口限位后的坐标验收；配置的偏移不一定等于最终身体位置。准备状态与从前一合法格真实走近分别取证。检查角色与机关底座间距时使用实际节点位置，不能只比较两个常量。
- 裁切素材的脚锚取有效实体底部，结合声明的 alpha 阈值和支撑方向校准，不统一套用 `H × 0.4` 等画布比例；悬挂、漂浮、平放及含底座的素材分别保留其锚点语义。
- 可见模型、碰撞与高度查询应来自同一地形描述。三者一致后，仍要确认它们没有共同生成非法通路。
- 检查完整物件底面和角色胶囊占地，不只检查中心点。台阶边缘允许的脚底包络按项目移动模型判断，不能将正常相邻一级接触当穿模，也不能用宽松阈值放过真正悬浮。
- **硬底座与叶冠分开**：硬石基、镜座、灯脚按真实占地局部防入，花冠和光晕不整体变成硬墙。增加阻挡时同时接入点击绕行、伙伴跟随、同格接近与旧非法脚点恢复；不能只挡住胶囊，却留下无限顶墙或不可达的默认停步点。动态物品落地前让受影响人物实际走出占地，取消保留携带物，拾起/撤销清除障碍。落地目标与操作者所在格可以不同，不擅自改写目标或限制既有放置能力。
- **遮挡与穿入分验**：前景植物遮腿按真实可见范围、实际卡片变换和前后关系判断，兼顾两位角色；范围缓存于资源/场景重建，逐帧不扫描像素。硬石基保持正常深度与实体性，不靠透明掩盖身体进入。物理扫掠后的护栏/脚点限位也不得把身体二次推入硬物；负向连续输入与点击走近均需验证。
- **登记创建路径**：同类硬物可能由核心、机关、原装饰、建筑或云庭等不同工厂创建。硬底座创建时同步登记“不做整卡软遮挡淡化”的语义，建筑框体与光封层分别标注；不能只给某张图片或某关加白名单，留下另一工厂的石门/灯塔继续幽灵化。
- **位置适配与尺寸分开**：用户认可尺寸后只修落点，不借摆位再缩放。石灯/岩石/建筑取完整基座，拱门分别核对两柱脚；植物区分根簇与可外伸叶冠。最后几行alpha的窄脚印只可作前脚锚，不能代替整个底面。选位同时检查实际花坛底座、人物初始/停靠、常走通道、当前及未来接岸；最近可支撑位置不等于合理位置。稳定布局不能随角色行走、开花、撤销或加载而追移。
- **投影分离单独验收**：地面底座互不相交，仍可能在等角视图中竖叠。灯与花、核心与小物分别看主体和脚部；机关牌、主角及伙伴在真实默认操作站位均应可辨，不能只检查主角是否挡牌，遗漏牌挡伙伴。高低台还要确认杆和底座没有藏进前景地形，只有符号可见不足以通过。旋转物件检查各实际朝向，不能仅凭一个朝向的平面距离通过。永久遮住主体须重新选同高落点；任意手动走位造成的短时遮挡与默认站位缺陷分开记录。修改默认操作站位后执行原路线，确认胶囊没有占到即将断开的接岸边缘，不通过放松占用保护让操作通过。
- 排查“只露屋顶/只有尖端”：先检查实际支撑、脚锚、周围高台的视线遮挡、透明排序、相机和HUD，再决定移位；不要直接抬高模型或关闭深度。
- 关键操作位被建筑遮住时，先尝试原同高支撑内的停步点，并用自然走近验证；正常高差机制与玩家主动走到背后的遮挡另记边界，不为全时可见移走高岸或追移物件。
- 装饰位置排除出生点、关键交互中心、未探索路径、当前/未来停靠区和根路占地；按物件真实占地判定，记录项目特例，不能用粗略距离一刀切所有场景。
- 边界应说明是否可走。薄连接保留薄板语义，固定岛保持合理底座，高差与桥长按玩法保留；无授权不通过新增固定地板或底座解决缺口。

## 4. 楼梯与动态连接生命周期

通用原则：阶梯需要水平踏面、真实立面、闭合边界和落脚区，外观、碰撞与支撑同源。不要统一各关的梯级数、总高差和跨度；以项目已经认可的台阶规格为准。

把以下状态写成当前项目的明确合同，再实现或修改：

| 状态 | 检查项 |
| --- | --- |
| 未生成/未接岸 | 不残留可走碰撞，不凭效果预览提前解锁；平台侧面封闭 |
| 生长/搭建 | 明确从何端向何端生成，顶/侧/底面进度一致；规则何时提交、输入何时锁定有唯一来源 |
| 已接通 | 两端高度、踏面、边缘、角色正反向通行与停步一致 |
| 离岸/旋转/平移/升降 | 外接梯断开后收回或隐藏、恢复封边；同一刚体内部有效梯保持；运动中不抢先使用终点接岸形态 |
| 落稳 | 根据实际合法邻接建立接岸梯，不能仅凭投影靠近生成通路 |
| 回收/取消/撤销/读档 | 遵守项目确定的即时移除或动画语义，恢复规则、支撑、角色及物件，清除临时网格、材质和碰撞 |

持续扳杆、守板等操作另检查“谁在维持、何时有效、何时结束”：

- 持续状态与一次拾取/下蹲动画分开；姿态绑定有效持有者及当前条件，实际身体、可见手部与机关握点一起验收。不能只改动画名，身体仍远离把手；需要走近时由真实移动执行，不能传送图片。
- 连续移动模式下，离开保持状态的判定覆盖同格内的实际水平移动与非当前角色的跟随移动。无位移的按键、碰撞漂移与真正离开区分，不能只等逻辑格改变。
- 若释放会收走他人支撑，规则、身体位移和撤销检查点必须共同接受或共同回滚。永久固定后的道路独立于临时保持，旧存档残留标志不能让角色永远维持动作或重新激活已结束的临时操作。
- 重复操作是否幂等、明确松手、换手、跳跃/形态切换、取消自动接近、撤销/读档与暂停按该关契约验证；不要为方便输入偷偷把“保持”改为开关。

至少看一次开始、中段、结束及恢复状态；只看最终静帧不证明生命周期正确。占用支撑保护、隐藏路径与水位/光照条件继续由玩法规则控制。

## 5. 瀑布、灯与环境效果

- 瀑布是有源头、唇口、水帘、落点/消散和时间行为的整体。分别检查水槽宽与石砖/岸宽比例、水帘宽与落差比例，不能所有岛共用一条细线就宣称统一。
- 源位置来自实际岸沿，水流与台面衔接；避免穿进墙里、越过根路或从核心道具中心流出。地形调整后重验水源是否仍存在和可见。
- 有真实接收水体才画接水波纹；无接收面按场景设计自然消散，不制造悬空水池。不要从场景视觉高度臆造规则水位。
- 灯、拾取光晕和水流需在普通游玩画面可辨，不能只在调试特写中存在。先调适合的尺寸与位置；不靠全局置顶、无限增亮或强制常驻屏幕解决。
- 使用既有动画时钟和暂停/减少动态/粒子设置。动效恢复需验证实际帧变化与暂停冻结；静态节点或截图不足以证明动画正常。

## 提示和场景界面

- 还原旧界面时同时核对台词、阶段提示、当前动作及真实入口功能；原图里的文字不是可以无条件常驻的状态。完成、归还、打开门等动作之后，默认指引必须跟随实际进度，不能继续催促已经完成的步骤。
- NPC问候同时检查逻辑接近、真实身体距离与层高。计时、重复冷却及主动提示优先级属于会话表现，不写入解谜进度。
- 布局中的可见性、文字和字体尺寸只在值改变时更新。不要在每次布局里先隐藏再显示同一控件，避免最小尺寸变化反复触发布局；在真实应用内静置多个渲染帧，再切换状态验证稳定，不能只调用一次布局函数即验收。

## 6. 验收与性能边界

对每次改动挑相关检查，不建立无差别全量门槛：

| 改动 | 最低有意义证据 |
| --- | --- |
| 文档/Skill | 引用、适用范围、例外、问题状态及Skill结构校验 |
| 道具尺寸/位置/贴图 | 实际普通视图原图；与基准同条件对照；目标桌面和小横屏；遮挡/脚锚/轮廓检查 |
| 相机/地图尺度 | 相同物件与相邻格的投影比例，正常→全景→返回；边缘、HUD、安全区及跟随 |
| 楼梯/运动/显隐 | 几何与碰撞、正反向实体移动、过渡关键帧、取消/撤销/恢复；未解状态不能绕过 |
| 拾取/交互 | 真正输入造成计数、物件显示与状态变化，撤销/读档正确 |
| 性能 | 普通发布构建，记录设备/分辨率/DPR、冷启动、首用动作、重复操作、持续行走；截图采集与计时分开 |

先复用资源、缓存、局部重建与状态更新；主体轮廓、裁切和脚锚测量预计算或按资源缓存，尺寸变化只更新受影响实例，不每帧扫描像素、重建尺寸资源、材质或网格，也不为装饰每帧扫描全地图。不将 rAF、平均FPS、无头测试时间或“用了引擎”当作无卡顿证明。披露实际峰值和测量范围。

交付证据标明源码/构建、场景状态和输入方式。QA注入只证明被准备状态的表现；真实输入才证明该流程。自动截图须实际查看；基线更新需有变化理由、差异审查和适用范围，旧失败记录保留。
