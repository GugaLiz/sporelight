# Godot 原生花园制作与接地规范

本目录由主线与云庭共用。玩法通路来自规则核，空间、接触和图片深度由 Godot 原生节点执行。

2026-11-10：后续开发先读 [全关卡现行规则](../../../docs/56-全关卡优化规则与首关验收基线.md) 与 [逐关玩法契约](../../../docs/57-全关卡玩法契约与优化清单.md)。实体楼梯和显隐生命周期以 [66号计划及验收](../../../docs/66-全关实体楼梯与显隐统一计划及验收.md) 为现行专项合同。本文提供公共实现细节；首关专属数值不直接推广。`true-stairs-final` 已通过原生回归、双尺寸GPU画面与正式包操作验收，4222已切换；首次材质准备峰值仍按66号记录保留。

2026-11-11：当前4222更新为 `art-restoration-delivery`。原版完整墙画、拾取浮动、瀑布/雨/喷泉/蝴蝶与HUD恢复见 [67号记录](../../../docs/67-原版地图与关卡美术动效恢复及验收.md)。`native_garden_effects.gd` / `native_garden_atmosphere.gd`复用缓存与统一时钟，遵循真实支撑、深度、暂停和设置；禁止用每帧全板查询或新建地形驱动效果。上段实体楼梯规则继续生效。

## 场景与职责

- native_world.tscn：单个持续更新的 3D SubViewport、正交 Camera3D、环境、光源与地形/物件/角色容器。
- native_actor.tscn：脚点为原点的 CharacterBody3D、半径 0.16 的胶囊、独立 Visual、AnimatedSprite3D、携物点、AnimationPlayer。
- native_surface.gd：实际支撑面、水平踏面、竖直立面、封闭侧面与碰撞。通用楼梯共用 generic_stair_geometry.gd；可视承载面、碰撞、support_height 与步态查询读取同一几何定义。
- native_garden_stage.gd：应用兼容接口、资源装配、地形差量、物件表现、镜头、发现显隐和交互命中。
- garden_water.gdshader：有水面语义的关卡使用柔边水色，章节背景不隐含整张水板。

## 空间与运动

1-1 使用 `first_garden_profile.gd` 的真实离散台阶：水平踏面、竖直立面、接岸入口和分组岛体基础。网格、碰撞和支撑采样共用定义；不使用下述通用窄梯肩部的自动对中限制。东根桥的逻辑 x=0.58…1.48 形成六阶，并通过 profile 映射拉长物理跨度；后排现为六阶，沿 z=-0.41…-1.31 展开，整幅踏面等高，没有西侧斜楔。南岛始终为 -0.65 的平面；南向根路长出后，才在 z=0.58…1.48 形成六阶连接。台阶通行通过限定合法支撑的胶囊上/前/下扫掠实现。1-2 通过独立 profile 接入真实阶梯与全宽通行；其余13关使用章节表现能力（原图花坛、章节调色、角色深度、交互圈）及通用实体四级梯，保留原有平台、梯宽和逻辑连接，不套用首关专属尺寸。详见 [首关规则提取](../../../docs/52-首关规则提取与后续关卡接入.md)、[第二关表现合同](../../../docs/53-第二关表现优化与玩法保护.md) 和66号现行迁移记录。

默认逻辑 x/z 一格对应 1 个世界单位，高度一层为 0.65。独立 profile 可定义同源坐标映射与物理层高（1-1 东桥加长，1-2 层高0.45及右岛加宽），规则格与存档身份保持。角色根变换只由 application/native_movement.gd 的 motor 写入。Visual 可做接地与动作，不能把规则位置拉回格中心。

普通落台中心半宽为0.20，总宽0.40，大于胶囊直径0.32。正交梯道在落台外相连，保留转向区；通用窄梯半宽0.32，肩部至0.42。原0.60连接跨度采用四级、每级0.15踏深，0.65总高差对应0.1625级高。碰撞也采用真实水平踏面和竖直立面，不能保留旧连续坡面来代替抬阶通行。

连续肩部必须用实际胶囊路线验证。单看中心射线能够通过，不能证明角色不会被侧肩卡住。2026-11-06 曾出现中心线与接缝测试通过、胶囊仍卡在正交坡交点的情况；修复使用实际平落台，未添加传送或无条件吸附。

通用根路尚未长出时，不为未来 socket 预留悬空半梯；Surface.rises 只读取当前真实格与合法连接。根路从实际前驱逐节显现，当前受影响接岸同源更新，其他岛体与未连接格不变。生成使用完整几何加材质裁切，输入事务锁保持至提交；首关回收立即移除消失格的表面，并非倒放生长。取消、撤销和重进须清理临时材质与残片。

root/bridge/shadow 的侧板从对应承载顶点向下0.20，不能沿用固定岛屿的基础底部。通用薄连接采用逐阶底面和闭合立面，避免斜底穿过平肩；首两关已确认连续斜底保留。不得把玩家种出的连接变成向下填满的墙而遮住低层和角色。

实际梯道宽度必须进入通行合同：半宽0.32扣除主角胶囊半径0.16和余量0.02，身体中心可用横向带为±0.14。traversal_profiles 直接读取当前 Surface.rises。普通平地仍自由行走；接近梯口时先以实际速度靠近合法带再前进，不能赋Y或瞬移。第四轮真实浏览器曾在偏心位置(3.457,1.32)发现中心路线测试未覆盖的侧肩悬浮，因此保留偏心、停止/反向及点击与键盘切换的体积验证。将断开、消失或改变高度的支撑须按整个胶囊脚印检查占用，不能只查人物中心。

## 素材与接地

主角使用原 256×256 帧，固定脚轴在源 y=236，AnimatedSprite3D offset=(0,108)，pixel_size=0.00625。

首关已恢复原 pixel_size=0.00625，铺砖、石墙、草地采用原纹理。台阶踏面及立面分别将原 stairs 图片中的等角石面四边形映射到真实平面，不再直接截取带斜边的矩形贴上去。压条两端在本格内部采样同一级踏面，不能跨台阶连接。实时阴影仍未启用，材质明暗不能宣称为真实投影。

滚球源为 89×99，不能套用主角脚轴。滚球按真实高度归一为 0.8 世界单位，图片中心置于地面以上 0.4，offset=0，绕图片中心旋转。退出滚球恢复主角规格。

胶囊在阶缘可能接触相邻一级，底部中心与正下方踏面的差值不等于接触侵入；须检查实际胶囊扫掠的接触点。仅校准Visual，物理根仍由motor控制。首两关视觉回落上限保持0.20；通用梯取至少0.20且容纳一级高度加实际胶囊半径，读档采用同一界限。沿梯速度为普通速度的62%，横向保持正常速度；可见脚底在真实踏面至一级高度之间连续过渡，停止回到踏面，阴影独立贴地。分别记录物理接触、Visual脚点、支撑和遮挡，不以固定penetration=0或中心高度差替代证据。

双角色同格的间距由实际局部姿态保存，Visual 不横向冒充另一个物理位置。原伙伴程序画只在缓存纹理生成时使用，持续动作使用原生节点。

首关 flower/bloom 保留原图完整花坛及石底座，不裁成植物后用几何盒子替代。首关侧墙改用与地面同源的 paving-valley 自然石板：garden_island_stone.gdshader 将连续世界 UV 恢复至一格一幅的比例，镜像拼接并内缩原插画边缘，避免非无缝图重复时出现亮边；侧面轻微压暗并正常受光。其余关卡保留原墙砖。台阶纹理随每级踏面重新映射，不将完整等角楼梯图拉伸到斜坡上。源图片字节保持不变。

首关花坛宽度为1.28、根台宽度为0.82；起始/东岛/南岛基础底部为 -0.67 / -0.15 / -1.23。保留地图平面格距和人物尺寸，通过收薄墙体与放大交互物平衡比例。

首关根台、花坛和孢子使用 `garden_prop.gdshader` 消费原图片。花坛底座单独降低蓝灰饱和度并匹配石材暖色，根台减弱原图高亮光柱，孢子只保留原图圆心种子和球面、淡去UI外圈装饰。等角图片按原画前缘脚点放置在实际接触范围前角，不把整张图片向地下平移。根台和花坛在角色遮挡时保留60%透明度权重。`garden_contact.gdshader` 在真实地面绘制柔和接触暗部，这是美术接触效果，不是实时光源投影。详见 [首关物件与地图融合](../../../docs/49-首关物件与地图融合.md)。

## 更新与信息

- 结构签名决定何时更新网格，普通走路、镜头和同布局刷新不重建几何。
- world.visible(tile) 独立更新显隐；发现、灯光与窗口变化不要求拓扑哈希变化。
- 灯/镜叶光束的签名独立于静态物件，携灯移动不能留下旧光束。
- 光束在当前可见庭院平面范围内绘制，保留实际反射和接收位置；光路发生变化的机关未完成对齐时隐藏目标态连接，结束/撤销后恢复。裁剪与动画不改变规则射程、发现或完成条件。
- `mechanism_props.gd` 只读真实机关状态：琴台编排/节拍、门闩、根系照料、留影与升降刻度。刻度随平台运动，复用节点；3D符号显式使用原Noto字体，不依赖Web缺失的系统字形。
- 根尖预览只包含当前合法邻接。预览参与原生深度；UI 加号仅在没有墙体遮挡时显示。
- 装饰性植物可局部淡化，结构、谜题未知信息不自动透明。
- 日/月影用不同色相，固定记忆另有亮度区别。可交互花种、压板、门闩必须反映实际状态。

- small 通道有共享 native_low_arch.tscn，净高 0.64；伙伴胶囊高 0.56、半径 0.13，主角高 0.8、半径 0.16，图像和实际碰撞对应。
- 1-4 住宅花门、门封、喷泉和原鼹鼠图像均可见，开门反映 home 状态。NPC 图像只缓存一次。
- 水阀上的两路浅槽属于模块局部节点，随平台同轨旋转和升降。末关的跨区域供水关系使用源/受水标记及稀疏透明水滴，不画可能被误认成道路的连续硬杆。固定根系已有真实根路，不另叠斜向捷径线。

- 池塘章节四关按原站 `GardenEnvironment.build_pond_geometry` 恢复有机水域、岸口与生态；2-2也有原版环境池塘。`OriginalPondEnvironment` 独立于规则地块，不提供碰撞或道路。云庭第二关的完成溢流有独立来源与状态，不套主线通用瀑布。

## 原站逐关元素适配

现行原站标准与逐关证据见 [71号记录](../../../docs/71-原版逐关元素恢复与比例验收.md)，优先于70号候选尺寸。`original_garden_dressing.gd`保存12关104个原装饰条目，依据真实surface延迟出现或在同高支撑内迁移；`original_cloud_art/dressing.gd`恢复三云庭专属建筑、地标及修复后场景。独立的原塘环境缓存生态网格与全景投影边界，不逐帧扫描全地图。

`original_prop_ratios.gd`以原完整画布像素宽换算地块占比，完整底座必须有实际同高支撑；布局只在重建时确定，不能随角色或开花追移。核心保留正常深度和完整不透明主体，实际停靠点位于合法支撑内；原生角色尺寸及规则ID保持。原站包袋语义由`original_carry_art.gd`实现，主线物品以叶包小图示携带，云庭星种仍专用，不再沿用此前“手中完整实体同地面等大”的临时方案。

## 镜头与输入

Camera3D 使用 KEEP_HEIGHT。尺寸和密度必须用实际 unproject_position 差值验证，不能只假设公式正确。正常视图采用同视口首关尺度：普通竖屏密度目标 68，低横屏 52，桌面按已确认首关边界计算。大地图和小屏跟随角色；全景独立适配整图，桌面也可使用。不得为塞入整张大地图而单独缩小该关人物与石砖。

set_layout 相同矩形直接返回，避免每跨一格的 HUD 刷新重置镜头。短暂消息和动作弹层不改变关卡缩放边界。

机关离岸开始时，跨刚体外接梯在两岸收平并恢复封边，同一刚体内部高差梯保留。运动模块复用该出发网格、碰撞及完整离岸侧壁，随刚体轨迹移动；落稳时一次安装目的地合法接岸几何。不得带着外接半梯悬空运动，不得先建立终点台阶再反向旋到起点，也不得在中间帧重建网格/碰撞。旋转、平移、升降、反向撤销与云庭桥片遵守同一合同。独立固定岛和模块按各自最低台面计算底座；1-1/1-2专用地形规则保持。现行边界见66号；此前尺度依据见 [机关建模与尺度历史验收](../../../docs/64-机关落稳建模与全关视觉尺度验收.md)。

后续关卡的物件底座与交互圈共享实际支撑中心，旋转/平移/升降期间跟随实体表面，圆环网格按支撑几何版本缓存。圆环按实际踏面分片，不能跨立面连接成坡形三角面；直立精灵脚锚与平放贴图必须分开处理。首两关原造型保留。物件对齐依据见 [全关对齐历史记录](../../../docs/65-全关物件与接岸对齐调整及验收.md)，其中装饰坡面横线已被66号真实台阶方案替代。

实际命中的触摸/鼠标事件必须消费。触摸后的模拟鼠标短期去重，避免种植或交互执行两遍。

## 动作与设置

set_actor_mode 管持久滚球；play_emote 使用原生 AnimationPlayer 和原 jump 帧执行视觉小跳，身体支撑不改变。reset_actor_actions 在换关、回首页、读档等生命周期取消过渡。普通 movement 更新不得立即覆盖 emote。

soft/standard/hd 映射真实 MSAA 与环境粒子预算；particles 控制原生环境微尘；dynamicLight 控制装饰受光，规则光束始终可读。减少动态保留方向与操作节奏，降低跳跃幅度和摆动。

## 验证

native_world_render_test.gd 覆盖 15 关、110 个初始/拓扑/完成状态，使用 PhysicsServer 射线独立比较支撑网格和碰撞，并检查薄承载板、通行余量、发现缓存、花种、动作与设置。native_camera_render_test.gd 核对四尺寸真实投影、可读密度、脚点安全区与镜头缓存。

native_route_test.gd 由运动工作流维护，使用真实胶囊完成所有关卡路线，覆盖中心线之外的体积接触。

native_water_render_test.gd 检查正/反 90° 的中段、升降锚点、未对齐供水隐藏，以及动画前后的 Node/Mesh 身份不变。水滴使用共享 MultiMesh，仅更新实例变换；机关动画不得每帧创建网格。此项不是水体物理模拟。

实体梯专项使用 native_generic_stairs_test.gd、native_generic_stair_movement_test.gd 和 native_stair_lifecycle_test.gd，检查独立几何语义、真实胶囊接触、逐级停步、生成/回收及离岸/接岸，不通过重录旧坡面期望值证明新方案合格。

这些检查不替代 GPU 像素与人工画面评审。正式验收需检查对应构建指纹的桌面、横竖屏、台阶上下行与动作截图/录像，并保留失败与修复记录。本轮原生通过范围、GPU进度和正式包交付状态统一记录在66号。
