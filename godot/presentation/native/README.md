# Godot 原生花园制作与接地规范

本目录由主线与云庭共用。玩法通路来自规则核，空间、接触和图片深度由 Godot 原生节点执行。

## 场景与职责

- native_world.tscn：单个持续更新的 3D SubViewport、正交 Camera3D、环境、光源与地形/物件/角色容器。
- native_actor.tscn：脚点为原点的 CharacterBody3D、半径 0.16 的胶囊、独立 Visual、AnimatedSprite3D、携物点、AnimationPlayer。
- native_surface.gd：实际支撑面、立面、坡槽、踏边与碰撞。可视承载面和 support_height 查询读取同一几何定义。
- native_garden_stage.gd：应用兼容接口、资源装配、地形差量、物件表现、镜头、发现显隐和交互命中。
- garden_water.gdshader：有水面语义的关卡使用柔边水色，章节背景不隐含整张水板。

## 空间与运动

1-1 使用 `first_garden_profile.gd` 的真实离散台阶：水平踏面、竖直立面、接岸入口和分组岛体基础。网格、碰撞和支撑采样共用定义；不使用下述通用窄坡肩部的自动对中限制。东根桥在 x=0.58…1.48 形成六阶，进入东岛前已完成升高；后排八阶在 z=-0.35…-0.99 展开，整幅踏面等高，没有西侧斜楔。南岛始终为 -0.65 的平面；南向根路长出后，才在 z=0.58…1.48 形成六阶连接。台阶通行通过限定合法支撑的胶囊上/前/下扫掠实现。其余关卡继续使用原有坡槽。详见 [楼梯对齐与物件比例](../../../docs/48-首关楼梯对齐与物件比例.md)。

逻辑 x/z 一格对应 1 个世界单位，高度一层为 0.65。角色根变换只由 application/native_movement.gd 的 motor 写入。Visual 可做接地与动作，不能把规则位置拉回格中心。

普通落台中心半宽为 0.20，总宽 0.40，大于胶囊直径 0.32。正交坡道在落台外相连，避免胶囊进入一条坡时顶住另一条坡的侧肩。主要坡槽半宽 0.32，肩部至 0.42；相邻半坡各升降 0.325，主要坡面约 47°，低于 motor 的 56° 上坡界限。

连续肩部必须用实际胶囊路线验证。单看中心射线能够通过，不能证明角色不会被侧肩卡住。2026-11-06 曾出现中心线与接缝测试通过、胶囊仍卡在正交坡交点的情况；修复使用实际平落台，未添加传送或无条件吸附。

根路尚未长出时，latent socket 仅为固定建筑预留坡口，不创建支撑面和通行许可。根路出现后只新增对应实体，其他高台不重新变形。

root/bridge/shadow 的侧板从对应承载顶点向下 0.20，不能沿用固定岛屿的基础底部。否则玩家种出的连接会变成一面向下填满的墙，遮住低层和角色。

实际坡槽宽度必须进入通行合同：半宽 0.32 扣除主角胶囊半径 0.16 和余量 0.02，身体中心可用横向带为 ±0.14。traversal_profiles 直接读取 Surface.rises，包含为未生长根路预留的坡口。普通平地仍自由行走；接近坡口时先以实际速度靠近合法带再前进，不能赋 Y 或瞬移。第四轮真实浏览器曾在偏心位置 (3.457,1.32) 发现中心路线测试未覆盖的侧肩悬浮，因此新增偏心、停止/反向及点击与键盘切换的体积验证。

## 素材与接地

主角使用原 256×256 帧，固定脚轴在源 y=236，AnimatedSprite3D offset=(0,108)，pixel_size=0.00625。

首关已恢复原 pixel_size=0.00625，铺砖、石墙、草地采用原纹理。台阶踏面及立面分别将原 stairs 图片中的等角石面四边形映射到真实平面，不再直接截取带斜边的矩形贴上去。压条两端在本格内部采样同一级踏面，不能跨台阶连接。实时阴影仍未启用，材质明暗不能宣称为真实投影。

滚球源为 89×99，不能套用主角脚轴。滚球按真实高度归一为 0.8 世界单位，图片中心置于地面以上 0.4，offset=0，绕图片中心旋转。退出滚球恢复主角规格。

胶囊在坡面接触时，其底部中心可能略高于中心采样地面。只校准 Visual.y（范围 -0.2 至 +0.12），保持物理根由 motor 控制。角色真实姿态、Visual 脚点、支撑高度分别记录；不以固定 penetration=0 作为证据。

双角色同格的间距由实际局部姿态保存，Visual 不横向冒充另一个物理位置。原伙伴程序画只在缓存纹理生成时使用，持续动作使用原生节点。

首关 flower/bloom 保留原图完整花坛及石底座，不裁成植物后用几何盒子替代。首关侧墙改用与地面同源的 paving-valley 自然石板：garden_island_stone.gdshader 将连续世界 UV 恢复至一格一幅的比例，镜像拼接并内缩原插画边缘，避免非无缝图重复时出现亮边；侧面轻微压暗并正常受光。其余关卡保留原墙砖。台阶纹理随每级踏面重新映射，不将完整等角楼梯图拉伸到斜坡上。源图片字节保持不变。

首关花坛宽度为1.28、根台宽度为0.82；起始/东岛/南岛基础底部为 -0.67 / -0.15 / -1.23。保留地图平面格距和人物尺寸，通过收薄墙体与放大交互物平衡比例。

首关根台、花坛和孢子使用 `garden_prop.gdshader` 消费原图片。花坛底座单独降低蓝灰饱和度并匹配石材暖色，根台减弱原图高亮光柱，孢子只保留原图圆心种子和球面、淡去UI外圈装饰。等角图片按原画前缘脚点放置在实际接触范围前角，不把整张图片向地下平移。根台和花坛在角色遮挡时保留60%透明度权重。`garden_contact.gdshader` 在真实地面绘制柔和接触暗部，这是美术接触效果，不是实时光源投影。详见 [首关物件与地图融合](../../../docs/49-首关物件与地图融合.md)。

## 更新与信息

- 结构签名决定何时更新网格，普通走路、镜头和同布局刷新不重建几何。
- world.visible(tile) 独立更新显隐；发现、灯光与窗口变化不要求拓扑哈希变化。
- 灯/镜叶光束的签名独立于静态物件，携灯移动不能留下旧光束。
- 根尖预览只包含当前合法邻接。预览参与原生深度；UI 加号仅在没有墙体遮挡时显示。
- 装饰性植物可局部淡化，结构、谜题未知信息不自动透明。
- 日/月影用不同色相，固定记忆另有亮度区别。可交互花种、压板、门闩必须反映实际状态。

## 已有对象的最小可见性清单

- main item mark 如果已有 state.items 实体，只由实体表现；不能再补一个“花种”标记。云庭种子没有 state.items 项，才使用对应花种表现。
- small 通道有共享 native_low_arch.tscn，净高 0.64；伙伴胶囊高 0.56、半径 0.13，主角高 0.8、半径 0.16，图像和实际碰撞对应。
- 1-4 住宅花门、门封、喷泉和原鼹鼠图像均可见，开门反映 home 状态。NPC 图像只缓存一次。
- 水阀上的两路浅槽属于模块局部节点，随平台同轨旋转和升降。末关的跨区域供水关系使用源/受水标记及稀疏透明水滴，不画可能被误认成道路的连续硬杆。固定根系已有真实根路，不另叠斜向捷径线。
- mechanism_visual_profile.tres 只配置已有供水条件和支撑 anchors，不负责解谜。新连接必须等机关实际对齐才显示；既有连接的端点随真实支撑移动。未来关卡使用相同规范。
- 没有水面语义的 2-2 和云庭不铺整张方形水板。2-1/2-4 的水色使用柔边材质。

## 镜头与输入

Camera3D 使用 KEEP_HEIGHT。尺寸和密度必须用实际 unproject_position 差值验证，不能只假设公式正确。普通竖屏密度目标 68，低横屏 52；小屏跟随角色，大屏按稳定建筑边界取景，概览是明确的独立视图。

set_layout 相同矩形直接返回，避免每跨一格的 HUD 刷新重置镜头。短暂消息和动作弹层不改变关卡缩放边界。

实际命中的触摸/鼠标事件必须消费。触摸后的模拟鼠标短期去重，避免种植或交互执行两遍。

## 动作与设置

set_actor_mode 管持久滚球；play_emote 使用原生 AnimationPlayer 和原 jump 帧执行视觉小跳，身体支撑不改变。reset_actor_actions 在换关、回首页、读档等生命周期取消过渡。普通 movement 更新不得立即覆盖 emote。

soft/standard/hd 映射真实 MSAA 与环境粒子预算；particles 控制原生环境微尘；dynamicLight 控制装饰受光，规则光束始终可读。减少动态保留方向与操作节奏，降低跳跃幅度和摆动。

## 验证

native_world_render_test.gd 覆盖 15 关、110 个初始/拓扑/完成状态，使用 PhysicsServer 射线独立比较支撑网格和碰撞，并检查薄承载板、通行余量、发现缓存、花种、动作与设置。native_camera_render_test.gd 核对四尺寸真实投影、可读密度、脚点安全区与镜头缓存。

native_route_test.gd 由运动工作流维护，使用真实胶囊完成所有关卡路线，覆盖中心线之外的体积接触。

native_water_render_test.gd 检查正/反 90° 的中段、升降锚点、未对齐供水隐藏，以及动画前后的 Node/Mesh 身份不变。水滴使用共享 MultiMesh，仅更新实例变换；机关动画不得每帧创建网格。此项不是水体物理模拟。

这些检查不替代 GPU 像素与人工画面评审。正式验收需检查对应构建指纹的桌面、横竖屏、坡道运动与动作截图/录像，并保留失败与修复记录。
